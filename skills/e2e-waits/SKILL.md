# 端到端场景怎么等

为什么有这一页：2026-11-20 一天里，四个场景都是因为「等得不对」才红的，分别修了四次：hallexit（#351）、finish（#378）、lang（#368）、T4 上的十个（#379）。同一个错不要再犯第五次。

## 三条规矩

1. **等条件，不等时间。** 用 `t.until(async () => 条件, 上限毫秒, "等的是什么")`。上限只是兜底，不是等待本身；失败时报出 `t.state()`，方便定位。不写 `waitForTimeout(固定秒数)` 之后紧接着断言。
2. **不按固定帧数断言。** `await t.frames(1)` 之后马上读结果，在慢机器上常常还没算出来，在快机器上（T4）中间的过程又可能已经跑完。正确做法是：动作之后用 `t.until` 等到要的那个状态出现，例如 `__yard().target` 不再是 null、`__inside()` 变了、`__eyeSpace().state === "ready"`。`t.frames(n)` 只用来让画面多画几帧，以便截图或取平均值。
3. **动作要等页面肯接，再做下一个。**
   - 进殿、出殿、穿帷幕时，先等 `pass()` 结束（`settle`），再发下一个指令，否则会被页面丢掉（#351 B）。
   - 点按钮前先等它真的可以点：滚进视口，按帧等它不再移动，用 `elementFromPoint` 确认最上面一层就是它，再点（#378 finish）。
   - 有过渡的状态（推近拉远 `push`、开场 `opening`、导演镜头 `director`），等过渡结束再读「之后」的值（#368 大殿那一例）。

## 写完自查

- 在免费机器上连跑 3 次都过；改动涉及镜头或时序的，T4 上也连跑 3 次（`tools/gpu-render.sh` 或 #363 的 T4 跑法）。
- 场景里没有新写的数字坐标，坐标从 `site` 数据或页面钩子读（见 LESSONS.md「测试不写死场景坐标」）。
- 新场景要在 `tests/e2e/durations.json` 里记上实测时长；分片数会自动算（#377），不用改分片单测。
