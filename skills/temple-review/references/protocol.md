# 评审流程 v1.0：自审与依据

更新：2026-11-14。以下为本项目的评审约定，不把外部最佳实践称作游戏质量认证。

## 现有流程保留的做法

- 源码、开发者声明、实际运行与最终验收分别记录。
- 截图、录像与测试均锁定提交，保留历史证据。
- CI quick只证明其覆盖的启动检查，不能推定全路线或美术通过。
- 目标设备性能不足时明确blocked；不由软件GPU换算手机或Mac表现。

## 本次自审发现的改进点

| 旧流程中的问题 | v1.0约束 |
|---|---|
| 同时进行多个软件渲染任务，可能放大点击超时 | 浏览器、截图和性能任务串行；记录系统负载和首个失败 |
| 30秒超时后，扩大到90秒可以进入 | 只记作诊断成功，保留40.7秒响应记录；不能据此抹去失败或认定性能通过 |
| 持键2.5秒、移动不足0.2米直接判失败 | 区分实际输入、帧数、逻辑dt和墙钟；不足以归因时标unknown/harness/environment |
| 新提交在评审期间到来 | 锁定证据提交；最新HEAD单列，不混用旧图，也不无限追新 |
| 命名gate和screen与验收相机语义不完全一致 | 相机ID关联实际参数与取景目标，补充图不冒充标准机位 |
| JSON、页面、交接说明可能各自出现旧状态 | 结构化报告统一事实来源，发布前校验并读回；迁移前保留legacy报告 |
| 创建定时任务不等于后台读写已经验证 | 首次执行检查读源、隔离环境、写入、发布和读回；未成功前保持未验证 |
| 托管单文件上限导致录像发布失败 | 使用项目托管限制；T00当前为25MiB，压缩副本保留原时长与原始哈希 |

## 分层结论与关闭条件

- **pass**：要求、适用环境和证据匹配，证据确实支持结论。
- **partial**：明确通过的子范围以及剩余部分，不用“基本完成”代替。
- **fail**：观察与约定验收不符；环境归因不明时描述可复现现象和限制。
- **blocked**：缺权限、设备、图形环境或有效数据，不能写成通过。
- **问题关闭**：修复后在匹配的版本、机位和环境复测，附新证据。

产品功能、视觉、性能、安全/素材、发布状态各自结论，不算一个无依据的“完成百分比”。可用脚本生成摘要，但美术判断仍需实际看图。复用Skill不要求使用子代理；若环境支持并有授权，可按维度独立复核，不虚构评审角色。

## 项目立意如何进入验收

《山门之外》以“一城一寺，一段值得慢下来的路”为策展方向。选择空间独特、艺术可看、文化可追溯的寺院原型，提炼特色后创作场景。小众优先，少量知名寺院可因隐藏的艺术细节进入候选。

因此评审除功能外，还要回答：没有特殊滤镜时此处仍有辨识度吗？路线是否有显露、遮挡与停留的节奏？轻互动是否帮助观看和理解？材料、声音、季节与地方是否相符？这些是设计判断，须结合画面或运行路径说明，不能编造成史实。

## 参考的官方实践

- [Agent Skills规范](https://agentskills.io/specification)：采用SKILL.md元数据、按需引用资料和可选脚本组织包；名称与目录一致。
- [Claude Code Skills](https://code.claude.com/docs/en/skills)：项目Skill放在.claude/skills；显式调用方式为/temple-review。
- [Codex Skills](https://developers.openai.com/codex/skills)：采用.agents/skills项目入口，使用$temple-review调用。
- [Playwright Best Practices](https://playwright.dev/docs/best-practices)：使用可靠定位、自动等待和可重试断言；保留失败诊断，视觉比较需要一致环境。
- [Playwright Visual Comparisons](https://playwright.dev/docs/test-snapshots)：像素基准只在受控条件下有意义，初次生成不等于人工批准。
- [GitHub Actions Secure Use](https://docs.github.com/en/actions/reference/security/secure-use)：凭据最小权限，处理不可信代码与输出；固定第三方Actions提交，部署权限只给需要的作业。

这些资料支持执行方法，不替代目标设备、艺术判断、素材许可和本项目验收条件。

## 按需真实GPU / Hugging Face Jobs

用户已允许在必要时考虑商业HF Jobs，并说明有PRO会员；这不等于无限预算或任何任务都应启动GPU。本轮文档与Skill更新不启动付费作业。

触发条件：图形改动需要真实GPU验证，或软件渲染明显干扰响应/截图而无法归因。先完成静态检查，复用已有有效证据；文档改动不启动GPU。优先单个t4-small作业，显式timeout，串行合并所需机位，结果落盘后终止作业。

T00建议的默认护栏：每轮最多1个作业、20分钟timeout、预计计算费不超过US$0.50。创建前读取当前硬件费率、账户余额/额度、配置和用户授权，记录规格、费率、估算与job ID。无法确认预算、超出护栏或需要更高规格时先确认；不因为已有授权内的付费动作本身反复请求许可。不自动充值、扩容或无上限重试。护栏是本项目默认提案，其他项目自行配置。

官方说明：Jobs按硬件使用分钟计费，PRO等订阅所含计算额度可用于Jobs，须有正余额；PRO不是无限免费GPU。以运行时官方价格与余额为准，不把旧文档中的T4价格写成固定承诺。

- [HF Jobs计费](https://huggingface.co/docs/hub/en/jobs-pricing)
- [HF Jobs配置与timeout](https://huggingface.co/docs/hub/en/jobs-configuration)

最小化上传：只用私有存储和允许的文件清单；不上传.git、账号凭据、日志中的秘密或无关文件。不把整个工作区打包给作业。给运行代码的子进程和发布步骤分开授权。

现有tools/gpu-render.sh会排除佛像模型，GPU runner还会忽略部分模型404；因此它输出的成功不能证明内殿资产完整。评审须逐项记录预期/实际资源和缺失原因，外景诊断不能代替内殿验收，不能吞掉错误后声称全部通过。

记录真实GPU报告与软件报告各自环境；T4结果只属于该GPU环境，Mac和手机仍按目标设备规范单独测试。

## v1.1 增补（2026-11-19）

v1.0 之后项目里定下、评审时必须知道的规矩。出处在仓库里，评审时以 main 上的原文为准；这里只是索引。

**评审的位置。** 本评审由定时任务在全新会话里执行，与主创会话互不共享上下文，这正是它的价值：主创合并的东西由它独立复核。主创不改评审结论（`AGENTS.md`「谁派活，谁合并」）；评审也不改主创或所有者已记录的决定，不同意时在报告里写明理由和证据。所有者的话与决定看 `docs/handoff/LATEST-GOALS.md`（按序编号），主创的工作规矩看 `AGENTS.md`「主创怎么做这个角色」。

**证据不进 git（#223）。** 图和录像在 Hugging Face 公开数据集 `bolechen/temple-walk-evidence`（原件），CI 镜像到 R2（`tools/evidence.config.json` 的 `base`）。仓库里每个证据目录只留 README、短文本、`MANIFEST.json`（路径、字节数、SHA-256、提交）和至多一张 1 MB 的拼图。取回：`node tools/evidence.mjs pull <目录>`；全量核对：`verify --all`。评审自己的证据也照此推送（`push`），沙箱里给 `hf` 占位令牌 `hf_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx`，Node 加 `NODE_USE_ENV_PROXY=1`。证据只在仓库里留了清单时，核对哈希后才可引用。

**真机结果。** Pixel 8a 的真机测试由 muse 用 adb 做，结果写在各 issue 的评论里（第一行结论：过 / 没过 / 没验）。`真机已验` 标签只表示该 issue 的真机项**全部**通过；2026-11-19 曾发现标签被贴在没过、没验的 issue 上，已全部摘掉。评审引用真机证据时读最后一条真机评论，不看标签。Mac 真显卡的结果在 #238、#264。

**两套 walker（碰撞迁移 #161）。** 第一进院默认走从画出来的网格烘的格子（#265），第 4 步（#274 / PR #276）把全图换过去；`?walker=old` 是旧的写出来的平面，`?walker=mesh` 是格子能到之处都用格子。`__walker()` 报当前用哪套。单测、`edges`、`nearplane` 各有 `:grid` 版（`pnpm run test:grid`、`edges:grid`、`nearplane:grid`）。评审「能不能走到、会不会穿模」时两套都要看；新开出来的地（第 3 步约 209 m²）以前没人看过，背面、墙顶外、远景是重点。

**改着色器要有真显卡结果。** #231 香炉的烟在软件渲染下正常，在真显卡上 `pow` 底数略小于零得 NaN、经泛光把半屏染黑并上线。SwiftShader 看不出这类问题；着色器改动没有 T4 或 Mac 的图，相关项标 blocked，不判 pass。

**留影的景深（PHOTO-02）。** 所有者 2026-11-19 看过对比图后定：默认全景清晰，虚化只在留影设置里玩家自己打开时出现；主创据此把 `?shot` 也定为不虚化（#275）。PHOTO-02 仍按它自己的验收条件判：同一锁定提交高档举相机时 `__probe().post.dof` 为 false、近景与远山同样清晰。

**看作者没想到要看的那一面。** 一个零件用到新的地方算改形体（素匾 #245 背面也印了字）；改形体的证据要有正面、侧面、俯视或斜俯视（`AGENTS.md`「改形体的，从几个方向看」）。机位和构图类改动看 16:9、4:3、手机竖屏三种画幅。

**范围。** T00 的验收范围仍是五区（竹林起点、台阶、照壁、山门、第一进院），基准是 J01（夏昼雨后）。下一关暂定 T05（#280 的七佛造像试验出结论后由所有者定，备选 T02）；`docs/t05/` 等调研包不是 T00 的验收对象。

**常驻的专项评审。** 建筑结构、3D 模型、音乐三个评审会话的意见写在各 PR / issue 评论里（交接文档 `docs/handoff/review-*.md`），可作为专项证据引用，但它们不是本独立评审，结论仍由本评审自己判。
