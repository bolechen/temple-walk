# 关卡手册：做一座寺的顺序

所有者 2026-11-17：「T00 的工作哪些是可以复用的，要不要整理成后续关卡的工作流」。这一页只记序章 T00（云径禅寺）**实际走过**的顺序和从中得到的教训，不为还没做的关卡预设结构。第二关走完后按实际修订。

状态说明：第 1–9 步是 T00 的经验；第 10、11 步 T00 自己还没走完（验收结论仍在旧证据上，发版未合），写的是计划。

## 一、每关重做的，和拿来就用的

| 每关重做（内容） | 拿来就用（引擎与工具） |
|---|---|
| 实地与文献调研，「灵魂元素」和「有意没有做的」清单 | 建筑、台阶、地形的生成器，碰撞与可走区域自动登记 |
| 平面：建筑、台地、路径、可去的地方 | 小沙弥：骨骼、行走、坐、两种视角、跟拍、打卡镜头 |
| 验收机位、美术目标图 | 材质、四季四时、雾、阴影、画质分档、调色 |

## 二、顺序

每一步写：产出什么、谁评审、用什么判。

1. **调研。** 产出 `docs/<寺>.md`：这座寺凭什么值得走（灵魂元素，一条一个出处），哪些有意不做。所有者定取舍。没有这一页不画平面。
2. **平面与可走性。** 产出关卡的平面数据。判：单测从第一步洪水填充能走到每个命名地点；`pnpm run edges` 0 处超限。先用白模走通全程，再谈好看。
3. **验收范围与机位。** 产出六个左右锁定机位和基准季节时辰（T00 是 J01 夏昼）。之后每次改动都拿这几个机位对照。
4. **景观评审，第一次。** T00 是在建筑做完之后才发现远景露天、山体硬边（#112 之后开了五个 issue）。下一关在第 2 步白模阶段就从每个能站的地方向外看一圈：地平线以下不露天，远处有东西可看。景观是第一卖点。
5. **结构评审。** 建筑的柱网、斗栱、重檐、平坐由结构评审方按法式看一遍（T00 分了三个阶段）。凡是「为了能站人、能看见」所做的偏差，记进 `SOURCES.md` 和 `decisions.md`。改形体的证据要正、侧、俯三个方向。
5a. **绕一圈普查。**（#252）建筑和陈设做完、上线前，由我们自己把「只做了一面」的东西找全：`node tools/around.mjs` 从 `site` 的数据列出每一类东西，用烘好的可走格子（`node tools/bake-walk.mjs`）找出玩家站得到的四面和一个斜俯视的机位；`tools/around-gpu.sh` 在 T4 上拍，`python3 tools/around-sheet.py` 拼接触表，另有 200 个均匀取样的游客眼找清单想不到的。发现逐条写进 `docs/<关>/around-review.md` 并各开 issue；`tests/unit/lettered-faces.test.mjs` 长期守着「带字带画的贴图只画在一个朝向上」。T00 的做法和找到的东西见 `docs/t00/around-review.md`。
6. **仪式、朱印与镜头。** 每处做什么、朱印怎么得、打卡时镜头去哪。机位是数据；转场走动画，不硬切；玩家一动就交还。先定每处「玩家该看见什么」，再写镜头。
7. **美术目标。** 每个代表性机位一张目标图和可量的指标（`look.py`）。分阶段做，先便宜的（调色、雾、软阴影），量过再上贵的。两个机位的目标互相打架时（T00 的 A2 与 A3 抢太阳方向），改目标的季节时辰，不扭光。
8. **声音。** 每个分区一段乐句，主题随朱印逐音出现；环境声要有出处（鸟只在山上，殿内不鸣）。
9. **界面与语言。** 新增文字四种语言齐全，字体裁切更新；手机上每个面都过 `mobile-audit`。
10. **授权核对。** 进产物的每件素材在登记表里有一行，按收费上架的口径核过；署名进鸣谢页。发布前做，不留到发布后。
11. **验收与发布。** 锁定机位在 T4 上重拍，独立评审在新证据上给结论（谁也不能代改）；所有者用自己的电脑和手机按清单走一遍；发版由所有者合。

## 二之二、走路数据：画出来，再挂意图标记（#265 首院，#274 起全图）

**新关卡不手写 `walk.solids / decks / ramps / posts / drops`。** 能走的地面、挡路的东西、台沿都从画出来的网格烘（`tools/bake-walk.mjs`，做法见 `CLAUDE.md`「The floor baked from the drawn meshes」）。T00 自 #274 起户外各层、凌霄阁平坐、八间殿内默认都走烘出来的格子；手写的那一份只为 `?walker=old` 留着，到第 6 步删。没读过本仓库的人照下面五步做：

1. **画。** 建筑用 `put(opts, [x, z], 转几个直角, 层)`，台阶用 `stairGeo`，器物用 `mesh()` 加进 `root`。高过 0.25 米（`BAKE.CLIMB`，他一步迈得上的高度）的台就得有踏步或让他跳（0.255 米到他的跳高之间、没有栏杆的台沿，烘焙自己认作可以跳上跳下）；T00 的半山亭、望江亭台高 0.3 米没画踏步，旧数据靠一块手写台面走上去，#274 才补画。
2. **说从哪里进。** 户外格子的种子是 `site.start`（`site.views.arrive`）；每间殿是 `room.door`；平坐是 `site.lofts[id].door`。新关卡在 `tools/walk/scene.mjs` 的 `gridsOf` 里照样列出它的格子（一张户外的，每个上层回廊一张，每间房一张）。
3. **挂意图。** 网格表达不了的才写，挂在画它的那一行上，不另写坐标。全表见下。
4. **烘，看。** `node tools/bake-walk.mjs`（约一分钟，之后走缓存），`node tools/walk-diff.mjs <基准.bin> --png=tools/out/walk-diff` 出图：灰是两边都到，蓝是多出来的，红是少了的。命名地点（`scene.mjs` 的 `targetsOf`：打卡点、座位、殿门、命名机位、每个画框和功德箱、梯脚、殿内机位、平坐的门）有一个走不到就失败。开着 `?debug` 面板的「碰撞 → 画出格子、外廓、眼球」站到现场看：绿点能站，红点不能，白圈是他的外廓，黄球是眼睛。
5. **守。** `pnpm test`（`gridwalker.test`：每段台阶来回走、每座殿四周、殿内绕柱、平坐只在栏杆内）、`pnpm run edges:grid`（他的身体不进任何东西）、`pnpm run nearplane:grid`（含 `eyeroom`：能到的格子 0 个在院墙外、竹林里、屋顶上、殿身里；眼离任何面不小于近裁剪面四角的距离）。画的不对就改画或补意图，不去改格子。

**意图标记全表**（挂在画它的那一行上）：

| 写法 | 什么时候用 | T00 的例子 | 谁保证不漏 |
|---|---|---|---|
| `mesh.userData.walk = "post"` | 要绕着走、不许踩的矮物件：射线穿过它看下面的地，它从地面起按他在它那个高度的伸出挡住。高不过 0.6 米、宽 0.4 到 1.2 米、自成一个网格的小东西烘焙也会自己认成这一类 | 茶寮的蒲团、矮茶案连同桌上的东西、院里茶案连同凳（`site.js`） | `gridwalker.test`「画出来的每个蒲团和凳都是座位」；`edges:grid` |
| `mesh.userData.walk = "floor"` | 要让他踩上去的东西，圆边、斜面也算（烘焙平常只把 15° 以内的面算作地：台阶是一级一级的踏面，垂带的斜顶不能站）。整件都是地：它的边不挡他，鞋够得着它的地方他就站在它的顶面上 | 山顶凌霄阁前的蒲团（`site.js`）；佛前和祖师案前的拜垫（`interior.js`：上香的站位就在垫上） | 命名地点检查（殿门、`lookback` 机位、上香的站位都在它上面）；`edges:grid` 膝盖以下 |
| `mesh.userData.walk = false` | 画了但不在路上：不进烘焙 | 远处的雾片、光柱、调试面板画的格子（透明、`alphaTest`、`ShaderMaterial` 的材质已自动排除） | `edges:grid`、`nearplane:grid` |
| 殿门 `hall.stop`（`site.js` 登记殿门那一行算出来的矩形） | 画出来开着、走进去由触发器管的门：门线以里关上 | 每座能进的殿 | `edges.test`「进殿在门槛」 |
| `site.closed`（`site.js`，一个矩形加一句为什么） | 画出来是地面、却不该走进去的地方 | 山门两侧间（前后都是关着的板门，从门洞往旁边一步就进去了）；前院两侧竹林（竹子不进烘焙，边界只能写成意图；与旧 walker 的「竹林在两侧合拢」是同一个数 `SITE.GROVE_IN`）。#274 把其余各层查了一遍，加了一处：龙井龛里的池子（石槛只有 0.24 米，比一步低，他原来能跨进去站在水面上） | `walk-diff`「画的地面能站、旧数据走不到的」一栏，每处超过 1 m² 都要在 PR 里说一句；慢测 `eyeroom` |
| 座位 `site.seats` / 殿内 `seat()`、`sitAt()`（`kind`：`stool` / `cushion`） | 能坐的地方，和画它的同一行 | 每只蒲团和凳 | `gridwalker.test` 按 `CUSHION`/`STOOL` 的尺寸把画出来的坐具一个个找出来，对上座位 |
| `site.places`、`rooms.spots`、`room.stair`、`site.lofts`、`site.views`、`HALL_VIEWS` | 要去的地方：打卡点、画框和功德箱、梯脚、平坐、机位 | — | `walk-diff` 与 `gridwalker.test`：有一个在格子上走不到就失败 |
| `walk.roofs`、`shade` | 镜头和雪要知道的屋顶、铺地变暗的地方：由 `building.js` 按参数生成，不是手对的，留着 | — | `eaves`、`sweeps`、`shelter` |

**不用标签、由烘焙自己认的**：台阶（每级低于 `CLIMB`）；能跳上跳下的台沿（高差大于一步、不超过 1.5 米、台面一侧开着、没有栏杆、台下 0.9 米处落得了脚）；栏杆（画了就挡）；门槛（8 厘米以下、槛面是一块落脚处）；树根和香炉脚这类低立面（面背后没有落脚处，按鞋的外廓收边）；台沿下面一掌宽的线脚（容不下鞋，不算能站）；地面以上到头顶的任何面，包括平的树枝、石板底（高过一步就算挡路）。

**画的时候要知道的几条**（都是 #274 在 T00 上踩出来的）：

- 他有多宽是量出来的（`tools/walk/outline.json`）：两样东西之间的净宽不到 0.9 米左右他就过不去。凌霄阁底层回廊柱面到栏杆 0.83 米，走不通，`gridwalker.test` 的 `NARROW` 里列着，要走通得改画。
- 殿里画了整条的东西，别指望「数据里留个口」：禅堂门内的坐榻旧数据留了过道、画的是整条，他一直从坐榻里穿过去。要过道就画成两段。
- 地面必须朝上、上面留得出 1.45 米净空（`BAKE.CLEAR`）才算地；台地的石体下面、桌面底下不是地。
- 山体（`backdrop.js` 的 earth）永远不算地，它盖住的铺地也走不上去：T00 山顶台地两侧的土坡盖过了铺地的边，那一条在格子上到不了。

## 三、新开一关要建的文件

- `docs/<level>/`：`README.md`（怎么跑）、`decisions.md`、`SOURCES.md`、`asset-register.csv`、`delivery.json`、`KNOWN-ISSUES.md`、`evidence/`（只增不改）。
- `app/levels/<level>/`：平面与关卡数据（#138 之后）、`gallery/`、`boards/`、`locales/`、殿内机位表。
- 一份长目标文件只在一条线的工作确实多到一个 issue 写不下时才建（T00 有 `art-goal.md`、`structure-goal.md`）。

## 四、T00 的教训，下一关照此办

- **先看全局，再抠细部。** 返工最多的不是代码，而是做完才评审：结构三个阶段、镜头三轮、景观五个 issue。评审往前放（第 4、5 步）。
- **涉及尺寸的决定先量后说**，并排出图再定（竖匾、回廊宽度都是看了图才定对）。
- **测帧只比同一个 Job 里的差值**（`docs/t00/geometry-budget.md`「五之二」）；每份报告带站点指纹。
- **真机真人最缺。** T00 到发布前几乎没有在真手机上走过。下一关从第 2 步起，每条线收尾都请所有者走十分钟。
- **PR 小、对话短、正文跟着代码走**，流程细则在 `AGENTS.md`。

## 五、地面的记忆（#267）

落在地上、要留下的东西，往地面记，不各写一套。地面有两层，都跟着他、同一个 32 米见方（低档 24 米）、每次挪八分之一、走远就忘：

| 层 | 文件 | 记什么 | 格式 |
|---|---|---|---|
| 压痕 | `trail.js` | 雪里的脚印：深度（R）、踩下处的地面高度 × 深度（G） | GPU 上的图，2048²（低档 1024²），RG 8 位 |
| 落下的东西 | `litter.js` | 叶、花瓣：每格 1/4 米，最多 7 片各记落点与编号，更旧的记成一堆的数量 | CPU 上的记录，每帧有变才上传一张 2N×N 的 RGBA16UI 小图（高档 256 KB，低档 144 KB） |

压痕是连续的凹陷，用图；落下的东西是一件件有位置的东西，用记录（图只记「多少」，记不住「哪片在哪」，叶就会在眼前换位置）。下一关：松针、花瓣、香灰往 `litter.js` 记（换颜色和形状即可）；雨后的湿脚印往 `trail.js` 记（B 通道空着）。
