# T03 白盒与开工计划

核对日期：2026-11-17。本文只写到「第一版白盒能走通、能看图、能量帧」为止。精模、完整寺院、太子会游行、周五集市都不在第一版。

---

## 1. 第一版做什么、不做什么

### 做

- 五区白盒：东巷（A）、广场（B）、戏台侧边（C）、寺院一进（D）、回到广场（E）。
- 广场（约 60 × 22 m）、寺门（10.1 × 8.3 m）、第一进天井/厢房、观音楼（10.9 × 8.6 m）、戏台（9.5 × 11.2 m，三层）的体块。
- 一条可走通的路线，键盘 + 触摸。
- 寺门—戏台的对望；门洞框住戏台的「一帧」。
- 六个候选机位。
- 广场四周的铺面/马店体块（不做室内）。
- 红砂石铺地、两棵槐树、东寨门/东巷。
- 五段声场的合成层（可先做 Z1/Z2/Z3/Z4）。
- 五处安静观察（声/框/摊/门/回）。
- 原创壁画 1–3 幅（第一进侧墙/观音楼），不做复制。

### 不做

- 中殿、大殿内部；壁画的近距离观看。
- 戏台二层展厅/三层魁星阁；登台。
- 完整寺院（三进）；方丈院/僧寮。
- 太子会游行、周五集市、完整戏曲演出。
- 石宝山、玉津桥、欧阳大院内部、南/北寨门。
- 整座沙溪镇/农田/黑潓江。
- 多人、NPC、对话树。
- 七印/朱印体系（用「广场记·五处」）。
- 四季四时的全部 16 种（先做 S01 + 1 备选）。
- Steam/桌面外壳。

## 2. 白盒的五个节点与验收

| 节点 | 位置 | 必须能做的事 | 验收 |
|---|---|---|---|
| A 东巷 | 东寨门—巷子 | 从巷子进入；听到远处鼓点；看到戏台飞檐的一角 | 能从东寨门走到广场，不卡；声音先到 |
| B 广场 | 四方街 | 走进广场；看寺门与戏台相对；两棵槐树；红砂石 | 寺门/戏台同时入画；不靠箭头能找到戏台 |
| C 戏台侧边 | 戏台东南/背面 | 看一层铺子、二层入口、三层魁星阁；听木地板/搬动 | 三层关系读得出；不登台；楼梯像后加 |
| D 寺院一进 | 门楼—天井—观音楼 | 过门洞；在天井站住；看观音楼；回望戏台 | 门洞框住戏台；天井声光不同；不进入中殿 |
| E 回到广场 | 四方街 | 回到广场；看收摊/灯/人变化；结束 | 广场状态变化；可随时结束 |

### 2.1 总体验收

- [ ] 从 A 到 E 全程可走，无卡死、无穿模、无掉出。
- [ ] 键盘（WASD/Shift/E/Space）与触摸（摇杆/点地/交互）都能完成。
- [ ] 五处观察都可跳过，不集齐也能到 E 并结束。
- [ ] 寺门—戏台的对望成立；门洞的「一帧」可找到。
- [ ] 六个候选机位都能站人、能取景。
- [ ] 广场四周的铺面/马店不进入，但有体块/檐口/门面。
- [ ] 无页面错误、控制台错误、失败请求。
- [ ] 单测：从第一步洪水填充能走到每个命名地点。
- [ ] `pnpm run edges` 0 处超限；`nearplane` 无切割。
- [ ] `mobile-audit` 无 <44 px 控件、<12 px 文字、越界。
- [ ] T4 上量一次帧耗，记录在 `docs/t03/`（不是 T00/T01 的数字）。

## 3. 白盒的技术路线

### 3.1 先分关卡，再写内容

- `app/levels/t03/`：平面、建筑参数、views、places、locales、gallery、boards。
- `app/shared/`：引擎、材质、行走、镜头、音频、界面。
- 若关卡拆分（#138）还没做完，先在 `app/src/site.js` 里加一个 `T03` 分支，但**把数据放在 `app/levels/t03/site-t03.js`**，不要散在引擎里。

### 3.2 建筑

- 第一版：`buildHall` 加 `style: "ming-bai"` 参数；先做体块 + 屋顶剪影。
- 寺门：`buildGate` 或 `buildHall` 的 `gate: true`，10.1 × 8.3 m，两层、重檐硬山、中开间通道。
- 第一进：一个天井 + 南北厢房 + 观音楼（10.9 × 8.6 m，两层、重檐悬山）。
- 戏台：新 `buildStageTower`，9.5 × 11.2 m、三层、凸字形、三重檐、14 飞角、12.2 m。
- 四周民居：`buildBaiHouse` 的简化体块（白墙/土黄墙 + 小青瓦 + 深木门面）。

### 3.3 地面与可走性

- 广场：一个 deck（约 60 × 22 m），红砂石；向东微降 0.3 m。
- 东巷：一个 deck（3–4 m 宽），略低。
- 寺门/第一进：一个 deck，高 0.3–0.6 m，1–2 级台阶。
- 戏台：solid（不可进）；台前 3–4 m 可站带。
- 两棵槐树：posts（树干），树池可站。
- 四周铺面/马店：solids，不做室内。
- 中殿/大殿：solid + 不可达；用门/绳/暗部挡住。

### 3.4 镜头

- 第一版用 T00 的第三人称跟随 + 第一人称；不做新的镜头系统。
- 六个机位用 `views` + `shots.js`；`?show=cam01` 等。
- 戏台三层檐、寺门、观音楼、四周铺面进 `walk.roofs`，否则跟随镜头会穿。
- 门洞的「一帧」不做强制相机；只做触发判定。

### 3.5 广场的公共生活

- 第一版：3–5 个简单生活事件（摆货/扫地/送货/开门/收摊），每个 10–20 秒；低模/剪影。
- 不做人群模拟；不做对话；不做交易。
- 事件可缺席；缺席不是失败。
- 时间推进：C05 的「换场」用状态切换，不做时间跳跃动画。

### 3.6 季节

- 第一版只做 **S01 秋季柔光** + 一个备选（冬季晴冷或雨后）。
- `moodOf` 新增字段：`squareWet`（广场湿态）、`marketState`（生活事件状态）、`stageLight`（戏台受光）。
- 不做 16 种；等基准定了再扩。

## 4. 性能预算（草案，必须实测）

T00 的数字（T4，1080p）：

- 首院高档 9.3 ms，低档 4.7 ms；屋顶是三角形大头；绘制次数比像素更紧。
- `?tour=120x3` 高档平均 61 fps，95th 21 ms。

T03 的体量估计：

| 项 | 估计 | 依据 |
|---|---|---|
| 建筑三角形 | 25–45 万 | 寺门/观音楼/戏台/四周体块；比 T01 少 |
| 广场/铺地 | 5–10 万 | 红砂石板 + 磨损 |
| 树 | 5–10 万 | 两棵槐树 + 少量背景树 |
| 人物/生活事件 | 1–3 万 | 低模/剪影 |
| 远景 | 3–8 万 | 鳌峰山/农田/巷道 |
| 总三角形 | 40–75 万 | 低于 T00 的 110 万 |
| 绘制次数 | 120–200 | 合批后 |

**目标**：高档 1080p ≤8 ms，低档手机尺寸 ≤4 ms。达不到就砍：先砍背景树、生活事件、远景细节；不要先砍戏台/寺门/广场。

**量法**：同一个 GPU job 里比差值；报告带站点指纹；不用软件渲染的数字外推。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 没有现场测绘 | 广场/戏台/寺门比例可能错 | 白盒先按 OSM + 政府尺寸；精模前现场补测 |
| 建筑词汇与 T00/T01 不同 | `buildHall` 要大改 | 先做 `style` 参数与体块，不追求一次到位 |
| 戏台三层/飞角比例难 | 认不出「魁阁带戏台」 | 先做剪影，再从侧面/俯视看图 |
| 广场四周 OSM 缺失 | 体块/街墙不完整 | 用文字描述 + 现场照片补；标注「重建」 |
| 公共生活做成「表演」 | 违背主题 | 只做低模/剪影/生活事件；不做演员/舞台 |
| 社区/表演者授权 | 录音/拍摄不能进游戏 | 默认全合成；现场采集先取得同意 |
| 壁画复制侵权/文物风险 | 不能用真实壁画 | 游戏里用原创壁画；卡片说明 |
| 旅游宣传语污染 | 「小丽江」式画面 | ART.md 的 must_not；文案审校 |
| 性能 | 三角形/绘制次数超标 | 先砍背景树/生活事件/远景，不砍戏台/寺门 |
| 季节与 T01 重复 | 像同一地方 | 用红砂石/土黄墙/小青瓦/广场区分；不用 T01 的黄墙琉璃 |
