# T05 白盒与开工计划

核对日期：2026-11-17。本文只写到「第一版白盒能走通、能看图、能量帧」为止。精模、全套彩画、十四胁侍的最终造型都不在第一版。

---

## 1. 第一版做什么、不做什么

### 做

- 五区白盒：院落远望（A）、台基与月台（B）、殿门与中轴（C）、侧向与群像（D）、梁架与回到中央（E/F）。
- 大雄殿体块：九间×五间、单檐庑殿、青灰瓦、3 米台基、月台、踏道、三门四窗、三块竖匾。
- 殿内：七佛体块（七尊不同高度/手印/头向）、14 胁侍体块、2 天王体块、佛坛、背光、倒坐观音（可省）。
- 梁架：八缝、彻上明造、斗拱剪影、彩画色带；不追求每一铺精模。
- 一条可走通的路线，键盘 + 触摸。
- 六个候选机位。
- F01 入口漫射天光的第一版光模型；殿内可读、不死黑。
- 三层声场的合成层（院外/门洞/殿内），先做 Z1/Z3。
- 无量殿/天王殿的外观；内山门/牌坊/外山门只作背景体块。

### 不做

- 整座寺院的所有配殿/西宫禅院/钟亭碑亭内部。
- 七佛/胁侍/天王的最终精模；第一版用体块 + 手印/头向差异。
- 彩画/壁画的逐铺/逐幅精绘；第一版用色带/剪影。
- 十四胁侍的身份考证与命名（学界未定）。
- 绕到佛坛背后、登佛坛、撞钟、拓碑。
- 七印/朱印体系；T05 用「观察页·三页」。
- 四季四时的全部 16 种；先做 J01 初冬晴冷 + J02 雪后。
- 多人、NPC、对话树。
- 2025 年修缮的脚手架/围挡（游戏标明「非今日实况」）。

- [ ] 从 A 到 F 全程可走，无卡死、无穿模、无掉出。

- [ ] 三张观察页都可跳过；一页不做也能走到 F 并结束。
- [ ] 六机位都能站人、能取景；CAM-06 不硬塞七尊。
- [ ] 七佛在体块阶段就能看出「不一样」：高度/手印/头向/袈裟/胸衣。
- [ ] 14 胁侍不是 14 份复制品；2 天王在两端。
- [ ] 殿内光比成立：门亮、佛坛暗、梁架更暗；脸可读。
- [ ] 无页面错误、控制台错误、失败请求。

## 3. 白盒的技术路线

### 3.1 先分关卡，再写内容

T00 的平面与关卡数据还写在引擎里，拆分是 #138。T05 不要重复这个错误：

- `app/levels/t05/`：平面、建筑参数、views、places、locales、gallery、boards、hall-views。
- `app/shared/`：引擎、材质、行走、镜头、音频、界面。
- 如果 #138 还没做完，先在 `app/src/site.js` 里加一个 `T05` 分支，但**把数据放在 `app/levels/t05/site-t05.js`**，不要散在引擎里。

### 3.2 建筑

- `buildLiaoHall`：九间×五间、单檐庑殿、青灰瓦、减柱、彻上明造、七铺作。
- `buildPlatformYuetai`：3 米台基 + 37×15 月台 + 18 级踏道 + 钟亭/碑亭。
- `buildLiaoGate`：内山门/牌坊/外山门只作背景体块；第一版不做内部。
- `buildWuliangHall`：无量殿/天王殿，清初，五间（一说三间），单檐歇山，16.14×12.22；可作「辽代造像」小展室。
- 所有建筑先做体块 + 屋顶剪影，再做斗拱/门窗/匾。

### 3.3 造像

- `buildSevenBuddhas`：七尊共享基础人体，但头/手/袈裟/胸衣/座/背光分别做。
  - 手印：迦叶禅定、毗婆尸说法、释迦与愿；毗舍浮/拘那含牟尼按已知指式；拘留孙/尸弃先做「待核」的通用印，不要编。
  - 高度：中央 9.0 米，两侧 8.6–8.9 米（白盒）；现场再核。
  - 头向：释迦略向西/右转；其余正南。
- `buildAttendants`：14 尊，3–4 个姿态模板 + 每尊冠/衣纹/手势差异；不命名。
- `buildGuardians`：2 尊，持杵，3.5–4 米。
- `buildBackGuanyin`：明代，面北；第一版可省。

### 3.4 彩画/壁画

- `buildLiaoCaihua`：朱红衬地 + 矿物绿/白/黄丹 + 铁线描；飞天/网目纹/宝相花三种母题；按梁架分件排布。
- `buildYuanMural`：东西墙十佛、北墙八菩萨、南尽间十一面观音；暗色、大人物、空背景。
- 第一版只做色带/剪影；精模再做纹样。

### 3.5 地面与可走性

- 院落地坪 0；台基/月台 +3；殿内地面 +3；佛坛 +3.87。
- 台基/月台是 `decks`；踏道是 `ramps`；佛坛是 `solids`。
- 佛像/胁侍/天王是 `posts`（圆形，半径按体量放大）；柱是 `posts`。
- 台基/月台边缘做栏杆/挡墙，不做 `drops`。
- 殿内不能有雪/雾/花瓣；`dress()` 要关掉。

### 3.6 镜头

- 第一版用 T00 的第三人称跟随 + 第一人称；不做新的镜头系统。
- 六机位用 `views` + `shots.js`；`?show=cam01` 等。
- 大雄殿的屋檐/屋脊进 `walk.roofs`；否则跟随镜头会穿屋顶。
- 48×25 米的室内，`eyeShut` 要重新标定；第三人称不能穿墙/穿佛坛。
- CAM-06 用 65° fov，但**不声称看全七尊**；验收需要全景时用三张拼接。

### 3.7 光

- 第一版：南面开口 + 天光 + 地面反弹；不做复杂 GI。
- 殿内光比 8:1–16:1；佛脸可读；梁架不死黑。
- 可加一盏极弱 altar lamp；标为设计补光。
- 雪后变体：屋顶/台基/院子有雪；殿内没有雪。

### 3.8 声音

- 第一版做 Z1（院外县城）+ Z3（殿内长混响）；Z2 门洞滤波可后补。
- 脚步：砖/石/门槛三种；`steps.js` 扩展。
- 音乐默认无；若做，只在进门/回到中央各一小段。

## 4. 性能预算（草案，必须实测）

T00 的数字（T4，1080p）：

- 首院高档 9.3 ms，低档 4.7 ms；屋顶是三角形大头；绘制次数比像素更紧。
- `?tour=120x3` 高档平均 61 fps，95th 21 ms。

T05 的体量估计：

| 项 | 估计 | 依据 |
|---|---|---|
| 大雄殿建筑 | 25–40 万三角 | 九间、屋面、斗拱、梁架；比 T00 的单殿大 |
| 七佛 | 7×4–6 万 = 28–42 万 | 8–9 米，近景可看；3 个 LOD |
| 14 胁侍 | 14×8–12k = 11–17 万 | 2.5–2.7 米；2 个 LOD |
| 2 天王 | 2×10–15k = 2–3 万 | 3.5–4 米 |
| 佛坛/座/背光 | 5–10 万 | 七座须弥座 + 背光 |
| 彩画/壁画 | 2–5 万（几何）+ 纹理 | 主要是纹理/贴图 |
| 无量殿/月台/钟亭/碑亭 | 5–10 万 | 背景/第二站 |
| 院子/围墙/地面 | 2–5 万 | 平原院子 |
| 总三角形 | **80–140 万** | 高于 T00 的 110 万，低于 T01 的 110–190 万 |
| 绘制次数 | **180–300** | 需合批；七佛/胁侍/梁架/彩画可能各占几批 |

**目标**：高档 1080p ≤12 ms，低档手机尺寸 ≤6 ms。达不到就砍：先砍院子细节、无量殿、胁侍的 LOD、彩画纹样分辨率；**不要先砍七佛的面部/手印**。

**量法**：同一个 GPU job 里比差值；报告带站点指纹；不用软件渲染的数字外推。

**T05 的特殊风险**：

- 48×25×16 米的室内，比 T00 的房间大一个量级；`inside.cjs` 的相机/近平面要重新标。
- 七佛 8–9 米，近景面部占屏幕很大；不能用低模糊过去。
- 14 胁侍 + 2 天王 = 16 尊；如果都用独立网格，绘制次数会爆；需要合批/LOD/实例化的「非七佛」部分。
- 彩画/壁画的纹理如果太大，移动端会爆内存；需要 1024/2048 两档。
