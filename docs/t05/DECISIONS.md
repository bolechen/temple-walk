**2026-11-21，殿里不灌雾，门洞才暗得下来**（主创同意，单独一个 PR #481，回应 Fable 第 4 条）。

- **判法**（美术总监给，主创转，照原话）：
  - **白盒阶段（夏昼雾）**：A 站（z = 44）门洞中部和正面墙的亮度比 ≤ 0.60。主判另取一张近处图：站在月台上，正对当心间，门外 6 m，门洞中部和正面墙的亮度比 ≤ 0.25。两条都过才算。
  - **成图阶段（T05-J01 初冬晴冷）**：A 站 ≤ 0.20，门洞和直棂窗的亮度比 ≤ 0.5；cam02 上门洞是画面里最暗的大面。这一条写进成图那一项的验收。
  - **量法**：门洞取当心间门洞中间六成的面积，墙取尽间的实墙，算屏幕上线性亮度的平均。
- **原因**有三处，都查清了：
  - 雾：three 的雾按距离加，后墙离眼约 70 米，殿内多暗都被雾抬亮。
  - 壁画底：殿墙内侧那层壁画底的面和墙的内面重在一处，两面争同一个像素，亮的墙面一条条、一斜片透出来。美术总监看到的「后墙斜向明暗分界」就是这个。
  - 地面：殿内地面是台基顶的一整块面，殿内遮蔽到不了它。
- **做法**：
  - `fog.js` 加一个「不受雾的盒子」（`U.uFogShut`、`U.uFogShutY`，关卡用 `site.fogShut` 给）。视线在盒子里那一段不计雾，铺地的 `fogMix` 也照这样算。序章不给盒子，八个殿的门内图逐字节相同。
  - 壁画底离开墙面 5 厘米。
  - 殿内单铺一层地面。
  - 殿墙以内各面受 20% 的天光；补光关掉。
- **本 PR 的数**（线性亮度）：
  - A 站：0.24，过（≤ 0.60）。
  - 近处图，门外 6 m：门洞 0.017。
    - 同一站位转过去量尽间实墙是 0.255，比值 0.067，过（≤ 0.25）。
    - 近处图正对当心间，画面里看不见尽间。画面里能看到的墙只有门额上那一条，在檐下的阴影里，只有 0.031，用它算是 0.54。
    - 哪一种算，请美术总监定。
