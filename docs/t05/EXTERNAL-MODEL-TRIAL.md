# 外部模型造像试验：T05 七尊的头（GPT 6.2 Astra）

2026-11-25 起草。所有者问：「听说 GPT 6.2 Astra 的 3D 能力比较强，单独的 3D 建模可以拿一个任务给他试一下」「拿 T05 佛像合适吗？这个是当前的卡点」。本页只准备材料，不建模、不花 Tripo 点数、不动 `app/` 和 `tools/`。我们调用不了 GPT：由所有者把第三节的任务说明和附图贴给它，再把它交的文件交回来，接入、出图、送审由我们做。

## 一、结论

1. **合适，但要把题目收窄到「头」。** 七尊现在卡在脸上，不卡在身子上：
   - 游戏里站的还是白盒泥块（`app/levels/t05/altar.js`），真像在 `tools/` 的审图台里，Tripo 网格加我们自己的修形和上色，已经做了七轮（#407、#463、#683）。
   - 挡进殿的是神情：皱眉、撅嘴，拘留孙、毗舍浮、拘那含牟尼的下唇和下面那团圆垫在仰看里读成张开的口（#701；美术总监：「佛的脸不静，后面什么都立不住」）。动网格五次没动到那一团，美术总监让先试上色，压不住再回网格，那时要换手段或重出头。
   - 眼睛暂用闭目，目标是半开垂目（#516，所有者定的），现有网格的上睑是按闭目雕的，画不出睁眼。
   - 所以最值钱的一题是：**一颗神情安静、半开垂目、嘴闭合的头**，做成独立的闭合块，套到现有的身子上。成了，#701 和 #516 一起解掉；不成，只损失所有者贴两三轮的时间。
2. **交付用网格（GLB），不用 `building.js` 那样的生成函数。** 理由见第二节。拿不出二进制文件时，退一步交一个 Blender 脚本，由它在我们这边生成 GLB。
3. **我们这边不另做一版对比。** #701 正在用不花点数的办法修现有网格的嘴，它就是我们的那一版；两边在同一组机位、同一份上色配方、同一台 T4 上比。要不要再花点数让 Tripo 重出一颗头作第三方，等这次结果出来再说。
4. **所有者 2026-11-25 定了：只做头，七尊共用一张脸**（逐尊微调头向、头宽比）。还剩登记方式一件，见第六节。

## 二、两种交付方式

| | 生成函数（照 `building.js`，JS 里用代码搭几何） | 网格文件（GLB），由我们接材质 |
|---|---|---|
| 适不适合佛头 | **不适合**。建筑是参数化的直线和曲面，一张表就说得清；脸是连续的有机曲面，神情差在毫米级（唇凸、眉心、嘴角），用 JS 搭基本体很难到这个精度，Tripo 的高模都还在调 | **适合**。外部模型擅长的就是这类形；我们的造像管线本来就是吃网格的 |
| 能不能接上现有管线 | 接不上：上色走的是像自己坐标里的锚点和掩码（`tools/t05-hall/paint.js`、`mask.py`），法线贴图从高模烘，LOD 用 meshoptimizer 减，都要一块网格 | 直接接：焊点、闭合检查（`closed/topology.py`、`gate.py`）、三档 LOD、法线烘焙（`bake.py`）、锚点、上色配方，命令都在 |
| 和 `procMat` 的关系 | 造像本来就不走 `procMat`；七尊用的是 `paint.js` 改的 `MeshStandardMaterial`（按锚点分区、mood 的光照照常） | 同左，不用新东西 |
| 复现 | 代码在库里，可复现 | 文件进证据库，SHA-256 登记；若交的是 Blender 脚本，脚本进库，同一输入跑两次逐字节相同（`tools/blender/README.md` 的规矩） |

**推荐：GLB 高模；退路是 `bpy==5.3.0` 的无界面脚本，输出同样的 GLB。** 颜色、贴图、季节、雪都不要它做：佛像在殿内，不积雪；颜色由 `ART.md` §3.1 和 #683 的配方定，交来的东西只要几何。

## 三、任务说明（直接粘贴）

把下面整段贴给它，并附上第四节列的图。

```text
你好。我在做一个网页 3D 游戏（three.js），场景是一座辽代风格的古寺大殿，殿里一排坐着七尊彩塑佛像，
每尊连座高约 9 米。佛像的身子已经有了，现在卡在脸上。请你做一颗佛头，作为独立的 3D 网格交给我。
这颗头会用在七尊上（之后由我们逐尊微调头向和宽窄），所以要一张七尊都用得上的、安静的佛脸。

【要的是什么】
一颗汉传佛教彩塑坐佛的头，从颈根到肉髻顶，含螺发、肉髻、双耳（长耳垂，不穿孔）。
只要几何（形），不要颜色、贴图、材质；上色由我们自己做。

【神情（最要紧）】
静。具体是：
- 眉：平，眉头不低于眉梢；眉心没有竖褶，不皱眉。
- 眼：半开、往下看（垂目）。上睑厚而下垂，睑裂张开约为眼宽的 0.2–0.3；正视看得见一条眼裂，
  不能读成闭眼，也不能读成瞪眼或斜视。上睑是实心的厚块，不是一片悬空的薄片，睑下不能有缝。
- 嘴：小，闭合，嘴角微微上收（嘴角比下唇中点高一点，不往下撇）。不撅嘴：上下唇不向前突出。
  下唇下面不要有圆鼓鼓的垫（颏唇隆起），颏和下唇之间是一道很浅、很缓的过渡，
  否则从下往上看会读成张着嘴。人中浅。
- 下巴：圆而收，不前突，不堆肉。
- 整体：宽脸、额平、颧不突，安静写实，不是卡通，不是日式动漫，不是泰式或藏式的尖肉髻。
参考：附图 A、B 是我们自己出的原型图（同一组像的正面和背面），脸要和它们读成同一种神情和同一家人。
附图 C 是一尊真像的照片，只参考眼睛半开下视的样子。附图 D、E 是我们现在的毛病（下唇下的圆垫在仰看里像张口），请避开。

【观看条件（决定什么要做准）】
访客永远是从下往上看：殿门口约 17 米、仰角 23°；殿中 10 米、仰角 36°；佛前 4 米、仰角约 60°。
请在仰角 36° 和 60° 下也检查神情：仰看会放大下唇和下巴的体量，会把眉心的褶读成皱眉。

【尺寸和坐标（必须照做）】
- 单位米，Y 轴向上，脸朝 +Z，左右对称轴是 X = 0。
- 原点放在颈部底面的中心。
- 尺寸：原点到肉髻顶约 2.2 米；嘴宽约 0.50 米；眉线到嘴缝约 0.60 米；头宽与头高之比 0.71–0.83。
- 颈部往下多留约 0.35 米的颈根，底面封平。这颗头会「插进」身子的颈口里，不和身子缝合，
  所以它自己必须是一个完整的闭合体。

【网格要求】
- 一个或少数几个各自闭合的块（水密：每条边恰好两个面，没有开口边、没有非流形边、法线朝外一致，
  没有游离碎片，没有自相交的壳）。螺发可以是和头皮相交的独立闭合小块。
- 高模：面数 30 万到 200 万之间都可以，越能把唇、睑、螺发的形做准越好。我们会自己减面到 2 万 / 6 千
  并从高模烘法线贴图，所以细节放在形上，不放在贴图里。
- 不要贴图、不要 UV、不要顶点色、不要骨骼。

【交付】
1. 首选：一个 GLB 文件（glTF 2.0 二进制）。
2. 如果你不能直接输出文件：交一个 Blender 5.3（Python 模块 bpy==5.3.0，无界面运行）的脚本，
   运行 `python3 make_head.py out.glb` 就生成上面那个 GLB；不联网、不下载任何东西；同样的输入跑两次，
   输出文件逐字节相同（不用随机数，或固定种子）。
3. 附一段说明：面数、包围盒尺寸、你做了哪些检查（水密、对称、尺寸），以及你对神情各条是怎么处理的。
4. 附三张你自己渲染的灰模图：正面平视、正面仰角 36°、侧面。

我们会把它装到身子上，按上面的观看条件出图，由两位评审看，评审意见交回给你再改一两轮。
```

## 五、评分标准

两边（外部模型的头、#701 修过的现有头）走同一套。每一轮都记：轮次、所有者花的时间、交来到可审的接入工时。最多比三轮，看谁收敛得快，不只看第一版。

### 5.1 进门检查（接入的人做，不过就直接退回，不送审）

| 项 | 线 | 怎么量 |
|---|---|---|
| 闭合 | 开口边 0、非流形边 0、≤10 面碎屑块 0、朝向一致 | `python3 tools/t05-statue/closed/topology.py <head.glb>` |
| 尺寸与朝向 | 原点到肉髻顶 2.2 m ± 5%，嘴宽 0.50 m ± 10%，脸朝 +Z、对称轴 X = 0 | 包围盒加 `face-measure.py` 取点 |
| 减面 | 减到 2 万、6 千后轮廓不破、不出洞（三档同一套锚点） | `tools/t05-statue.mjs --error=0.05 / 0.1` 后再跑 `topology.py` |
| 法线烘焙 | 高模烘到近档无大片错色、睑下和唇缝不出黑斑 | `tools/t05-statue/bake.py` 的出图 |
| 脚本（若交的是脚本） | `bpy==5.3.0` 无界面能跑，不联网，两次输出 SHA-256 相同 | 跑两遍比哈希 |

### 5.2 Opus 初审（3D 评审，判形）

在高模上量，数写进 PR：

- 唇凸 / 嘴宽 ≤ 0.03；眉心褶深 ≤ 0.01 脸宽；眉头不低于眉梢；嘴角比下唇中点高 0–0.06 嘴宽（#463 的四个量）。
- 颏唇沟深度 ≤ 嘴宽的 8%；颏前点相对下唇前点的前凸 ≤ 释迦原型值 + 0.03 嘴宽（#701 3D 评审的线）。
- 睑裂开口 0.2–0.3 眼宽（#516）；眼区以外离脸平滑面超过 5 mm 的薄片为 0；睑下无缝、睑缘无破碎三角（#463 r8C 的意见）。
- 装上身子后：颈部插接处在六个访客机位看不见缝和穿插（`closed/backfaces.py` 的背面视线不多于原件）；头和身子的比例、头向和原来一致或经评审认可。
- 灰模出图：10 m 平视、10 m 仰看（`faceFrom10`）、4 m 仰看、3 m 侧面。

### 5.3 美术总监终审（判画面）

上 #683 的配方（唇、肤、螺发分区照现行线），在 T4 上出殿内光的图：

- 10 m 仰看和佛前 4 m 仰看：读成「闭着的唇和圆颏」，不读成张口；不皱眉、不撅嘴；读成「半开、往下看」，不是闭眼、不是瞪眼。
- 和原型图 A、B 并排，读成同一种神情、同一家人；若共用一张脸，七尊并排的 cam03、cam04 读起来仍是一组而不是七份复制（美术总监判）。
- cam03 门口初见：中间三张脸读得出（PRD §9 第 6 条③），不比现在差。
- 唇的现行线不退：唇亮度是头部的 0.58–0.64，唇饱和比颊高 0.10–0.15，色相 12–16°（#480 第七轮）。

### 5.4 T4 帧耗门槛

- 口径照 `docs/t05/PHASE2-COST.md`：同一个 Job 里新头和现有头交替，高档 1920×1080 的 cam03、cam06，低档 960×540 的 cam03，每处两轮倒序。
- **门槛**：①新头近档换上后，比现有头同档多不超过 0.3 ms（两档都算）；②七尊接入后整帧 cam03、cam06 高档 ≤ 12 ms、低档 ≤ 6 ms（PRD §9 第 7 条）。参考：白盒台子上七尊近档上色约多 2.5 ms，现在 cam03 冬昼 8.22 ms。
- 体积：每颗头近档 GLB（meshopt 压缩后）加一张 2048 法线图，合计 ≤ 1.5 MB。

## 六、要所有者定的

设定上已经写死的，不再问：七尊的排列和尊名（`DECISIONS.md` 2026-11-20）、各尊手印与衣式（`refs/t05-concept-2026-11-21/README.md`、释迦改与愿印 2026-11-21）、眼睛的目标是半开垂目（#516）、颜色规则（`ART.md` §3.1）。这次只换头，手和衣都不碰。

没有写死、要所有者定的（1、2 两条所有者 2026-11-25 已在决定卡上选「只做头，七尊共用一张脸」）：

1. **只做头，还是整尊。** 推荐只做头：卡点在脸；身子、手印、衣式已经过了好几轮审，整尊重来等于把这些审再走一遍。整尊也能试，但要多给它正背面和侧面，接入还要重对全部锚点（约 1 天）。
2. **七尊共用一张脸，还是只先给一尊。** 原型图六张脸画的是同一个面相（主创 2026-11-21：「面相、肉髻、螺发、体量……一致，看得出是一组」），真寺里七尊也是一个作坊的手。共用一张脸、逐尊微调（头向、头宽比），七尊的脸一次就能统一；但「七尊共用一张脸」是设定图上没有写的，所以问所有者。不共用，就只先给拘留孙，过了再说别的六尊。
3. **怎么登记外部模型的产出。** 照 Tripo 和原型图的做法：`asset-register.csv` 一行写「所有者用 GPT 6.2 Astra 生成，交本项目使用」，原件进证据库，SHA-256 登记；`SOURCES.md` 标「所有者指定」。若对这家服务的商用条款有顾虑，所有者说一声，我们先查条款再接。
