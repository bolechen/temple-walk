# 造像管线：T05 七佛与 T00 佛像重做（#315）共用

核对日期：2026-11-20。issue：#359 验收第 4 条。依据：七佛造像试验 #280（PR #285，`STATUE-SPIKE.md`）、彩塑上色试验 #287（`COLOR-SPIKE.md`）、#315 正文与所有者 2026-11-20 的评论、`LATEST-GOALS.md` 第 63、65、70、71 条。本页只写计划，不花点数。

## 一、结论

1. **一条管线，两个用户。** T05 的七佛（以后还有十四胁侍、二天王）和 T00 殿里要换掉的博物馆扫描（#315），走同一条「查清史实 → 提示词与种子 → Tripo 出几何 → 焊点减面 → 分档 LOD → 近档烘法线 → 按区上色 → 进殿验收」。差别只在第一步谁定（T05 等顾问，#315 等所有者批史实表）和第三步每尊写什么。
2. **几何用 Tripo，颜色用我们自己的材质。** 这是 #280 的推荐（路 A）和 3D 评审在 PR #285 上的意见；路 B（公有领域扫描）没有辽、金、北宋的坐佛，手印改不了（`STATUE-SPIKE.md` 结论 2）。
3. **试验留下的三个洞，正式做之前先补**，它们不等顾问：①6 万面的脸一贴金就露折面（`COLOR-SPIKE.md`「最大的问题」1）→ 近档从 148 万面的原件烘法线贴图；②从正投影图读锚点会读错（同上 2，释迦的前臂）→ 半天做一个「在模型上点一下给出像自身坐标」的取点工具；③再往下减面减不动（6 万面停住，三档 LOD 没验）→ 改用 meshoptimizer 带属性的简化和更大的误差上限，或 Tripo 的智能重拓扑接口（见 §四）。
4. **暗殿要光照探针。** 不给反射，贴金在暗殿里是黑的（`COLOR-SPIKE.md` 结论 2）。试验用的是 `PMREMGenerator.fromScene` 拍一张环境图。本机的 three r186 里还有一个现成的探针格子 `LightProbeGridWebGL`（`node_modules/three/examples/jsm/lighting/LightProbeGridWebGL.js`，`WebGLRenderer.js` 里有 `isLightProbeGrid` 的分支，2026-11-20 核过文件在），按说明是 L2 球谐、可以在 GPU 上分批烘、多次反弹。它能不能让 `procMat` 和像的材质自动吃到殿内的漫反射，**没验**；T05 第二阶段第一件事就是拿白盒殿比这两种（§五）。

## 三、共用的工具放在哪

- **离线工具**：`tools/statue/`（新目录）——`tripo.mjs`（由 `tools/t05-tripo.mjs` 改名搬来，带 `--level`）、`prep.mjs`（由 `tools/t05-statue.mjs` 搬来，加 LOD）、`bake-normal.*`、`anchors.cjs`、`views.cjs`（单尊四面、五个距离的出图，照 `tools/novice-views.cjs` 的做法）。旧名各留一个转发，直到 #280、#287 的复现命令不再被引用。
- **页面代码（引擎，各关共用）**：`app/src/statue-paint.js`（由 `tools/t05-hall/paint.js` 搬来，接三档 LOD 共用一套锚点）、`app/src/statues.js`（按距离取、LOD、探针）。
- **每关的数据**：`app/levels/<id>/statues/`（提示词、锚点、GLB、法线图）。按 `CLAUDE.md` 的规矩，在本仓库加工过的文件连同生成它的工具进 git；Tripo 原件和中间件进证据库。
- **和小沙弥接入（#163）共用的**：分件、补面、贴图压缩那几步（`tools/novice-tripo.mjs` 一带）。#315 正文写明「#163 先做，工具可以共用」，所以 `tools/statue/` 在 #163 合并后再建，免得两边各搬一次。

## 五、哪些等顾问，哪些不用等

**等顾问（`ADVISOR-BRIEF.md` 的八问）：**

- 七尊各自的手印（尤其拘留孙、尸弃、毗舍浮、拘那含牟尼和释迦），衣式（迦叶通肩还是袒右），排列与中尊（问 1–3）。**手印定前不生成正式七尊**（第 65 条）。
- 彩塑各部分的颜色和做法、胸衣花纹还是龙纹、背光是否逐尊不同（问 5、6）→ 决定锚点的区和 `recipe` 的值。
- 玩家能对佛像做什么、取景和灯光的分寸、像前文字（问 7）→ 决定 `PRD.md` §6 里「合掌」做不做。
- 「七佛与辽七帝」一说提不提（问 8）。

**不用等，现在就能做：**

- 白盒殿、院落、台基、六站、烘焙地面（`PLAN.md` 第一阶段）。七尊先用体块，高度、头向、座高按 `DECISIONS.md` §3「可由主创定」。
- 试验里已生成的三尊（毗婆尸、迦叶、释迦，证据库里有原件）作**占位**放进白盒殿看比例和光，不当正式像。
- 工具：`tools/statue/` 的搬家、LOD、法线烘焙、取点工具（§二第 4–6 步），用试验那三尊做测试数据。
- 光照探针对比：`PMREMGenerator.fromScene`（一张环境图）对 `LightProbeGridWebGL`（探针格子），在白盒殿的 CAM-03、佛前 10 m、侧廊 12 m，T4 同一 Job 量帧耗、出图。
- 走进殿门的曝光渐变（three 没有现成的，#280 风险表已列）：在 `post.js` 里按「在殿内的程度」调曝光，先做灰盒光比测试。
- #315 的史实表（第 0 步）。
