# 造像管线：T05 七佛与 T00 佛像重做（#315）共用

核对日期：2026-11-20。issue：#359 验收第 4 条。依据：七佛造像试验 #280（PR #285，`STATUE-SPIKE.md`）、彩塑上色试验 #287（`COLOR-SPIKE.md`）、#315 正文与所有者 2026-11-20 的评论、`LATEST-GOALS.md` 第 63、65、70、71 条。本页只写计划，不花点数。

## 一、结论

1. **一条管线，两个用户。** T05 的七佛（以后还有十四胁侍、二天王）和 T00 殿里要换掉的博物馆扫描（#315），走同一条「查清史实 → 提示词与种子 → Tripo 出几何 → 焊点减面 → 分档 LOD → 近档烘法线 → 按区上色 → 进殿验收」。差别只在第一步谁定（T05 等顾问，#315 等所有者批史实表）和第三步每尊写什么。
2. **几何用 Tripo，颜色用我们自己的材质。** 这是 #280 的推荐（路 A）和 3D 评审在 PR #285 上的意见；路 B（公有领域扫描）没有辽、金、北宋的坐佛，手印改不了（`STATUE-SPIKE.md` 结论 2）。
3. **试验留下的三个洞，正式做之前先补**，它们不等顾问：①6 万面的脸一贴金就露折面（`COLOR-SPIKE.md`「最大的问题」1）→ 近档从 148 万面的原件烘法线贴图；②从正投影图读锚点会读错（同上 2，释迦的前臂）→ 半天做一个「在模型上点一下给出像自身坐标」的取点工具；③再往下减面减不动（6 万面停住，三档 LOD 没验）→ 改用 meshoptimizer 带属性的简化和更大的误差上限，或 Tripo 的智能重拓扑接口（见 §四）。
4. **暗殿要光照探针。** 不给反射，贴金在暗殿里是黑的（`COLOR-SPIKE.md` 结论 2）。试验用的是 `PMREMGenerator.fromScene` 拍一张环境图。本机的 three r186 里还有一个现成的探针格子 `LightProbeGridWebGL`（`node_modules/three/examples/jsm/lighting/LightProbeGridWebGL.js`，`WebGLRenderer.js` 里有 `isLightProbeGrid` 的分支，2026-11-20 核过文件在），按说明是 L2 球谐、可以在 GPU 上分批烘、多次反弹。它能不能让 `procMat` 和像的材质自动吃到殿内的漫反射，**没验**；T05 第二阶段第一件事就是拿白盒殿比这两种（§五）。

## 八、七尊的出厂姿势与脸（#701，2026-11-25 定）

做法在 `docs/t05/evidence/701-final/README.md`（逐尊的表）与 `701-r1`…`701-r35`（逐轮的图与数）。要点：

- 管线：原模 → r3c 操作（焊接容差 **1e-8**，不是 1e-6；1e-6 会塌 210 个面）→ `tools/t05-statue/face-ship.py`（莲座以上绕座后缘前倾 4°、头再倾 10°，合计 14°；颏按 L4 重建；各尊另做的几笔）→ `repair.py` → 分区减面 `zoned.mjs`（脸盒不减 / 耳 8,500 / 颈·手 ~9.0k / 其余 ~31k；档的归属按 r3c 站直时的盒子，`--member`；头已倾的文件再加 `--unbow`）→ `bake.py --face=`（脸区不带法线）→ `pack.mjs`。一条命令：`tools/t05-statue/ship-fig.py`；总表：`fig-sheet.py`；打包上桶登记：`ship-upload.py`。
- 释迦牟尼是另一条管线（#514 的与愿印嫁接）：不倾身，头 14°，`ship-fig.py --from=… --prebow=10`；`closed/gate.py` 管手/膝。
- **改嘴之前先核 `face.json` 的嘴角坐标**：嘴角在 x = ±0.25 m。701 的前两轮把「鼻唇沟」块子放在 x 0.115→0.135 m、「嘴角窝」块子放在 x 0.155→0.175 m，**都落在两嘴角之间**（鼻底下、唇上），抹掉的是唇框和唇红的外圈，不是脸颊上的沟；毗婆尸 10 米上的唇线化开、上唇鼓软就是这个（701-r33/r35）。真在脸颊上的沟与窝要放在 |x| > 0.26 m；块子的软边不能停在嘴角上，停在脸颊平处。拘那含的 K1L 用了那两个块子（在嘴角之间），脸总监已认，没有回头。
- **烘好以后、打包以前可以再补一步（2026-11-26，#763，现在只有释迦用）**：`node tools/t05-statue/mend.mjs <像> <烘好的.glb> <出.glb>`，按 `tools/t05-statue/<像>/mend.json` 做两件事：法线图上的坏点（朝向偏离表面超过 72° 的像素）用旁边的好像素补；形上按清单去碎面、剪细长面、压平翘边、给没有底的壳补一截圆筒。清单里的每一项都点名连通块（按三角面数）和一个盒子，文件换了、连通块对不上就拒绝，所以清单只对它写明 SHA-256 的那个文件有效。新加的点都落在法线图上一处中性的位置，靠自己的法线受光。外框不许动（页面按外框立像，锚点从外框量），工具自己查。释迦：`sakyamuni-V14b.glb` → `sakyamuni-V14c.glb`，再 `node tools/t05-pack-figures.mjs <入> <出> 1024 sakyamuni`（后面可以只点名要打包的像）。
- **判腕、手这些近处的东西，用访客真能站到的地方看**：释迦在佛坛最西端，离他的右手最近的是西廊（像自己的坐标里眼在 (−4.05, 0.2, 2.6)）和坛前（(−1.95, 0.2, 3.1)），都是在四米外往上仰 55–65° 看；平视的特写不是访客看到的，拿它判会修错地方。
- 近视点上的限度：这七尊的形是「正前 10 米略仰」与「侧廊斜看（7 m、斜前 55°、眼高 1.6 m）」两个机位判的；正侧只作检查。
- **尸弃的颏面（2026-11-26，美术总监追加一小单，701-r36）**：灰模上下半脸「花」，是颏面鼓面上的几个小隆起（三个小丘）。只在颏面抹平：`face-ship.py --chin-smooth=0.4`（`flatblocks` 的椭圆块，中心在唇下 0.24 m、半宽 0.15、半高 0.08、软边 0.10，起伏保留 0.4，150 遍）。试过起伏保留 0.2–0.25、软边 0.03–0.06：颏面会成一块有硬边的平板（圆盘），弃；唇、嘴角不动（唇带点位移最大 0.22 mm），颏中线最前点只退 2.9 mm（颏面内点位移最大 28 mm）。现用文件 `sikhin-M40v*`，取代 `M40`。
