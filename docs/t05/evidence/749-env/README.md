# #749：去掉一直全黑的环境光贴图

## 改了什么

`app/src/sky.js` 原来每换一次心境就用 PMREM 从天穹烤一张环境光贴图，设成 `scene.environment`，所有 `MeshStandardMaterial`（含 `procMat` 的木、石、瓦、铜、金……）每个像素都去查它两级 mip。可 `PMREMGenerator.fromScene(env, 0.02)` 的立方相机远平面是默认的 100 m，天穹半径 600 m，整个被裁掉，相机只看见渲染器的清屏色（从没设过，黑）。所以这张贴图从来全是 0，每个像素查来的光都是零。

现在不设环境贴图（`scene.environment = null`），也不再烤。黑贴图贡献的光是精确的 0，去掉以后画面不变；省下的是每个受光像素那几次纹理查询。T05 殿里七尊的金身用的是它们自己的殿内光探针（`levels/t05/figures/load.js` 的 `envMap: state.probe`），不受影响。

真要让天光照亮表面（把远平面放到天穹之外），是改画面，要走美术审，不在这个 PR 里。

## 证据一：贴图里确实全是 0

`envprobe.cjs`：在改动前的代码（main 同一份 `sky.js`）里临时挂一个钩子，把当时的环境贴图整张读回（768×1024，半浮点），三个心境各一次：

| 页面 | RGB 最大值 | alpha 为 1 的像素 |
|---|---|---|
| `?level=t05&season=winter&time=day` | 0 | 532,992 |
| `?season=summer&time=day`（T00） | 0 | 532,992 |
| `?season=autumn&time=dusk`（T00） | 0 | 532,992 |

钩子只在本地 dev server 上挂过，没有提交。

软件渲染（SwiftShader）出图在同一站点上跑两次本身就有逐像素抖动（cam04 同站两次差 125,540 个像素、最大 24），所以没法拿软件出图证"逐像素一样"；改前改后的平均亮度到小数点后两位相同（cam04 74.28 / 74.28，court 87.04 / 87.04）。
