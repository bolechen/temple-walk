# #701 第四轮：r3 的 210 条开口边——不是退化面，是导入时的焊点容差

照 3D 评审（#701 评论 2026-11-25T11:02）的要求先修 `repair.py` 的导出，再出闭合的 r3c。评审推断「导出时删退化面前没先合并共点」；**我查到的位置不一样**，下面是做出来的，不是推断。

## 查到什么

- 不加任何操作（`ops: []`），只让 `repair.py` 导入再导出拘留孙原件：面数 1,463,014 → 1,462,804（少 210），开口边 0 → 210，非流形边 0 → 210。所以与配方无关，在导入/导出。
- 用 bmesh 逐步量：导入后 46,264 条开口边（Tripo 每个 UV 岛写一份点）；`remove_doubles(dist=1e-6)` 之后点 731,400、面 1,462,804、开口边 210、非流形边 210；再 `me.validate()` 之后不变（没有零面积面，最小面积 5e-9）。**所以是 1e-6 的焊接把相距几微米、不属于同一条缝的点焊在了一起，塌掉了 210 个面**，不是 validate 删了退化面。
- 容差试了几个：1e-9 和 1e-8 都得到 731,505 点（与 `topology.py` 的按位置焊接一致）、1,463,014 面、开口边 0、非流形 0；1e-7 就又开了 60 条。取 1e-8（`tools/t05-statue/repair.py`，一行，不改配方）。
