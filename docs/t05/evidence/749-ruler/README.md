# #749 量尺：`__cost` 只在画面画倒影时才画倒影

T4（`tools/gpu-render.sh t4-small`，Job `6b07ddddb6a90bbe997f8163`，运行 `20261126-072042`），J01 冬昼，高档 1920×1080，每行开一页、暖 1.5 秒、数 6 秒帧率、再 `__cost(40)`。`report.json` 是 Job 原样带回的报告，没有图（这次只量帧耗，量尺的改动不动画面）。

## 量的是哪棵树

不合并的本地测量树（没有推）：main `c0ea233` + #763 `7f4a9a9`（七尊）+ #762 `2ff363e`（殿内灯光，合并时只有 `docs/t05/DECISIONS.md` 冲突，取 #762 的）+ `ea99b3c`（殿门写死开着，同 #754 合并 T4 的做法）。
- 旧尺：上面这棵树，`base/` 路径（`BASE_SITE`）。
- 新尺：同一棵树再加本 PR 的 `yard.js` 一个提交（`report.json` 的 `site.commit` 是 `6ff059d`）。
- 两边都带七尊的模型（`KEEP_MODELS=1`；本 PR 顺手让 `BASE_SITE` 也认它，不然对照组的殿里是空的）。

## 为什么旧尺偏高

真实那一帧（`yard.js` 帧循环）只在 `quality.planar > 0 && mirrorOn && !inside` 时画地面镜子：`mirrorOn` 要站在 `mirrorAt`（脚下 −0.6 到 2.0 m）且关卡的 `mirror(mood)` 说要（T05：铺地湿，#753）。J01 是干石面，T05 的殿内站在 3 m 台基上，所以这五个机位的真实帧都不画镜子。`__cost` 原来只看 `quality.planar > 0`，每帧多画一遍整座寺的倒影。改后五处重画（帧、定格、`__cost`、`__probe`、`__censer`）都问同一个 `mirrorDrawn()`。

怎么证明新尺和真实帧走的是同一条路：
1. **新尺 ≈ 旧尺关掉倒影**：五个机位新尺均值与 `off=reflect`（新旧两边）都在同一个范围里（差 ≤ 0.6 ms，小于同站两轮之差，cam03 两轮差 1.2）。`off=reflect` 把 `quality.planar` 置 0，真实帧和 `__cost` 都不画镜子。
2. **真实帧没变**：按帧率折算的 ms（帧循环里真实画出来的，含无头浏览器自己的约 10 ms 呈现）旧新两边差 −0.85 到 +0.54，正负都有，在噪声里；若真实帧原来也画倒影，旧尺那边该慢 1.4–2.4 ms。
3. 三角形数、绘制次数旧新相同（帧循环里数的）。

注意：
- 旧尺下 cam06 这次 11.15，#754 合并 T4（`20261126-035734`，`d0b43bd`）是 12.60：那次是另一棵树（#763 `ddbfd63`、#762 加 penumbra 试验），也是另一个 Job，不能直接比。
- 新尺下最紧的是 cam02（11.56，第二轮 11.88）和 cam03（11.41，第一轮 12.01）；同站两轮跳动最大 1.2 ms。
