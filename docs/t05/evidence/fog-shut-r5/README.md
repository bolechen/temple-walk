## 这一轮改了什么

1. **殿墙单独成一个网格**。原先殿墙和院墙合在一个网格里，按室外画。
2. **墙的内皮一直到墙角都算殿内**。墙是只有角点的长盒子。山墙内皮的前端伸进了前墙的厚度里，那里的角点落在殿内盒子以外，被当成室外，亮度就顺着整面墙抹开了。上一轮东山墙是后墙的五倍，补光关掉也一样。现在按法线判：墙厚以内、朝殿里的面算殿内；朝外的面、顺着墙的面不算。
3. **山墙的壁画底收到前墙内皮为止**，不再伸进前墙。

单测：`t05-plan.test.mjs` 最后一条（墙角的内皮、外皮、壁画底的范围）。

## T00 不变：像素对比

**判法**（主创定，2026-11-21）：PR 对 main 的差，不超过 main 对 main 两次渲染之间的差。比分布，不只比最大值，三项都要满足：
- 平均差；
- 差 > 2/255 的像素占比；
- 差 > 8/255 的像素数。

**怎么跑的**：
- 软件渲染 1280×720，J01 夏昼，第一人称；
- 命令：`node tools/shots.js cam01@summer-day@first … cam06@summer-day@first`；
- 两份代码：main 2a2a575（单独的 worktree）和 33132ef（本 PR，4c14c8a 相对它只改了文档）；
- main 上 cam01、cam05 又各出了一张（`--tag=again`），量 main 对 main 的噪声。

**逐字节**：六张都不同。PR 和 main 不同，main 和 main 也不同：软件渲染每次跑都不完全一样，所以「逐字节相同、最大差 < 0.5/255」这一条，连同一份代码也过不了。

**怎么读**：
- 三张 cam01（两次 main、一次 PR）两两之间的差一样大，PR 那张不比两张 main 之间更远；cam05 也一样。
- 按字面，cam01 的 PR 对第一张 main，三项各比 main 对 main 高 1–7%；对第二张 main，平均差和占比更低，像素数更高。
- 单独一次 main 对 main 的样本，本身就在这个幅度里上下。

**差在哪里**：
- 差图是满屏均匀的细颗粒，没有边缘，也没有建筑或地面的形状。
- 差 > 30 的像素共 77 个，聚成几处，每处都是一片飘落的竹叶：只出现在其中一张图上，另一张那里是竹林的暗色。
- 最大差 163 在 cam01 的 (1032, 179)：PR 那张有一片黄绿色的叶子，main 那张没有。(1034, 497) 那处正相反，叶子在 main 那张。

**为什么不会变**：盒子为空时，`fogShut` 在做任何运算之前就返回 0，雾深度乘以 1.0。
