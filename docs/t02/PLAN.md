# T02 白盒与开工计划

核对日期：2026-11-17。本文只写到「第一版白盒能走通、能看图、能量帧」为止。精模、NPC、登顶、湖上航线都不在第一版。

---

## 1. 第一版做什么、不做什么

### 做

- 五区白盒：林间窄路（Z1）、岩口（Z2）、木楼下部（Z3）、侧向栈道（Z4）、上层小殿（Z5）。
- 一个主岩穴：洞口 37 × 32 m、深 27 m、内腹 10 × 12 m（提案值）。
- 一组原创架空木楼：蜃阁、上殿、观音阁、南安阁、库房五个体块 + 主平台 + 状元柱 + 短柱/横材。
- 一条可走通的路线，键盘 + 触摸；洞内第一人称，洞外可第三人称。
- 六个候选机位。
- 101 级石阶、侧向栈道、栏杆、岩口券洞。
- 林间窄路、洞口外的湖面/崖壁/杉林。
- 一间上层小殿室内（佛坛 + 像设占位 + 梁架 + 残彩）。
- 五段声场的第一版（Z1/Z2/Z3/Z5）。
- G01 岩下柔光（推演）的第一版光色。

### 不做

- 湖上航线、游船驾驶、码头排队。
- 现状重建的 10 栋建筑全部复原。
- 五座宋构的逐间精模、材份、彩画复原。
- 佛像精模、五百罗汉、千手观音。
- 一线天、状元桥、周边丹霞点。
- 多人、NPC、对话树。
- 七印/朱印体系（第一版用「岩行记」五处观察）。
- 四季四时的全部 16 种（先做基准 + 1 备选）。
- 夜景、灯光秀。
- Steam/桌面外壳。

## 2. 白盒的五个节点与验收

| 节点 | 位置 | 必须能做的事 | 验收 |
|---|---|---|---|
| Z1 林间窄路 | 湖边 → 洞口 | 沿石阶/土路上行；听水声渐近；看到洞口 | 不靠箭头能找到路；不穿岩；石阶可走 |
| Z2 岩口 | 洞口/券洞 | 穿过券洞，进入岩腹；第一次看见平台底 | 洞口高宽比成立；洞内暗但可读 |
| Z3 木楼下部 | 平台下 | 走到平台下，抬头看柱、梁、栈、岩壁 | 能数出 ≥4 类支点；不穿柱；平台不「浮」 |
| Z4 侧向栈道 | 南侧栈道 | 沿栈道走到上层；看两阁的高低差 | 栈道宽 ≥1.1 m；栏杆不挡视线；不掉下 |
| Z5 上层小殿 | 小殿/回望 | 进殿看梁架；回望洞口与湖 | 洞口是亮部；室内可读；回望成立 |

### 2.1 总体验收

- [ ] 从 Z1 到 Z5 全程可走，无卡死、无穿模、无掉出。
- [ ] 键盘（WASD/Shift/E/Space）与触摸（摇杆/点地/交互）都能完成。
- [ ] 五处观察都可跳过，不集齐也能到 Z5 并结束。
- [ ] 六个候选机位都能站人、能取景。
- [ ] 洞穴的尺度压得住木楼；木楼不是玩具。
- [ ] 柱、短柱、横材、岩壁的接触看得见；没有「一根柱撑全部」的视觉。
- [ ] 洞内暗但可读；洞口不过曝。
- [ ] 无页面错误、控制台错误、失败请求。
- [ ] 单测：从第一步洪水填充能走到每个命名地点。
- [ ] `pnpm run edges` 0 处超限；`nearplane` 无切割。
- [ ] `mobile-audit` 无 <44 px 控件、<12 px 文字、越界。
- [ ] T4 上量一次帧耗，记录在 `docs/t02/`（不是 T00/T01 的数字）。

## 3. 白盒的技术路线

### 3.1 分关卡

- `app/levels/t02/`：平面、建筑参数、views、places、locales、gallery、boards。
- `app/shared/`：引擎、材质、行走、镜头、音频、界面。
- 若 #138（关卡拆分）还没做完，先加 `T02` 分支，但**数据放 `app/levels/t02/site-t02.js`**，不要散在引擎里。

### 3.2 洞穴

- 新 `buildCave`：用参数化网格做洞口、洞腹、洞顶、左右钟鼓石；不要用一个巨大的球/盒。
- 洞壁是「反向 solids」：玩家在内部，镜头不能穿出；`walk.roofs` 要把洞顶算进去。
- 洞穴的 UV 用三向投影（triplanar），避免拉伸；AO 烘焙在顶点/贴图。
- 白盒先用低模 + 法线，不做 displacement。

### 3.3 木构

- `buildHall` 加 `style: "min-bei-song"`：穿斗 + 插拱 + 草灰泥 + 少柱础。
- 第一版：五个体块 + 屋顶剪影 + 平台 + 短柱；插拱只做正面可见的几朵。
- 状元柱：一根柱 + 柱头组物 + 大引；短柱/横材按「可见的支点」摆，不做满。
- 栈道/石阶：`stairGeo` + 木板 + 栏杆。

### 3.4 地面与可走性

- 洞底：不可直接走；用石阶/木栈/平台覆盖。
- 101 级石阶：级高 0.15–0.16 m、踏面 0.28–0.30 m、净宽 1.4 m（提案）。
- 侧向栈道：净宽 1.1 m、栏杆高 1.0 m、间距 ≤0.12 m。
- 平台：净宽 ≥1.5 m 环道；蜃阁门前 2 m。
- 不做 `drops`；栈道/平台边缘用栏杆/岩壁挡住。

### 3.5 镜头

- 洞内：第一人称，FOV 52°；`eyeShut` 要把洞壁、平台底、柱算进去。
- 洞外：第三人称跟随，FOV 44°；洞口回望时切第一人称。
- 六个机位用 `views` + `shots.js`；`?show=cam01` 等。
- 洞顶/屋檐进 `walk.roofs`，否则跟随镜头会穿。

### 3.6 季节

- 第一版只做 G01 初夏雨后上午 + 一个备选（秋晴午后）。
- `moodOf` 新增字段：`caveDamp`（洞内湿度）、`drip`（滴水频率）、`mouthLight`（洞口光强/色温）。
- 不做 16 种；等基准定了再扩。

## 4. 性能预算（草案，必须实测）

T00 的数字（T4，1080p）：首院高档 9.3 ms，低档 4.7 ms；屋顶是三角形大头，绘制次数比像素更紧。T01 的估计是 110–190 万三角形、250–400 draws。T02 的体量**应比 T01 小**（一个洞、五个体块、一条栈道），但洞穴的岩壁网格可能很贵。

| 项 | 估计 | 依据 |
|---|---|---|
| 洞穴岩壁 | 20–40 万 | 低模 + 法线；不做 displacement |
| 木构五座 | 20–35 万 | 穿斗 + 插拱，比 T00 的大殿省 |
| 平台/栈道/石阶 | 3–8 万 | 木板 + 栏杆 |
| 林/树 | 8–15 万 | 杉/阔叶，instanced |
| 湖/远景 | 2–5 万 | 低模 + 雾 |
| 室内 | 3–6 万 | 一间小殿 |
| 总三角形 | 60–110 万 | 低于 T00 的 110 万 |
| 绘制次数 | 120–220 | 合批；洞穴/木构/林/湖各一批 |

**目标**：高档 1080p ≤9 ms，低档手机尺寸 ≤5 ms。达不到就砍：先砍树、远景、室内细节；不要先砍洞穴与柱梁交接。

**量法**：同一个 GPU job 里比差值；报告带站点指纹；不用软件渲染的数字外推。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 没有现场测绘 | 洞穴/木构比例可能错 | 白盒先按公开数字；精模前现场补测 |
| 洞穴网格太贵 | 帧耗超标 | 低模 + 法线 + AO；不做 displacement；用雾/暗遮远景 |
| 洞内太暗 | 玩家看不清路 | 洞口反弹光 + AO + 局部提亮；不用全局滤镜 |
| 「一柱」被误解 | 结构讲错 | 让玩家数支点；文案写「柱+横材+岩壁」 |
| 宋构/现状混淆 | 历史讲错 | 分开写；游戏用「原创架空木楼」 |
| 重源传说 | 变成民族主义/偷师叙事 | 只写「寺传」；不做剧情定论 |
| OSM 无轮廓 | 平面不可信 | 明确标「提案」；不拿 OSM 当测绘 |
| 现场许可 | 不能拍摄/测量 | 先申请；不偷拍、不无人机 |
| 火灾叙事 | 变成猎奇/指责 | 不写老尼姓名；重点在「记录与重建」 |
| 素材授权 | Commons CC BY-SA | 只作参考；进游戏前逐张核 |
| 性能 | 洞穴 + 木构 + 林 | 先砍树/远景/室内细节，不砍洞穴与接触 |
