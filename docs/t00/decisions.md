## 界面：不接现成的 UI 库，自己写一层弹层栈（2026-11-15）

现状：叠在画面上的界面约 20 处，其中 7 处会挡住行走。原来的写法有几个问题：Esc 是 `yard.js` 里手写的一串优先级；
画作卡另挂了一个捕获键盘的监听，靠 250 毫秒的延时躲开打开它的那一下；签和画框共用一个 DOM，靠改按钮文字切换；
焦点几乎没人管；每个弹层都要自己记得放开鼠标。

做法：写了 `app/src/ui.js`，约 120 行，没有新依赖。所有弹层都放在一个栈上，分三种。

- 「modal」：菜单、朱印帐、照片、画作卡、签。用原生 `<dialog>` 加 `showModal()`，于是背后的页面不能操作，
  焦点留在弹层里，人物站住，按键只认弹层自己的。
- 「panel」：键位卡、时节面板、拍照设置。行走照常。
- 「mode」：举起相机。

Esc 永远只关最上面那一层，栈空了才打开歇脚菜单。关掉时，焦点回到打开它的那个按钮。
线上页面没有 doctype，在怪异模式下实测过，`<dialog>` 照常盖满画面并拿到焦点。e2e 加了 `layers` 场景。

为什么不用库（2026-11-15 调研）：

- Saltline（Fable 生成的那个）是手写 DOM。Bruno Simon 的 folio-2025 自己写了 `Menu.js`、`Modals.js` 这些文件，
  第三方库只用了 Tweakpane，做调试面板。
- 主机游戏《Fable》用的是 Forza 那套自研引擎，界面用什么没有公开资料。AAA 买 Coherent Gameface、Noesis 这类中间件，
  为的是在引擎里得到 HTML 和 CSS，而浏览器本来就有。
- 画在画布里的方案（three-mesh-ui、@pmndrs/uikit、PixiJS UI）都过不了中文字体这一关：
  - 要么只能用单张 MSDF 字体图；
  - 要么只读 woff，不读 woff2；
  - 要么默认去 CDN 补字，违反字体不从外部取的规矩。
- 游戏风的 CSS 套件（NES.css、RPGUI）早就停更了，风格也和庄严的禅寺相反。
- 通用组件库（Web Awesome、Pico.css）带着网页应用的外观。

将来两种情况可以再考虑：
- 开发时调光影，可以用 `?tune=1` 动态加载 lil-gui（three 自带一份），玩家看不到；
- 朱印帐、设置这类界面的状态多到手写同步开始出错时，再考虑 Preact + htm（约 8 KB，不需要构建）。

## 界面的样子：纸本（2026-11-15）

所有者看过两个方向的对比画布后选了纸本（另一个是漆木：深色漆板配金线）。规则如下：

- 画面上不放框。字直接落在画面上，靠一层淡淡的阴影托住；左上角另加一块暗晕，保证在亮天上也读得清。右侧五个按钮改成竖写的宣纸签条。
- 行事提示是一个圆相加两个字，圆相和地上的那个同源。
- 盖在行走上面的弹层（歇脚菜单、键位卡、时节面板、拍照设置、签、画作卡）都是毛边宣纸。选中的项用朱笔圈出；每张纸上最要紧的那个按钮是一方朱印（歇脚菜单里的「继续」）。
- 滑杆是一条墨线，已调到的那一段颜色更深，上面拖一方小印。
- 按键写成「字母下面一笔」，不再画成键帽。
- 签加了朱丝栏，上下留出天地，左下钤「云径」印。行书没有竖排用的标点，所以借用楷体的标点（`unicode-range`），竖写时逗号、句号才落在正确的位置。

纸纹、笔触、圆相、朱印都由 `app/src/paper.js` 在页面打开时用 canvas 现画，再以 CSS 变量交给 `app/src/ui.css`，不加载任何图片。生成器带种子，所以同一处截两次图是同一张。
每张纸的毛边按它自己的尺寸生成，尺寸变了就重画。按钮上不能用遮罩（有的浏览器画不出来），所以签条把毛边连同纸一起画成一张图。

## 行走时的控件减到两样，时节在七印圆满后才开（2026-11-15）

所有者在手机截图上看出右下角太挤：五张签条、"跃"、摇杆，再加上行事提示，下半屏同时有八样东西。决定如下：

- **行走时常驻的只剩两张签条：留影、歇脚。**
  - 身外：拿掉按钮。滚轮或双指把镜头拉到最近，再继续推，就切到小沙弥自己的眼睛；往外拉回第三视角。桌面上照旧可以按 V。
  - 朱印：并到左上角那枚小朱印上，点它打开朱印帐。印文是下一处地名的第一个字，七印圆满后是"圆"。
  - 跃：手机上拿掉。朝山的七件事都用不到跳，"下台阶"仍在台沿处出现。
  - 摇杆：平时只剩淡淡一圈，拇指按上去才显出来。手机上一会儿不碰屏幕，两张签条也会淡下去。
- **时节第一次来时不给选。** 第一次来，画面就是访客自己的季节和时辰（原本就是这样）。第一次集齐七印时四时打开（`journey.opened()`），之后：
  - 拍照设置里多一组"时节"，歇脚菜单里多"时节""时辰"两行，桌面上的 T 键也开始生效；
  - 朱印帐末页写一句"山中四时，自此由你"，底部提示说一次"时节已开"；
  - 点"重新朝山"清空的是印，四时仍然开着，所以第二遍可以边集印边换季节。

这样做的理由：你最早要的"可以选择季节和时间，拍照分享"仍然在，只是放到了走完一遍之后，成了朝山的回报；第一次来的人看到的，是他自己所在的那一季。测试用的 `?season=` 参数和 `__mood()` 不受这个限制。

## 楼阁的上层怎么落在下层上（2026-11-16，结构评审第三阶段）

结构评审 S-01、S-02 要求上层的柱子落在下层柱子上，楼阁的上层立在平坐上。两处需要取舍，都问过所有者：

- **山门上层与下层同深。** 下层只有前后两排柱（进深 6 米），上层原来进深 3.6 米，前后檐柱悬在下层六米大梁的半跨上。
  两条路：下层加两排内柱，或上层做成与下层同深。所有者选后者：不动山门的占地、门道和碰撞。代价是上层变深、
  上层屋顶变大，山门顶部更重，下檐成了挂在平坐下面的一圈腰檐；上层出檐由 2.1 收到 1.8 米，不超出下檐。
  CAM-04、CAM-05 的主体因此变了，验收证据要重拍。
- **凌霄阁保持体量，二层只对角柱，三层全对。** 柱线要一圈套一圈，三层若都保留三间，一层就得有七间，每间不足 2.2 米，
  在现有 15 米见方的底盘上放不下。所有者选「体量不变，只对角柱」（此前把三层改成单间，所有者也没有接受）。做法：
  - 一层内圈柱线由 ±4.86 移到 ±5.4，正好在二层角柱下面；二层其余的柱由平坐上的梁承托。
  - 二层由三间改为五间，柱线 ±5.4、±3.4、±1.2，开间 2.0 / 2.2 / 2.4 / 2.2 / 2.0，心间最宽、向外渐窄
    （结构评审方复核 #89 时的建议）。这样三层的 12 根柱全部落在二层的柱线上。二层的体量不变，柱子由每面四根变成六根。
  - 留下的不合法式之处，照实记着：一层梢间只剩 2.1 米；二层五间和三层两次间都不足 2.64 米；这些间都放不下补间
    （见下一条），一层的铺作间距因此不匀。`tests/unit/structure.test.mjs` 明确放过凌霄阁三层的开间规则和二层非角柱的 16 根柱，
    并断言放过的恰好是这些。
- **开间不足 2.64 米的不放补间。** 卷四要求「次間及梢間各用一朵」。一朵补间夹在两朵柱头铺作之间，间广不到两个慢栱长
  （2×1.32 米，按材分缩放）时栱头会相撞，所以这样的窄间不放。目前只落在凌霄阁上。
- **药师殿按厅堂取举高 0.27。** 它名为「殿」，但殿阁、厅堂是构架类型，不看名称：三间、前后两排柱的小殿，和禅堂、茶寮、
  大慧院同取厅堂。结构评审方复核 #88 时认可，要求记在这里。
- **大雄宝殿、御碑亭是重檐，不加平坐。** 一座殿两重檐，中间没有楼面。大殿上檐柱落在下层内圈柱线（±4.3）上；
  御碑亭上檐柱改为与下层同位（±2.0），下檐成了缠腰。

### 一、顶层回廊加宽到 1.6 米

他能站的地方，是回廊里离墙、离柱、离栏杆都够远的那一条（单位米，量自三层柱线 ±3.4）：

| 让出的 | 多少 | 由来 |
|---|---|---|
| 墙一侧 | 0.50 | 墙、槛、横披在柱线上，厚 0.16–0.24，半厚取 0.12；加身体 `BODY` 0.38 |
| 柱一侧 | 0.586 | 三层 `colTop` 3.0，柱半径 `COL_R` 0.20，`walk.posts` 取 0.206；加 `BODY` |
| 栏杆一侧 | 0.64 | `edgeIn = 0.16（栏杆内缩）+ 0.1（栏杆半厚）+ BODY`（`building.js`） |

回廊宽 w（即三层 `platOut`）时：柱间能站的宽 = w − 0.50 − 0.64 = **w − 1.14**；正对柱子处 = w − 0.586 − 0.64 = **w − 1.226**。

| w | 柱间 | 柱前 | 平坐外沿 | 檐口比平坐外沿多出 |
|---|---|---|---|---|
| 1.0（现在） | −0.14 | −0.23 | ±4.4 | 1.2 |
| 1.4 | 0.26 | 0.17 | ±4.8 | 0.8 |
| **1.6（建议）** | **0.46** | **0.37** | **±5.0** | **0.6** |
| 1.8 | 0.66 | 0.57 | ±5.2 | 0.4 |

- 1.0 米一处都站不进，这是 #101 调研的结论，算式对得上。
- 1.4 米柱前只剩 17 厘米：点地走、摇杆斜推都会贴着柱子卡住，镜头也更挤。
- 在 Node 里用 `createWalker` 实测（`trial.patch` 里的 `tests/unit/_probe_ring.mjs`，4 厘米一格做洪水填充）：1.0 米一格也站不进；
  1.4 米柱前 0.16、柱间 0.24；1.6 米柱前 0.36、柱间 0.44；1.8 米柱前 0.56、柱间 0.64。三种宽度下整圈都连成一片，四个角都过得去。
- **取 1.6 米。** 柱前 37 厘米，转角处（离角柱心至少 0.71 米，要求 0.586）转得过去。
- 1.8 米再宽，檐口只比平坐外沿多 0.4 米，从下面看平坐几乎顶到檐口，阁的轮廓变「胖」；平坐外沿也落进 `shelter.js` 让雪吹进来的那一窄条。
- 1.6 米时平坐外沿 ±5.0 仍在二层柱线 ±5.4 之内，加宽的部分整个落在二层的平面里，不会伸到二层的檐外；
  按腰檐二分举一估算，二层腰檐在 ±5.0 处的瓦面比雁翅版下沿低约 1.5 米，不相碰（实现时用测试量实数）。
- 一层、二层不动。二层仍是 1.0 米（二层不开放）。

**轮廓变了多少**：见 `docs/t00/evidence/loft/plan/` 的对比图（下面「对比图」一节）。只有三层平坐的外沿每边往外 0.6 米、雁翅版和栏杆跟着外移；屋顶、檐口、柱都不动。

### 二、加宽后合不合《营造法式》

**能引的原文都是转引，不是本轮自己读的。** 维基文库的卷四页面这次打不开（404），ctext 不许自动抓取，所以下面两句取自
`structure-review.md` S-01、S-02（结构评审方注明读的是维基文库本卷四）：

- 「造平坐之製，其鋪作減上屋一跳或兩跳。其鋪作宜用重栱及逐跳計心造作」
- 「四周安雁翅版，廣加材一倍」

**平坐楼面该挑出柱线多少，条文里有没有规定，本轮未核。** 按上面两句的做法推，楼面铺在平坐铺作之上、雁翅版挂在楼面外沿，
楼面外沿大致应在平坐铺作的最外一跳附近。现在平坐铺作挑出 `PING.reach` 0.6 米：

- 现状 1.0 米，楼面已经比铺作多挑出 0.4 米；
- 改为 1.6 米，多挑出 1.0 米，靠什么托住，现在的模型里没有交代。

### 三、顶层怎么做成可走的地方

**建议：顶层的回廊是平面图里的一圈楼面，只在「他在楼上」时才算数；到楼上要从一层房间过一次墨帘。院子照常画。**

先说一个量出来的事实：三层回廊（柱线外 0.5 到 1.6 米，即 |x| 或 |z| 在 3.9–4.36 之间）**整个落在一层的墙内（±7.5）**。
院子里任何一个他能站的点都不在这圈楼面的正下方：一层里面只有地下的房间，阁前的月台在 z 方向 7.95 米以外。
所以「一个 (x, z) 只有一个高度」在这里并不真的冲突，冲突只在「点地」和「从院子里瞄过去」这类问高度的地方。做法：

- **`site.js`**：`putStack` 给标了 `loft: true` 的那一层，在 `walk.decks` 里加四条回廊楼面（`h` = 三层楼面 35.31，`floor: "wood"`，
  每条带 `loft: "lingxiao"`），范围是墙外 0.5 到栏杆内 0.64；`site.lofts.lingxiao = { floor, ring, door, face, stair }` 记楼面、
  门口（三层南面门外，(0, topZ + 4.13)，面朝南）和一层梯脚。三层的柱子本来就在 `walk.posts` 里。
- **`createWalker`**：加 `setLoft(id | null)` 和 `loft`。`carved()` 只在 `loft === d.loft` 时才算带 `loft` 的楼面；
  所以平时（院子里、点地的视线里）这圈楼面不存在，他在楼上时它才是地。在楼上时 `blocked()` 对楼面以外一律为真，
  这样墙、栏杆外面、下面的院子都走不出去；`walk.drops` 不加顶层，`drop.js` 找不到可以跳下的边，空格只是原地跳起。
- **`eyeShut`**：在楼上时，眼睛不许出栏杆的内皮（`PX − 0.16`），也不许进墙（三层的 `core`）。另外二层腰檐在 `walk.roofs` 里
  的范围一直伸到 36.19 米，比三层楼面（35.31）还高，会把楼上低处的眼睛判成「在瓦里」：要把下层腰檐那一项在上层平坐范围内的
  顶截到上层楼面。
- **`yard.js`**：不进 `indoors()`。加 `aloft(loft | null)`：`inside` 仍为 `false`，所以 `COURTS` 照常画、太阳和天空照常、
  `setMood` 照常、镜面倒影照常按楼层判断（首院以外本来就不画）、雪照常下；只做 `walker.setLoft`、把他放到门口、
  `follow.reset`。`pass()` 扩成 `pass({ hall } | { loft })`：一层梯脚 → 顶层是「室内 → 室外」，墨帘按出殿的样子开（`on day`）；
  顶层 → 梯脚按进殿的样子（`indoors(lingxiao)` 后把他放在梯脚而不是门口）。
- **混响和配乐**：`audio.js` 的两种混响跟 `inside` 走，楼上 `inside` 为假，用院子的；`zoneOf(x, z, inside)` 在 z = −127 处本来就是
  `summit`，不用改。脚步：`floorAt` 返回楼面的 `floor: "wood"`，`underfoot()` 把有顶的平坐当干的。
- **`resume.js`**：存的地方多一个 `up: "lingxiao"`（`sanitizePlace` 只认 `site.lofts` 里有的名字）。刷新后 `接着走` 把他放回顶层；
  旧存档没有这个字段，照旧。`labelOf` 在楼上说「凌霄阁上」（四种语言）。
- **其他**：`trail.js` 在楼上不压脚印（平坐在檐下，`shelter` 本来也不积雪）；`hints.js` 第一次进凌霄阁说一次「楼梯在西北角，可以登楼」。

**考虑过、没有选的做法：**

1. **照现有的房间做（`walker.setRoom`，房间放在阁的真实位置上）。** 房间只有一个矩形、方形障碍、一层高度，`floorAt` 恒为 "room"，
   `eyeShut` 只查平面：圆柱、栏杆内皮、檐、上下层屋面都要在房间里重写一遍。`edges`、`nearplane`、`sweeps` 读的是平面图，
   房间要另接。走平面图则这些都直接覆盖到顶层。#101 建议的「建在真实位置上的房间」本意是「院子照常画」，这一点两种做法都做到。
2. **楼面直接放进平面图，不加开关。** 从阁前点阁身，视线穿过那圈楼面的高度时会「落」在楼上，他会试着走过去；洪水填充测试也会
   把它算成一块走不到的地。所以要开关。
3. **一层到顶层一路可走的楼梯。** 一层房间在地下 60 米，二层不开放，楼梯走不到真的顶层；做成可走的也只能走到天花板。
4. **二层也停。** #101 不在范围内。
