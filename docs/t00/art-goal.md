# 目标：向美术原型靠拢（给开发）

写于 2026-11-16。所有者给了六张美术原型，存在 `refs/art-prototype-2026-11-16/`。

## 先认清原型是什么

- 这六张是 AI 在游戏截图上改出来的电影感静帧（`manifest.json`：「AI cinematic edits of game screenshots; not unedited gameplay captures」）。画幅 2.39:1，离线出图，带胶片颗粒、光晕和完整的光照。
- 它们是**美术方向**，不是像素级的交付标准。
- 图里 AI 自己编出来的东西不是目标，例如：
  - 05 观音殿屋顶上多出的一副梁架；
  - 02 山门上层的栏杆和开间比例；
  - 06 屋顶的组合方式。
- 建筑以 `docs/t00/structure-review.md` 和 `docs/t00/structure-goal.md` 为准。

| 原型 | 内容 | 机位（已对齐，见 `art-targets.md`） | 季节与时辰 |
|---|---|---|---|
| 01-bamboo | 竹林、石阶、半山亭 | `art1` | 夏，清晨，斜光穿雾 |
| 02-gate | 山门正面 | `art2` | 秋，**白昼**（2026-11-17 由傍晚改：秋暮的太阳留给首院 A3，见 `art-targets.md` A2 备注），侧光扫过门板和檐下 |
| 03-court | 首院，小沙弥背影 | `art3`（第三人称） | 秋，逆光薄雾 |
| 04-tea | 茶寮前的茶桌 | `art4` | 秋，傍晚，掠地斜光 |
| 05-terrace | 观音殿 | `art5` | 夏，黄昏，窗格透出暖光 |
| 06-summit | 山顶回望 | `art6` | 秋，日出，银蓝色的雾 |

## 已定的前提

- 分档：所有者 2026-11-16 认可。桌面高档追原型，手机低档只保住构图和色调。
- 基准：J01 不动，原型作为各自「季节 × 时辰」下的目标（`art-targets.md` 的默认；所有者另有决定就改那里）。

## 和结构那条线的分工（2026-11-16）

- 建筑按《营造法式》改，见 `docs/t00/structure-goal.md` 的「2026-11-16 调整」。原型只管光和色调。
- 结构第二阶段（举高，#88）和第三阶段（平坐、上下层柱位）会改变 `art2`、`art3`、`art5` 里建筑的剪影。每次合入后，用 `tools/look.py` 重量受影响的机位。数值目标不变：它们量的是光和色调，`bands` 的 ±8 留了剪影变化的余量。如果某个机位因为剪影变化而系统性不过线，报给评审方，不要为了过线去改建筑。
- 性能：16 毫秒的总上限里已经扣掉结构几何的 1 毫秒。

## 要达到什么

在上表六个机位上，对应的季节和时辰下，桌面高档的画面在下面四件事上读得出和原型是同一个方向：
- 光从哪来；
- 明暗层次；
- 雾的远近层次；
- 植被的密度和质感。

每个机位的验收标准已经写在 `docs/t00/art-targets.md`（2026-11-16）：数值目标从原型量出，存在 `docs/t00/art-targets.json`，用 `tools/look.py --check` 检查；另配一份由评审人打勾的看法清单。验收以那份文件为准，不拿原型逐像素比。

## 分阶段

每个阶段单独一个 PR。

### 第一阶段：便宜的电影感

- `post.js`：
  - 高光加光晕（halation）；
  - 按季节和时辰各用一张 LUT 调色（由 `mood.js` 给）；
  - 颗粒保持细；
  - 高档有一层很浅的景深，只在拍照时由玩家在留影设置里打开「虚化」才开（#275；原为「定机位和拍照时开」，所有者 2026-11-19 看过后改）；默认、走路、`?shot` 定机位都全景清晰。
- 阴影：
  - 提高阴影图的分辨率；
  - 改成软阴影（PCSS 或 VSM）；
  - 树叶和竹叶用镂空的方式投出斑驳的影子。
  - 阴影图仍然每换一次时辰才画一次。
- 高档加 GTAO（three 自带 `GTAOPass`）。低档不开。
- 高度雾分层，接到 `mood.js`。
- 判断标准：六个机位拍前后对照图，放进 `docs/t00/evidence/art/`。

### 第二阶段：间接光（最大的卡点，先出方案再动手）

- 场景是代码生成的，没有光照贴图的 UV。先写一页方案比较，交给所有者选：
  1. 加载时在场景里布一张球谐光照探针网，用 three 自带的光照探针工具烘；
  2. 在 Hugging Face 的 GPU 机器上离线烘好，随站点发布；
  3. 换到 WebGPU，用屏幕空间 GI。这要把 `procMat` 的 `onBeforeCompile` 补丁迁到 TSL，等于重写材质层。
- 每种方案都要写清楚：
  - 加载多花多少时间、数据多大；
  - 每帧多花多少毫秒（在 T4 上实测）；
  - 季节、时辰切换时怎么办；
  - 殿内房间怎么办。
- 方案定了才实施。

### 第三阶段：体积光

- 01 的光柱、03 的逆光薄雾：做低分辨率的光线步进体积雾，用阴影图遮挡光线，只在高档开。
- 先在 T4 上测，首院高档单帧多花不超过 1.5 毫秒。

### 第四阶段：植被（单独立项，先补素材）

- 这首先是素材问题，代码画不出来：
  - 竹叶、柳杉的针叶、红枫的叶片贴图；
  - 成团的叶片几何；
  - 苔石、蕨类和地被。
- 来源只用 CC0 或者能证明有授权的，登记进 `docs/t00/asset-register.csv`。
- 性能手段：
  - 远处换贴片（impostor），分几级细节；
  - 透明叶片层层叠画的开销要实测，手机低档控制密度。
- 判断标准：01、03、06 三个机位的植被读得出层次。

### 第五阶段：材质细节

- 瓦面、石阶和木门的细节，全部用法线、视差贴图和贴花来做。不加三角面，因为三角面已经是瓶颈，屋顶占了大头。
- 加苔藓和污渍的分布：按朝向、离地高度、离水远近。

## 每个 PR 都要做到

- **测试。** `pnpm run check`、`pnpm run typecheck`、`pnpm test` 全过；动了 `app/` 的，推送前跑 `pnpm run verify`。新的东西要配测试，比如：
  - 「每个季节和时辰都有 LUT 字段」（`mood` 的测试）；
  - 「低档不开 GTAO 和体积雾」。
- **截图。** 用 `tools/gpu-render.sh` 在 T4 上拍六个机位，同时也拍 `cam01` 到 `cam06`，前后对照。SwiftShader 判断不了光影好坏，不能拿它的图作证据。
- **性能。** 改前改后各测一次，写进 `docs/HANDOFF.md`。
  - 首院高档现在约 9.3 毫秒，所有阶段加起来不超过约 16 毫秒；
  - 低档在手机尺寸下不比现在（约 4.7 毫秒）慢 20% 以上。
  - 超了就停下来报告。
- **手机。** 改了界面或画质分档，要跑 `tools/mobile-audit.cjs`。
- **来源登记。** 每个看得见的效果都在 `docs/t00/SOURCES.md` 登记一行。来源写「美术原型 2026-11-16（AI 改图）」或者实际的参考，不得把推断当作出处。
- **不改验收结论。** 没有对应提交的运行证据，不得改 `acceptance-report.json` 和 `ART-SPEC.md` 里的验收勾选。

## 不要做的

- 不要照着原型改建筑。原型里 AI 编出来的构件不是目标，建筑走结构评审那条线。
- 不要加原型里没有、`JINGSHAN.md`「有意没有做的」里明确不要的东西，比如红灯笼、石狮。
- 不要一个 PR 混几个阶段，不要为了求绿关掉测试。
