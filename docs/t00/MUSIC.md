# 配乐（T00）

2026-11-15 用户认可「七印集主题」的结构和全合成的路线，要求子代理评审后直接接入游戏。本页记录配乐是怎么组织的、
每处听到什么、怎么渲染出来听、还有什么没有验证。代码在 `app/src/score.js`（乐谱即数据）、`app/src/instruments.js`
（乐器与播放器）、`app/src/audio.js`（总线、混响、让位、后台暂停）。

**还没有人听过。** 自动测试和渲染报告只能证明：音准对、不削波、不叠播、换场按规则发生、乐句不机械重复。好不好听要人来听。

## 结构

- **调式**：G 羽（G B♭ C D F），主音是大钟的 98 Hz；钟声里本来就有一个小三度分音，配乐就建在钟上。改调只改 `MODE` 和 `THEME` 两处。
  檐铃改到同一调式里（D F G B♭），得印的磬声原本就是 D。这是我替用户定的，用户没有选过。
- **主题**：七个音，D F G F D C G，从中音区升到高 G 再落回低 G（上山到山门，再回到地上）。
  **七枚印各对应一个音**：第 n 枚印的磬声是主题的第 n 个音（高两个八度，第一枚就是原来那声 1175 Hz 的磬）。
  七印集齐之前，**没有任何一句完整地奏出主题**（单元测试在十分钟的模拟走访里逐句检查，按调式音级比，移位也算）；
  第七枚印得到后，下一句是完整的主题，琴先、箫后高八度再奏一遍。之后在山门和山顶偶尔再完整出现。
- **乐句按地点生成，不循环播放**：每处有自己的造句办法，起音、调式内移位、节奏伸缩、句长都随机（带种子），同一句不会连着出现两次。

## 地点与配乐对照

| 地点（`zoneOf`） | 范围 | 听到什么 | 句后留白 |
|---|---|---|---|
| 竹林 grove | 起点到第一段石阶顶 | 两三个高处的泛音，取自主题开头，相隔很远，像风碰出来的 | 9–16 秒 |
| 石阶 stair | 转折石阶、前庭，到照壁前 | 一声低空弦，再一段较长的主题片段（三到四个音） | 7–12 秒 |
| 山门 gate | 绕过照壁，见到山门 | **第一次**：主题的前五个音，下面一层很薄的五度和声，收在低 G 上——全曲第一个完整乐句。之后是较轻的变体 | 9–14 秒 |
| 首院 court | 山门以内的第一进院落 | 一两个单音（琴或泛音），大量留白让水滴和风说话 | 10–18 秒 |
| 殿内 hall | 任何一座殿堂里 | 没有旋律：一层持续的低五度，偶尔一声低空弦；换成殿内的短混响 | 4–8 秒，和声不断 |
| 后院 upper | 藏经楼、观音殿两层台地、茶坡 | 主题倒过来，或调式里的上行三音；箫开始应答 | 8–14 秒 |
| 山顶 summit | 凌霄阁台地 | 箫吹主题开头（高八度），琴以主题结尾作答 | 10–15 秒 |
| 七印圆满 complete | 第七枚印后的下一句 | 完整主题，琴一遍、箫高八度一遍 | 12–18 秒 |

**换场**：进入新地点后要**稳定停留 2 秒**才算到了，边界上来回走不触发。到了以后：
- 若正在留白，留白立即结束，新地点的第一句随即开始（上一句结束不到 1.5 秒的，等满 1.5 秒）；
- 若正有乐句在响且还剩 3.5 秒以上，尚未奏出的音全部丢弃，正在响的淡出 3.5 秒，再过 1.5 秒新地点开始（第一个音再等半秒，等音量回到位）；
  剩不到 3.5 秒的让它奏完。从踏过边界到听见新地点，最长约 7.5 秒（目标 4–8 秒）。
- 七印圆满那一句只在走进殿里时才被打断（殿内没有旋律）。第一次的山门乐句若被打断，下次回到山门会重新完整奏一次。
- 一个声部在一句里整体移八度来适应乐器音域，旋律的形状不变。

**让位**：撞钟时音乐降到 18%，9 秒后用几秒回到原样；击鼓降到 50%，2.5 秒；得印的磬降到 55%。

## 季节和时辰（`moodMusic`）

只改几个数，不写十六首：

| | 变化 |
|---|---|
| 春 | 琴和箫高一个八度，留白略短 |
| 夏 | 基准：每分钟 52 拍，琴领奏 |
| 秋 | 48 拍，箫出现得多 |
| 冬 | 46 拍，全部改为泛音（对话句里箫留着），留白长三成，和声更薄 |
| 晨 | 留白略短，箫少 |
| 暮 | 再慢 3 拍，箫多 |
| 夜 | 箫领奏（冬夜仍是泛音），再慢 4 拍，留白长两成，和声厚一些 |

箫只在它的音域里（D4 以上），一次只吹一个音；对话句（山顶、圆满）始终保留两种音色。

## 乐器（全部 Web Audio 合成）

| 名字 | 做法 |
|---|---|
| 琴 qin | Karplus–Strong 拨弦（每个音渲染一次缓存），按回路滤波器的半个采样补偿音高；共鸣板峰值 180 Hz、顶部低通；吟（缓慢颤音）和上（拨后滑入） |
| 泛音 harm | 正弦加微弱二次谐波，快起慢衰，底下一声极轻的拨弦 |
| 低空弦 low | 同琴，更暗更长 |
| 箫 xiao | 周期波形加带通气声，起音 35 音分的滑入，延迟出现的 4.6 Hz 颤音 |
| 和声 pad | 主音与五度、八度四个略失谐的振荡器，700 Hz 低通，3.5 秒起、5 秒落 |

每个声音最后都过一个 60 毫秒的闸门淡到零再停，避免咔声。实测音准：各音色在 0.1 音分以内（`report.json` 的 `tuning`）。

## 三条总线和设置

歇脚菜单里：**音量**（总）、**乐声**（配乐）、**山声**（竹风、滴水、檐铃、龙井的滴水回声）、**音效**（钟、鼓、磬、井水）。
每条的音量在混响送出之前，所以调到零不会留下回声（已在响的混响尾巴最多 3 秒）。设置存在 `yunjing.settings.v1`。
殿内外两套混响按是否在殿内切换（约 2 秒交叉）。页面退到后台时整个音频暂停，回来接着放；任何一次点按或按键都会尝试恢复
（iOS 有时拒绝无手势的恢复）。

## 渲染出来听：`node tools/music.mjs`

```sh
node tools/music.mjs                   # 夏昼和冬夜
node tools/music.mjs autumn-dusk       # 指定光景
```

沿一条约 11.5 分钟的模拟路线（竹林 70 秒、石阶 60、山门 12、首院 110、殿内 60、首院 25、后院 120、山顶 110 并在此得第七印、
后院 30、首院 40、山门 40），用页面同一份乐谱、同一套乐器离线渲染，输出到 `tools/out/music/`（不入库）：

- `<光景>.mp3`：整段配乐总线；
- `<光景>-<起始秒>-<地点>.mp3`：每处一段；
- `<第一个光景>-stem-qin|xiao|pad.mp3`：分轨（琴含泛音和低空弦；箫；和声）；
- `report.json`：峰值、削波样本数、每 5 秒响度、超过 3 秒的静默段、乐句与打断记录、各音色实测音高，
  以及 `balance`：在页面的真 `audio.js` 里实时测的各总线响度（配乐、山声、钟、鼓）。

2026-11-15 的一次结果（夏昼）：峰值 −13.4 dBFS，0 个削波样本，35 句、4 次换场打断；配乐总线平均约 −36 dB RMS、山声约 −35 dB，
钟声最高约 −11 dB，钟响时配乐降到平均 −49 dB。配乐总线上的长静默（10–20 秒）是有意的留白，游戏里由山声填上。

## 还没做 / 没验证

- **没有人听过**，包括音色是否有「电子味」、留白是否太长、主题是否好记。按目标第 6 条的五项听评（完整度、场景贴合、过渡、疲劳感、混音）要用户来做。
- 目标第 2 条的「两版 60–90 秒样片比较」没有做，用户选择直接接入。

- 只在无头 Chromium（软件渲染）里跑过；Safari、iOS 的后台恢复没有在真机上试。
- 主题只有一个；山门首句的打断和重奏、七印圆满在殿内得到时（`complete` 会等出殿）都只有单元测试覆盖。
