# 雕刻身体：两条路的比较（#80 第一步）

2026-11-16，分支 `claude/monk-80-options`，基于 `main` `b916f81`。本页只比较，不改默认身体，不替换 `novice.glb`。
标注：**实测** = 在本会话里跑过、数字可重现；**据官方文档** = 读了厂商自己的页面，没跑过；**第三方** = 厂商页面打不开，转述别处；**推断** = 我的判断。

## 一句话结论

**推荐先 A 后 B。** A 一天以内能做完，修好站立、合掌、走路、上下台阶的碎片（实测：重合顶点的分离从 19–24 厘米降到 0）；B 才能解决坐姿，但它的成败取决于生成模型时能不能得到「袍子一层、裤腿一层」。这一点官方文档都没有承诺，大概率要在 Blender 里手工补腿。另外，A 做的那一步「同位置同权重」，B 的模型同样要做（见 B.6 的实测），所以 A 的工作不会白费。

## A. 改权重（按位置归组、统一权重、沿网格平滑）

### 做了什么（实测）

- `tools/novice-weld.mjs`：把距离小于 1e-5 米的顶点副本归为一组，整组取平均权重，只保留最大的四个再归一；`smooth = n` 时再沿焊合后的网格把权重平滑 n 次（每次自己与邻居各占一半）。
- `tools/novice.mjs` 加了第 4b 步，只有设了 `NOVICE_WELD=1` 才会执行（`NOVICE_WELD=3` 表示焊合后再平滑两次）。Meshy 原文件（24 MB）不在仓库里，所以这次没有重建 `novice.glb`。
- `tools/novice-weld-trial.mjs` 直接读现在发布的 `novice.glb`，把四个部件首尾相接，分别用「原权重」和「焊合后的权重」让他做站立、合掌、走一个完整步态（第 30–120 帧）、上一段台阶（踏步高 15 厘米、深 30 厘米）、坐凳、盘坐，然后量两样东西：
  - 重合顶点最多分开多远，对应走路时袖口和下摆的碎片；
  - 袍子自身的边被拉长到多少。量法：只看绑定时长于 5 毫米的边，拉长超过 2 倍且多出 1 厘米以上，就算「被扯开」。焊合以后不会再分离，剩下的毛病就是拉扯。
- 这次不写任何文件。重跑命令：`node tools/novice-weld-trial.mjs [--smooth=2]`。

### 量出来的数（实测，`novice.glb` 现行版本）

- 顶点 17,704 个，归成 10,216 个位置；其中 6,368 个位置有不止一个副本，共 8,672 对。
- 权重不同（某根骨骼的权重差超过 1e-4）的有 **1,102 对**，最大差为 1，也就是一边全挂在某根骨骼上、另一边完全不挂。
- 其中 **1,045 对（95%）在部件交界处**：
  - 袖口和领口（皮肤/袍，345 对，高 0.58–0.96 米）；
  - 下摆里侧（袍/裤，585 对，高 0.16–0.42 米）；
  - 脚踝（裤/鞋，115 对）。

  这是因为 `novice.mjs` 按贴图颜色分部件，而贴图上颜色块的边界正是 UV 接缝，所以部件的分界线落在接缝上，接缝两边又是从代码身体的不同部件取的权重。这和所有者看到的碎片位置（袖口、手腕、下摆）一一对应。

| 姿势 | 重合点最大分离，原权重 | 焊合后 | 袍边被扯开的条数，原权重 | 焊合后 | 焊合并平滑两次 |
|---|---|---|---|---|---|
| 绑定 A-pose | 0 | 0 | 0 | 0 | 0 |
| 站立 | 97 mm（765 处 > 1 mm） | **0** | 67 | 171 | 41 |
| 合掌 | 195 mm | **0** | 158 | 278 | 115 |
| 走路一个步态 | 191 mm（799 处） | **0** | 263 | 472 | 171 |
| 上台阶 | 239 mm | **0** | 461 | 807 | 478 |
| 坐凳 | 323 mm | **0** | 552 | 833 | 639 |
| 盘坐 | 360 mm | **0** | 459 | 1,051 | 838 |

### A 能解决什么

- **裂缝和碎片能解决。** 焊合之后，重合顶点在任何姿势下都不会分开；#80 第二步的测试「重合顶点相距不超过 1 毫米」靠这一条就能过。
- 加两次平滑后，站立和走路时被扯开的袍边比原来还少（站立 67 降到 41，走路 263 降到 171）：袖子根部的权重不再陡变。
- 剩下的是什么还要看图（推断）：焊合后原来的裂口变成了被拉长的三角形，看起来是贴图被拉花，而不是破洞。站立、走路看不看得出来，要在第二步用 `portrait.js` 截图判断。本次没有截图。

### A 为什么解决不了坐姿

- 坐凳和盘坐时，焊合并平滑后仍有 639 和 838 条袍边被扯开，**比原权重还多**：原来的裂口现在连在一起，只能被拉长。
- 根源在结构，不在权重（实测）：绑定姿势下，裤子最高只到 0.423 米，袍子下摆最低在 0.164 米。下摆里侧直接缝在裤子上，大腿上半截和胯部根本没有几何体。坐下时裙摆骨骼把下摆掀起来，这层缝合的外壳只能被扯成长条，掀开后底下是空的。
- 改权重改不出不存在的腿，所以坐姿要么换一个分层的模型（B），要么在 Blender 里给现有模型补腿、把下摆剪开（也就是 B 的手工部分）。

### A 的工作量

- 需要所有者提供 Meshy 原文件（24 MB，SHA-256 `5244a309…`，见 `asset-register.csv`），用 `NOVICE_WELD=3 node tools/novice.mjs <原文件>` 重建。
- 另外要写 #80 第二步的两条测试，拍截图，登记新的 SHA-256。
- 预计半天到一天。风险是平滑会让袖口一带的权重稍软，要看截图确认。

## B. 重新生成，Auto-Rig Pro 绑定，再重定向到我们的骨骼

### B.1 用哪个生成模型（据官方文档，未验证）

- **首选 Tripo H3.1 的多视图生成**（`v3.1-20260211`）。
  - 输入键是 `front / left / back / right`，正面必须有，至少两张，PNG、JPEG 或 WebP，不小于 256 px。我们的设定图正好有正、侧、背三视图，裁开就能用。
  - 可选项：`face_limit`（文档说游戏资产一般 5–10 万面）、`quad`（四边面，强制输出 FBX，默认 1 万面）、`smart_low_poly`、`pbr`、`texture_quality`、`auto_size`（按真实米制缩放）。
  - 来源：<https://developers.tripo3d.ai/en/docs/generation-multiview-to-model/standard>
- **游戏向的 P 系列**（P1，以及「原生四边面拓扑」的 P2 `P2-20260801`）面数更好控，但 P2 不支持 `generate_parts`。来源：<https://developers.tripo3d.ai/en/models/p2>
- `generate_parts`（分部件生成）只有 H 系列有，而且要求不带贴图（`texture=false`、`pbr=false`），也不能和 `quad` 或 `smart_low_poly` 一起用。
- 推断：先用 H3.1 多视图、`face_limit≈20000`、带 PBR 贴图出一版，同时另出一版 `generate_parts` 的白模，看它会不会把袍子和腿分开。
- 文章里说的「Smart Mesh」对应的就是 P 系列或 `smart_low_poly`。这是推断：文章配图没有看到，Tripo 官网（tripo3d.ai）对抓取返回 403。
- **Meshy 的同类选项**（据官方文档，<https://docs.meshy.ai/en/api/image-to-3d>）：
  - `pose_mode` 可选 `a-pose` 或 `t-pose`，这一点 Tripo 的 API 文档里没有；
  - 多图输入 1–4 张；
  - Smart Topology 的 `meshy-t2` 自称「原生分开的部件」，最多 1.5 万面，只出三角面。
  - 我们已经有 Meshy Pro 的经验，可以作为备选；但上一个模型正是 Meshy 出的单层外壳。

### B.2 设定图是 A-pose，要不要补 T-pose 四视图

- **不一定要。**
  - 我们的骨骼本身就是 A-pose，`monk.update` 每帧从 A-pose 出发。
  - Tripo 的生成 API 没有姿势参数，文档也没说不接受 A-pose（据官方文档；Tripo Studio 网页版据说有「T-Pose」选项，只见于搜索摘要，未验证）。
  - Auto-Rig Pro 的 Remap 文档说它能处理 A-pose 和 T-pose 之间的差别（「Redefine Rest Pose」，<https://www.lucky3d.fr/auto-rig-pro/doc/remap_doc.html>）。
  - 用 A-pose 生成，绑骨和重定向反而少一步。
- **建议补一张正侧之外的右视图**（四视图里的 `right`），由所有者用出设定图的同一个工具出图，和上次出 `monk-apose-front.png` 的编辑一样。
  - 同时要**去掉斗笠和念珠**（它们由代码建），并把**下摆画短或画成能看见裤腿的样子**。这是推断：生成器只会建出它看得见的东西。
  - 补图是所有者的事：出图工具和账号在所有者那里。
- 本次试验也验证了**另一个方向**：如果最后拿到的是 T-pose 模型，在 Blender 命令行里把它摆回我们的 A-pose 并设为静止姿势，是可行的（见 B.6）。

### B.3 Auto-Rig Pro 的流程（据官方文档，未验证）

1. 角色放在原点、面朝 -Y。用 Smart：Get Selected Objects，然后手放标记点或用 AI 的「Guess Markers」（只支持人形），Match to Rig。来源：<https://www.lucky3d.fr/auto-rig-pro/doc/auto_rig.html>
2. 加挂件骨骼：Match to Rig 之后用 Shift-A 加自定义骨骼，直接挂在变形骨骼上（我们的 `robeFront/Back/Left/Right` 和 `sashTail` 挂在 hips 上，`hat` 挂在 chest 上）。导出时要把它们标成自定义骨骼：`cc_` 前缀，或用 Set Custom Bones，或加 `cc` / `custom_bone` 属性。来源：<https://www.lucky3d.fr/auto-rig-pro/doc/ge_export_doc.html>
3. Bind 有两种引擎：
   - Heat Maps，适合封闭的网格；
   - **Voxelized，适合「多层衣服、道具」**。

   FAQ 对由散件组成的网格（衣服）推荐 Split Parts，Bind 卡死时推荐 Voxelize，<https://www.lucky3d.fr/auto-rig-pro/doc/faq.html>。分层的衣服推荐从身体传递权重（Transfer Weights）。
4. 绑完先测抬臂、屈腿、转身、**坐下**，再修拉伸和穿插（文章作者的做法；这里还要加我们的两种坐姿）。
5. 导出用 GLTF 格式（要求 Blender 3.4 以上）：
   - 骨骼类型选 Humanoid 或 Universal；
   - 「Rename Bones from File」读一个 `root.x = hips` 这样的对照表，**能直接导出成我们的骨骼名**；
   - 影响数限制为 4。
6. 能否在 Blender 后台（命令行）运行：**官方没有说**。推断：导出可能能用脚本跑；Smart 的 AI 标记和 Bind 多半依赖界面，要在所有者电脑上手动做。

### B.4 重定向到我们的骨骼

- **主干骨骼**有两种办法：用 Auto-Rig Pro 的改名表直接导出成我们的名字；或者导出成 Unreal 命名，再由 `tools/novice-retarget-trial.mjs` 按 `MAP` 换算，扭转骨和拉伸骨并进所在的肢体。
  - 骨骼数可以不一样；**位置必须一样**。`novice.js` 只换几何体，静止姿势和反向绑定矩阵用的都是 `monk.js` 那副骨骼，所以网格必须处在我们的 A-pose 和比例里。
  - 做法是把对方的骨架逐根摆到我们的关节位置，让网格按这个姿势变形，再把这个姿势设为静止姿势（实测可行，见 B.6）。
  - 比例差太多时（例如生成的头身比和代码身体不同），这一步会拉伸网格。所以生成时要按设定图的比例。推断：Tripo 的 `auto_size` 加上我们缩放到 1.18 米，应该能对上。
- **挂件骨骼**有两种做法：
  1. **在 Auto-Rig Pro 里加成 `cc_` 自定义骨骼，自己刷权重**：袍子下摆按朝向分给四根裙摆骨骼，腰结以下的带子给 `sashTail`。
  2. **沿用现在的做法**：袍子腰带以下按代码身体最近的顶点取裙摆权重，`tools/novice-retarget-trial.mjs` 已经这样做，到大腿中部完全交给裙摆骨骼。
  - 推荐第 2 种：裙摆是弹簧，不是肢体；`monk.js` 的 `setupHem` 和缩短裙摆的逻辑都是按代码身体的权重调出来的。
  - `hat` 骨骼不带任何顶点：斗笠、念珠、背带仍由代码建（`straps` 在穿上雕刻身体时会显示出来）。
- **四个蒙皮部件**：
  - 在 Blender 里给每个部件一个以它命名的材质（`skin`、`robe`、`legs`、`shoes`）。转换工具按材质名切分，比现在按贴图颜色分可靠，不会再把部件边界放在 UV 接缝上。
  - 如果四个部件共用一张贴图，就在转换时再合成一个材质（`novice.js` 只取第一个部件的材质）。
  - 如果生成的模型是一整块，就在 Blender 里按面选择（L 选岛，或按颜色）分配材质，这是手工活。推断：约半小时。

### B.5 袍子和腿能不能分层

- **据官方文档，Tripo 和 Meshy 都没有承诺「袍子一层盖在完整的腿上」。**
  - Tripo 的 `generate_parts` 和分割接口（`/v3/mesh/segment`、SmartSegment）只是把已有的表面切开。被袍子挡住的腿要用 Part Completion 补（50 点数），补出来的是猜的。来源：<https://developers.tripo3d.ai/en/docs/mesh-segment>、<https://developers.tripo3d.ai/en/pricing>
  - Meshy 的 `meshy-t2` 自称能分开部件，也没说会补齐被挡住的部分。
- **做不到时在 Blender 里要手工做的**（推断，在所有者电脑上做，约 3–6 小时，熟练程度影响很大）：
  1. 沿下摆把袍子和裤子剪开，袍子的下摆收口（Solidify 加一点厚度，免得从下面看穿）；
  2. 补腿：从下摆以下的裤腿往上挤出到胯部，或者复制代码身体的腿和裤子的形状来改，两条腿在裆部合上；
  3. 补出来的腿用 Voxelized 绑定，或者从身体传递权重；
  4. 坐凳和盘坐各摆一次，修穿插。
- 改权重解决不了这一层（见 A）；**这是 B 的主要理由，也是 B 最大的风险。**

### B.6 在容器里实测了的部分（Blender 5.3.0 的 Python 模块 `bpy`，`pip install bpy==5.3.0`，没有界面）

用免费的东西代替生成器和 Auto-Rig Pro，跑通了「绑好的模型 → 我们的骨骼 → `novice.js` 穿得上」这一段：

1. `tools/novice-retarget-trial.py`：
   - 读入现在的 `novice.glb`，先用一副 A-pose 骨架把它弯成 T-pose，扔掉权重，当作「生成器给的 T-pose 新模型」；
   - 建一副 **Unreal 命名**的骨架（Auto-Rig Pro 游戏导出默认的名字）贴合 T-pose，用 Blender 自带的热扩散权重绑定（代替 Auto-Rig Pro 的 Bind）；
   - **重定向**：逐根骨骼摆到 `monk.js` 的 A-pose 关节位置，网格按这个姿势变形，再把它设为静止姿势。对方的关节和我们的关节**相差 0.00 毫米**；
   - 导出带蒙皮的 GLB。
2. `tools/novice-retarget-trial.mjs convert`：按对方关节名换成我们的骨骼编号，按材质名切成四部件，腰带以下的袍子换上裙摆权重，写成 `novice.glb` 的格式（未贴图时 1.24 MB）。
3. 用 `novice.js` 的 `bodyOf` 和 `monk.dress` 穿上：**格式被接受**，权重全部归一，走路 90 帧里每一帧都有一只鞋底着地。

同时暴露了两个问题，第二步要处理：

- Blender 的热扩散权重在这层不封闭的外壳上，有 **231 个顶点没有拿到权重**（导出时会多出一根 `neutral_bone`），转换时改用代码身体的权重补上。Auto-Rig Pro 文档对多层衣服推荐 Voxelized，正是为了这种情况。
- 按部件分别绑定以后，重合副本的权重**照样不同**（4,355 对），走路时最多分开 341 毫米。所以**无论哪条路，转换时都要再做一次 A 的「同位置同权重」**，或者在 Blender 里先合并重合顶点再绑。
- 热扩散权重的质量**不能代表** Auto-Rig Pro。这里只证明流程走得通，不证明效果好。

### B.7 面数和文件大小

- **现在**（实测）：`novice.glb` 1.68 MB，其中几何 1.24 MB（未压缩）、三张 1024 px WebP 贴图 0.44 MB；20,460 个三角面、17,704 个顶点。代码身体是 30,716 个三角面。
- **新的预计**（推断）：
  - 分层后（袍子带内侧，加上完整的腿）约 2.5–3 万三角面，未压缩几何约 1.6–1.9 MB；
  - 换成 meshopt 压缩（寺里的造像已经这么做，`interior.js` 设了 `MeshoptDecoder`，但 `novice.js` 现在没设，要加一行）估计能降到 0.5–0.8 MB；
  - 贴图不变；总计约 1–1.3 MB。
- **手机低档**（推断）：低档在手机尺寸下一帧约 55 万三角面（2026-11-14 在 T4 上实测），多一个 3 万面的身体约占 5%，**和代码身体的 3.07 万面相当**，不会更重。按 #80 的要求，第二步要在 T4 上量一次帧时间。

### B.8 哪些在云端做，哪些在所有者电脑上做

| 步骤 | 在哪做 | 说明 |
|---|---|---|
| 出补充视图（去斗笠和念珠、下摆露出裤腿） | 所有者 | 出图工具和账号在所有者那里 |
| Tripo 生成（选模型、面数、贴图） | 所有者 | 需要账号和付费；本会话不注册、不索要凭据 |
| 合并重合顶点、剪开下摆、补腿、分配四个部件的材质 | 所有者（Blender 界面） | 补腿是建模，需要看着做；合并顶点和分材质也可以给一个 bpy 脚本在云端跑 |
| Auto-Rig Pro：Smart 标记、Match to Rig、加 `cc_` 骨骼、Bind、试坐姿 | 所有者 | 付费插件不进仓库；官方没说能后台运行 |
| 导出 GLB（改名表输出我们的骨骼名） | 所有者 | 也可以导出 Unreal 名，云端再换算 |
| 重定向到我们的 A-pose、设为静止姿势 | **云端可做**（实测：bpy 5.3.0） | `tools/novice-retarget-trial.py` 已经跑通 |
| 换算骨骼编号、切成四部件、裙摆权重、同位置同权重、压缩 | **云端可做**（实测） | `tools/novice-retarget-trial.mjs` 加上 `novice-weld.mjs` |
| 测试、截图、`edges`、T4 帧时间 | **云端可做** | 现有工具 |

**所有者照做的清单（草稿）**

1. 用出设定图的工具出四视图：正、左、背、右，A-pose，去掉斗笠和念珠，衣服和设定图一致；下摆最好能看出裤腿是完整的。
2. 在 Tripo 里选多视图生成，模型 H3.1，带 PBR 贴图，面数上限 2 万，打开按真实尺寸缩放；另出一版勾「分部件」的白模做对照。两版都下载 GLB。
3. 在 Blender 5.2 LTS 里装 Auto-Rig Pro Full（Auto-Rig Pro 目前列出的支持版本最高是 5.2；5.3 已发布，但 Auto-Rig Pro 尚未列出支持）。
4. 打开模型：
   - 按距离合并顶点（Merge by Distance）；
   - 沿下摆把袍子和裤子分开；
   - 把裤腿补到胯部；
   - 给皮肤、袍、裤、鞋各一个以 `skin`、`robe`、`legs`、`shoes` 命名的材质。
5. Auto-Rig Pro 绑骨：
   - Smart → Guess Markers，核对标记点 → Match to Rig；
   - Bind 选 Voxelized；
   - 摆抬臂、屈腿、坐凳、盘坐，看有没有破面。
6. 导出 GLTF，影响数限制为 4，骨骼类型选 Humanoid（Unreal 名）。不需要加裙摆骨骼：转换工具会从代码身体取裙摆权重。
7. 把导出的 GLB 和 Tripo 原文件交给云端会话（放到能拿到的地方），记下 Tripo 的任务参数，以便登记进 `asset-register.csv`。

## 结论

1. **先做 A**（预计半天到一天，需要所有者提供 Meshy 原文件）。
   - 交付：重建的 `novice.glb`，加上 #80 第二步的两条测试（重合顶点同权重；站立、走路、上台阶时重合顶点相距不超过 1 毫米），站立、合掌、走路的截图。坐姿写进 `KNOWN-ISSUES.md`。
   - 实测已经证明分离会降到 0。风险是被拉长的三角形在截图里看不看得出来。
2. **再做 B**（所有者花约 $70 和 0.5–1 天在 Blender 里操作，云端再花约 1 天转换、测试、截图，T4 上量一次帧时间）。
   - 交付：分层的身体，坐凳和盘坐时没有空洞，七种仪式各一张截图。
   - A 的焊合步骤和本次跑通的重定向工具会直接用上。
3. **B 走不通时卡在哪一步**：最可能卡在「袍子下面有腿」。
   - 如果 Tripo 和 Meshy 都给不出分层的模型，所有者又不愿意在 Blender 里补腿，B 就只能停在「换一个拓扑更干净的单层外壳」，坐姿仍然不行。这时目标按 #80 退回 A 的范围。
   - 第二个风险是 Auto-Rig Pro 的 Smart 标记点和 Bind 只能在界面里操作（官方没说能后台运行），这几步一定要所有者在自己电脑上做。
