# #477 第二处：为什么大雄宝殿月台脚下的 6 格会随远处的树变（`inside()` 的并列面）

#533 合并后，T05 主创比较「main」与「把远处银杏换成别的」两次烘焙，大雄宝殿月台脚下仍差 6 格。本 PR 追到根并修掉。

## 一、机制

`bake.mjs` 的 `inside(S, x, y, z)` 判断一点是否在实体里：向四个水平方向各打一条射线，取**第一个**交点，四个方向的第一个交点都是背面，才算在里面；在里面的地面（`aboveUp && inside`）被取消，不记作地面。

月台的石座与台阶在踏步头相接，两者的面在同一个位置重合：石座的背面和踏步的正面离射线起点一样远。三角形相同、距离相同时，`raycastFirst` 返回哪一个，由 BVH 的排布决定，而 BVH 的排布取决于**场景里的全部三角形**。远处加一棵树、换一棵树，同一格就可能从「第一个是背面（在里面）」变成「第一个是正面（在外面）」，石座里的假地面时有时无，邻格的边界跟着变 5 cm。

最小复现在 `tests/unit/walk-bake-inside.test.mjs`：一座月台加台阶，远处按种子撒不同的方块，旧规则 24 个种子里有 12 个让同一点的判断不同。

## 二、修法

`inside()` 取到第一个交点后，再看它前后 1 mm 内的**所有**面：只要其中有背面，这个方向就算「里面」；只有当所有同距的面都是正面，才算外面。结果只与几何在这一点上是什么有关，与 BVH 无关。`BAKE.version` 28。

## 四、「远处几何变了，月台脚下不变」的单测

`walk-bake-inside.test.mjs` 第三项：真实的 T00 场景，围着首院 x −14..14、z −30..−2 窗口烘焙两次，一次全部场景，一次把所有树皮材质的网格（银杏、柏树的树干）藏起来，要求**一格都不同**。旧规则下有 9 格不同，现在 0。前两项是 inside() 本身：台阶与石座并列面在 24 个种子的远景下判断一致；空地、月台上、台阶之外为假，台阶内为真。
