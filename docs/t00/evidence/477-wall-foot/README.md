# #477：墙脚少关了一圈格子，机制查清了（2026-11-21）

**结论：不是几何对格子的局部影响，是烘焙里「谁被洪水走到了」这件事在远处变了。** 加了两座山门之后，沿着围墙脚一圈 0.35 m 高的石裙的顶面从「走不到的孤岛」变成了「走得到的地面」，墙脚旁边的格子于是换了一种方式被关；换了方式之后，关的范围小了 5 cm（一格）。两种结果他都站得住，edges 都是 0；但同一面墙、同一块地，烘焙结果取决于十几米乃至几百米外的台阶，这一点不是我们想要的。

## 一、现象

`node tools/bake-walk.mjs --level=t05` 对 f9454074^（#464 之前的 main）与 f9454074（三座外壳）的 `outdoors` 格子比较（两者网格范围、起点、步长完全相同，所以格子一一对应）：墙脚 `x = ±41.125`（北墙 `z = -39.125`，南端 `z = 220.125`）处沿整圈各多开一格宽的格子，共约 29.4 m²（#464 报的 28.2 m² 是对当时的 main 比的，同一批）。

## 二、机制，一步一步

1. 围墙是一块 0.8 m 厚、3.2 m 高的粉墙（面在 `x = ±41.6`），脚下一圈石裙：1 m 宽、**0.35 m 高**（比他迈得上的 `CLIMB` 0.25 高），外沿在 `x = ±41.5`，比粉墙的面多出 10 cm（`app/levels/t05/site.js` 的 `COMPOUND`）。
2. 烘焙里每个格子的地面要先**被洪水走到**才算有地面（`bake.mjs` 第 3 步：从起点出发，格子之间相差不超过 `CLIMB` 才连起来）。石裙顶（0.35 m）与地面（0）差 0.35 > 0.25，**走不上去**，所以石裙顶那 10 cm 宽的外檐是一块洪水到不了的孤岛：它的格子高度记作 `NaN`，即「没有地面」。
3. 第 4 步对每个格子看八个邻居：邻居是 `NaN`（没有地面）就把这个格子记为 `NOFLOOR` 边界，**从地面到 `CLEAR`（1.45 m）全高都当作有东西**（「墙身、殿的外壳，不知道里面是什么」，保守）。于是紧贴石裙外沿的那一排格子成了整高的边界，他的外廓在腰高伸出 0.379 m：外沿 `x = -41.5`、边界格 `x = -41.475`，关到 `x ≈ -41.096`，`x = -41.125` 的格子被关。
4. 外壳提交里，**外山门的平台是 0.5 m 高**，与两侧甬道围墙的石裙顶（0.35 m）只差 0.15 m，小于 `CLIMB`。平台是走得到的（有台阶），洪水于是从平台**越过石裙**，沿着石裙顶一路连通整圈围墙脚（连成一片 469 m²，接合处在 `x = ±8, z = 204–208`，高 0.50 m，每边约九十个格子）。石裙顶这回是「有地面」了。
5. 有了地面，外檐上的格子也成了正常的边界来源：石裙外沿的格子这回看到的邻居是真地面（0.35 m），比自己高 0.35 > `CLIMB`，记作 `LEDGE`（高 0.35 m，外廓只在鞋的高度，伸出 0.322 m）；粉墙面（`x = -41.6`）也成了自己的边界（离格子 0.475 m，大于 0.379）。边界变了，`x = -41.125` 的格子就不再被关了。

**哪一种是对的？** 粉墙面离 `x = -41.125` 的格子是 0.475 m，他的外廓最宽伸出 0.379 m（腰高），所以这一格其实够得着站、碰不到墙：开着是准确的，关着是保守的（保守在石裙外沿比粉墙面多出的那 10 cm）。两种他都不会进到墙里（edges 都是 0）。

## 三、最小复现（`repro.mjs`，一秒）

一块地、一面带石裙的墙（尺寸同上），烘焙后看墙中部（`z = 0.025`）院子一侧第一个开着的格子；再加一块不相干的东西：

| | 墙脚第一个开着的格子 `x` | 石裙顶 |
|---|---|---|
| A 只有墙和地 | 0.425 | 孤岛，没有地面 |
| B + 一块 0.2 m 高的小台（走得上去）贴着石裙的**端头**，离被看的格子 10 m | **0.375**（多开一格） | 走得到（0.35 m） |
| C + 同一块小台，离石裙端头 1 m（不贴） | 0.425 | 孤岛 |
| D + 同一块小台远远放着 | 0.425 | 孤岛 |

**关键不是「加了几何」，而是「那块几何让洪水从哪里走上了石裙」。** C、D 说明不相干的几何不动格子；B 说明只要有一处台阶使石裙顶走得到，整面墙脚的结果就换了一种。

## 四、可以怎么办（等主创定，没动代码）

1. **不改，把它写成正确行为。** 理由：保守的那一种只是比准确多关 5 cm，edges 为 0，没有一处走不到。缺点：这一格取决于远处的台阶，下次别的壳提交可能又动一圈。
2. **改成不依赖洪水，一律按准确的算（推荐试）。** 做法是：第 4 步里，邻居「走不到但有地面（有一个 span）」的格子，用它那一层地面的高度参与 `lo`/`up` 判断（记作 `LEDGE` 而不是 `NOFLOOR`），并且让走不到的格子也能成为边界来源（粉墙面进到边界）。这样 A 和 B 都得到 0.375。风险：这是共用的烘焙（`tools/walk/bake.mjs`），所有走不到的孤岛（屋顶、桌面、台基顶）周围的边界方式都会变，T00 的 walk-diff 可能不为 0，要逐处解释，T00 主创要签字。
3. **改成一律保守。** 走不到的地面也一律当作「没有地面」，包括被洪水走到的石裙外檐；做法是在洪水之后把比邻近地面高过 `CLIMB` 的那种「走得到的窄檐」（宽不足一只鞋）退回 `NaN`。会让 B 也得到 0.425，且把 #274 的「窄檐不是站得住的地方」推广到石裙。风险同上，且更多关格。

我的建议是先试 2，量一下 T00 与 T05 的 walk-diff；如果 T00 的变化大到解释不完，就退到 1，并把「这一格取决于远处台阶」写进 bake 的注释。
