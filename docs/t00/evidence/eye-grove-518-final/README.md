## 二、T05 前后对照（共用代码改了 bamboo.js、eyespace.js、level.js、yard.js）
`t05/`：`?level=t05&show=<arrive|b|d>&view=third&q=low`，`__eyeSpace` 变成 ready 之后再等 120 帧。

- `t05-before.json`（main）和 `t05-after.json`（head）里的 `__frame`：at、eye、look、dist，到小数点后四位**完全相同**。
- 截图不是逐位相同。差值大于 8 的像素：arrive 1189、b 232、d 272（全图 921,600 个）。
- 为了看清这些差是不是本 PR 造成的，同一个 main 构建又拍了一遍（`t05-before2-*`）。两次之间的差是 arrive 575、b 19354、d 97，所以上面的差都在运行间的噪声以内（风、飘落物）。
- T05 不提供 `eyeKeepOut` 和 `clearUnder`，走的还是改前的路径。

## 四、T4 帧成本（验收第 6 条）
`t4/`：Hugging Face Job，Tesla T4，ANGLE on Vulkan，run 20261122-013956。

- 同一个 Job 里 head 和 main 交替各量 4 次：main 的构建放在 `base/` 下（`BASE_SITE`），每轮先后顺序互换。
- 1920×1080，高档。每次先暖 1.5 s，再数 6 s 的帧，然后取 `__cost(40)`。
- `report.json` 的 `site` 记的是 head 的提交 fa578d0 和整站哈希。

| 机位 | head `__cost` 均值 | main 均值 | 差 | 三角形 head / main | 绘制次数 |
|---|---|---|---|---|---|
| court（秋·暮） | 13.66 ms | 13.67 ms | −0.01 | 1,996,872 / 1,997,064 | 394 / 394 |
| 竹林起点 `?cam=21.3,91.5,0,0.04` | 13.99 ms | 13.84 ms | +0.15 | 1,002,595 / 1,002,691 | 237 / 237 |
| 洗砚池报告点 | 8.54 ms | 8.54 ms | 0.00 | 473,803 / 473,901 | 64 / 65 |

- 三处的差都在 0.2 ms 以内，按 T00 主创定的线算过。
- 竹林起点单次之间的波动约 2 ms（13.2–15.4），差 0.15 ms 在这个波动以内。
- head 的三角形少几十到一百多个，是洗砚池边清掉的草丛卡片。
