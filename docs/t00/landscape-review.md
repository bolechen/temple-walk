## 结论

主创的判断成立：**远景是现在最弱的一层**。近景和中景站得住，过了围墙就像一块背景板。差距按影响大小排：

1. **空气（最大，也最便宜）。** 远处没有明度阶梯：效果图里从近到远是 31 → 39 → 55 → 63 → 69 → 74（天），每一层差 6～8 个 L\*，越远越冷；我们山顶回望里三重山和天挤在 80～89 之间，秋暮、春晨的远山**比天还亮**，还偏暖。冬昼、春晨的雾在 200 米处已经把寺院本身吃光，远山却因为不走同一套雾，反而浮在一片白上。原因是远山的着色器自己按固定比例混雾，不按距离，也不走 `FogExp2`。
2. **几何。**
   - 远山是三圈开口圆柱，每圈只有一条上沿：剪纸一样平，锯齿状的折线山脊，山体内部只有一层噪声斑。
   - 圆心放在 z = −45，离山顶太近。从山顶向南回望，三圈山的山脊仰角分别只有 4.3°、1.2°、3.5°，后两圈几乎全被第一圈挡住，所以看上去只有一道弧。
   - 谷底是一块空的平地。
   - 墙外的远竹是几条 17 米高的竖直卡片带：平顶、能看出重复，从山顶东西两侧看是一堵绿墙，带子尽头是一刀切的竖边。
3. **天。**
   - 夏昼（J01）是满天一片均匀的灰；
   - 云用的是值噪声，能看见直线折痕；
   - 春晨山顶回望的左上角有一块硬边的亮楔。
4. **穿帮。** **竹林起点向南看，竹子底下露出一条白天**：地面网格只铺到 z = 130，竹带的镂空后面就是天空（`__pick` 已核）。这是开场第一眼就能看见的地方，排在最前。

**最值的三件**，按顺序：
1. 补边界和穿帮（L1），改动小，开场就见效；
2. 远景空气透视阶梯（L2），不加三角面，观感变化最大；
3. 远山重做成多重山脊，加谷中云海（L3、L4），工作量最大，但有了 L2 才立得住。

远林（L5）和天空（L6）随后。六项各开一个 issue，见文末。

## 三、空气透视：量出来的数

**测法**：在同一张图上取 14×14 像素的小块，按 `tools/look.py` 的算法换成 CIE L\*a\*b\*（D65），读 L\* 和 b\*（正为暖，负为冷）。

**山顶回望，秋晨（`art6` 与效果图 06）**：

| 层 | 效果图 L\* / b\* | 我们 L\* / b\* |
|---|---|---|
| 天 | 73.8 / −3.5 | 86.0 / −4.9 |
| 最远一重山 | 68.7 / −4.9 | 86.6 / +3.8 |
| 中景山脊 | 62.6 / −8.5 | 83.1 / +4.6 |
| 谷中雾 | 54.8 / −8.2 | 88.4 / +3.8 |
| 近处林坡 | 39.1 / −4.7 | 85.4 / +3.9 |
| 近处杉树 | 47.8 / +0.4 | 46.7 / +1.8 |
| 近处屋顶 | 30.7 / −2.4 | 47.0 / −1.4 |

`tools/look.py --check 06-summit`：11 项未过，上面三条横带 89 / 89 / 83，目标 66 / 63 / 45。

**山顶回望，四种季节时辰的阶梯（只看 L\*）**：

| | 天 | 最远（R300） | 中（R215） | 近（R150） | 谷底 | 近处杉树 |
|---|---|---|---|---|---|---|
| 夏昼 | 81 | 81 | 80 | 71 | 74 | 29 |
| 秋暮 | 78 | **83** | **82** | 76 | 80 | 38 |
| 冬昼 | 89 | 89 | 89 | 85 | 91 | 77 |
| 春晨 | 89 | **93** | 88 | 85 | 91 | 80 |

**读法**：
- 效果图从近到远一级一级亮上去，每级约 6～8；我们远山三重之间只差 1～2，等于没有层次。
- 秋暮、春晨的远山比天还亮（加粗处），而且偏暖，方向反了。
- 冬昼、春晨从杉树到天整幅都在 77～93，等于一张白纸。

**原因**（代码）：
- 远山（`backdrop.js` 里的三圈山）用自己的着色器：山顶色和雾色按**固定比例** `k = 0.5 / 0.74 / 0.88` 混合，与距离无关，也不走 `FogExp2`。山脚的「雾」是按高度的 `veil`，雾色就是整片 `m.fog`，所以远山永远是那几个固定的灰。
- 场景的雾是指数平方雾，冬昼密度 0.011、春晨 0.014：100 米处已有 71% 和 85% 的雾，200 米处几乎 100%。山顶到首院就有 150 米以上，所以寺院先被吃光，不走这套雾的远山反而浮在上面。
- 雾只有一个颜色 `m.fog`，没有「近处偏地色、远处偏天色」的分层，也没有越远越冷。

**应当是什么**：
- 远山按真实距离走同一套空气：每一重山把明度往天的明度推、把色相往天的冷色推，越远推得越多；而且永远不超过天的明度（日出方向除外）。
- 谷底一层低雾（高度雾）把近山和远山隔开。
- 冬昼、春晨的雾按距离分段：250 米内留出寺院的结构，雾只在远处浓起来。

**参考**：
- 郭熙《林泉高致》的「三远」：「自近山而望远山，谓之平远」，后文说「平远之色有明有晦」（转引，未核原书版本）。
- 实景：径山一带属天目山脉，茶区资料说它多云雾、多漫射光（浙江政务网的径山茶资料，只核到摘要）。
- 游戏：Sucker Punch 说雾和大气散射是《对马岛之魂》定画风时的重点（PlayStation 博客的《羊蹄山之魂》技术文，原文核过）。

**判定**：局部修。不加面，改 `backdrop.js` 远山着色器和 `mood.js` 的雾表，见 **L2**。

## 四、逐层评

每条都写：位置、现状、应当是什么、属于哪个来源（几何、空气、天）、判定。

### 1. 山形

**位置**：山顶回望、凌霄阁前东西、首院看山，四种季节时辰都看得到。

**现状**（`lookback_*.jpg`、`art6_autumn-dawn.jpg`、`compare/06-…`）：
- 三圈 `CylinderGeometry(R, R, 1, 360, 1, true)`，R 分别是 150、215、300 米，只有上下两圈顶点。山的「形」只是上沿顶点的高度：5 次和 11 次正弦叠一个「北面高」的项，再加三支高频正弦当树梢。
- 结果是一条折线：每 1° 一个折点，轮廓上能看到一段段直线和尖角（`lookback_summer-day.jpg` 左半部）。
- 山体是一整片平面，没有朝光面和背光面，只有一层斑驳噪声。最远那圈的噪声在亮天下读起来像一团团石膏，不像山林。
- 三圈的圆心都在 z = −45。站在山顶（z ≈ −123）向南看，三圈山脊的仰角：

  | | 北 | 东 | 南（回望） | 西 |
  |---|---|---|---|---|
  | R150 | 10.7° | 5.8° | **4.3°** | 4.1° |
  | R215 | 21.1° | 10.2° | **1.2°** | 12.6° |
  | R300 | 19.4° | 7.3° | **3.5°** | 11.9° |

  向南回望这个主画面里，后两圈比第一圈还低，被挡住或贴在一起。这就是「远山只有一道弧」的直接原因。
- 最远的山离人只有 228～378 米。真山的远景在几公里外，而三圈都在 300 米以内，雾只能在「全看见」和「全白」之间切换，排不出层次。
- `docs/JINGSHAN.md` 写的是「五峰环抱，北面最高」。现在的轮廓是每圈五个起伏，北面加高，大意有了，但五座峰在任何一个画面里都认不出来。

**应当是什么**：
- 五到六重山，每重是一条有厚度的**山脊带**（几行顶点，有山脊、有坡面），不是一圈纸边。
- 从近到远：
  - 第一重：近的林山，0.3～0.6 km，就是寺院所在的山；
  - 第二、三重：中景，1～2 km；
  - 第四、五重：远景，3～6 km，最高、最淡。
- 距离不必真放那么远：可以把带子放在 0.4～0.9 km，按**假距离**给雾（每重一个「视作距离」）。这样不用把相机的远裁剪面放远。
- 从山顶回望，每一重山脊的仰角都比前一重高一点，像山水画的平远，能一眼数出三重以上。
- 五峰：北面的主峰和东西两侧的峰在回望和首院看山时能认出来。
- 山脊的轮廓用山脊噪声（ridged noise）加一点侵蚀感，不用正弦。坡面按太阳方向分明暗，阴天时只分轻重。

**参考**：
- 山水画的平远和深远（同上，转引）。
- 《羊蹄山之魂》把远山的模型和地形材质烘成贴图，以便远处也能显示更多细节（PlayStation 博客，原文核过）。我们的栈上可取的做法是**把远山的光照和雾预先算好，存进顶点色或一张小贴图**，不做实时高精度。
- three.js 上做分层山脊加雾色的做法很常见（runevision 的空气透视笔记，只核到摘要）。

**来源**：几何。**判定**：重做（远山部分），见 **L3**。

### 2. 远林和远竹

**位置**：首院向东越墙、凌霄阁前东西、山顶回望两侧、首院四向转圈。

**现状**（`court-east_*.jpg`、`lx-e_*.jpg`、`lx-w_*.jpg`、`turn-court-*.jpg`）：
- 墙外的「远竹」是 `backdrop.js` 里的 `band()`：一条条 17 米高的竖直平面，着色器画竹竿和叶团。从院里平视时还能读成一片竹林，但有三个问题：
  - **平顶**：叶团的上沿起伏只有一两米，整条带读成修剪过的绿篱（`court-east_summer-day.jpg`）；
  - **重复**：几条带共用同一种噪声，能看出同一个团块在复现；
  - **从高处看穿帮**：凌霄阁前向东西看，带子是一堵竖直的绿墙，尽头一刀切出竖边，后面就是灰天（`lx-e_summer-day.jpg` 右侧、`lx-w_summer-day.jpg` 左侧）。
- 墙外山坡上的 25 棵「远杉」（`site.js` 里标 `far` 的）在回望时排成一行行，挺好；但它们和远山之间是空的。近的林山没有树冠，只有斑驳的噪声面。

**应当是什么**：
- 远竹的叶冠上沿要有大的起伏（竹林冠层随地势有几米的高低），而且从高处向下看时，要读成一片**有顶面的林冠**，不是一堵墙。
- 带子的两端收进地形或雾里，不露切口。
- 近的林山（第一重）要有能读出来的树冠：用实例化的杉树和阔叶树的远景贴片（impostor），按山坡铺开，顶面朝上。J01 参考图和效果图 03、04 的那面林坡就是这个样子。
- 和近处真树、真竹的衔接：贴片的色调和近处的树一致，越远越淡（L2）。

**参考**：
- 《荒野之息》按近、中、远三档处理远处，远处用颗粒效果，中景的垂直范围用雾调整（Famicast 引述官方技术讲座，转引）。
- 远处换贴片、分级细节，已经写进 #72 第四阶段「植被」，但那是对着六个美术机位的近中景。

**来源**：几何。**判定**：局部修（远竹带）加重做（近林山的林冠），见 **L5**。

### 3. 云、雾、云海

**位置**：山顶回望、凌霄阁前、石阶转折、首院看山。

**现状**：
- 有三样东西：
  - 场景的指数平方雾；
  - 远山着色器里按高度的 `veil`；
  - `props.js` 的 14 片雾片：墙外两侧，一直排到山上，规定不过院子、不横过屋顶。
- 雾片这次没发现穿帮：`__pick` 查过的硬边都不是它。
- 春晨回望左上角那块亮楔，`__pick` 说是天空本身，不是 `props.js` 的光柱片。原因还没查清，可能是日晕叠上泛光（bloom），记进 L6。
- **没有云海**。谷底是一块平的灰地，在回望里读成一片空白的湖面（`lookback_summer-day.jpg` 中部偏下那条水平的边）。
- 山腰没有成片的雾带，看不到雾从林间升起。J01 参考图的那种山腰雾，我们没有。

**应当是什么**：
- 谷中一层云海：比山顶低 20～40 米、横跨整个视野的几层大面片，带柔和噪声的透明度，靠近地形的地方按深度淡出，慢慢漂动。这样谷底的空地自然被盖住，近山和远山被一条白隔开。
- 山腰几条雾带，贴着第一重林山的等高线。
- 季节时辰：
  - 夏昼和春晨最浓；
  - 秋暮薄，带暖色；
  - 冬昼贴地；
  - 夜里收起，或者只剩一条淡灰。

**参考**：
- 效果图 06 的谷中云海。
- Sucker Punch 说《对马岛之魂》的引擎做不到让云挡在地形前面，《羊蹄山之魂》才做到（同一篇博客，原文核过）。我们这一档用不起体积云，**面片云海**是对手机可行的做法。
- three.js 的 `@takram/three-clouds` 是体积云库，支持 WebGL，但很重，不适合低档（npm 说明，原文核过）。

**来源**：空气为主，几何为辅（几块面片）。**判定**：新增，见 **L4**。

### 4. 空气透视

见第三节的数和判定，即 **L2**。

### 5. 天空

**位置**：所有能看到天的画面。

**现状**（`sky.js`）：
- 天顶到地平线的两色渐变，加日晕、星和一层云。
- 云是值噪声 `fbm2` 投在平面上的一层，只用 `uCloud` 控制覆盖率。
- 夏昼（J01）`cloud = 1`，整片均匀覆盖，读成一块平的灰（`court-roofs_summer-day.jpg`、`lookback_summer-day.jpg`）。
- 天上能看到几条直的斜折痕。`__pick` 查过，这些点都只是天空本身：值噪声在低频时会露出格子方向，是天空材质自己的问题，不是别的东西挡在前面。
- 秋暮天顶偏紫（`#72` 的基线里已经记过「最亮的是偏紫的天」）。
- 春晨回望左上的亮楔（见上）。
- 太阳的方向（`SUN_DIR`）和天上日晕的位置用的是同一个向量，没有发现不一致。但效果图 06 那种「太阳落在两重山之间」的构图，我们的山太低，做不出来。

**应当是什么**：
- 阴天的云要有大的形体：几团明暗不同的云底，地平线一带亮一条（雨后山间常见的天光）。不要一整块灰。
- 换成梯度噪声或域扭曲噪声，去掉直线折痕。
- 天永远比最远的山亮一点；晨昏的天在太阳一侧暖，另一侧冷。

**参考**：效果图 06 的天。《林泉高致》也写到四时之气，说「烟云」随时节而变（转引，未核原书版本）。

**来源**：天。**判定**：局部修，见 **L6**。

### 6. 地平线和边界

**位置**：竹林起点四向、凌霄阁前东西、观音殿台地、石阶转折。

**现状**：
- **竹林起点向南看，地平线下有一条白天**（`turn-bamboo-s_summer-day.jpg`、`turn-bamboo-e_summer-day.jpg` 左侧、`stair-out_summer-day.jpg` 右下）。
  - `__pick` 在 (960, 640～760) 一列点上，都是先穿过 z = 116～124 的竹带，然后就是天空，中间没有地面。
  - 原因：`createEarth` 的地面网格是 280 × 360 米，平移到 z 从 −230 到 130；竹林起点在 z ≈ 92，南面 40 米外地面就没了。竹带着色器把叶缝 `discard` 掉，后面露出的就是天。
  - 这是游戏开场第一眼的地方。
- **远竹带的一刀切竖边**（凌霄阁前东西，见四、2）。
- **R150 那圈山上有一条竖直的硬边**：山顶回望左侧，`__pick` 确认是那圈山本身。原因未查清，可能是圆柱接缝或雾的 `veil` 在那里断开。
- 谷底那块平地的边（见四、3）。
- 观音殿台地看不到山：殿前向南被藏经阁屋顶挡住。这不算穿帮，但说明「观音殿台地向下看」不是一个看远景的好机位。远景机位应该选在台地东西两端，或者观音殿两侧。

**应当是什么**：
- 从任何能走到的地方、任何方向，地平线以下都是地形、林冠或云海，看不到天。
- 地形网格要铺到最近一重山的山脚，或者在外围加一圈向下的「裙边」，接到雾里。
- 远竹带的两端收进地形或雾里。

**来源**：几何。**判定**：局部修，见 **L1**。

## 十、补记：这六次 T4 运行画的是不是 `2d1c7d7`（2026-11-17 核对）

**起因**：主创发现，#128 之前几个会话共用 Hugging Face 桶里的同一个 `in/` 目录，每次运行都 `sync --delete` 覆盖它。别的会话可能在我上传之后、我的 Job 读文件之前，把 `in/` 换成它自己的版本。#125 的会话就遇到过一次画成 `main`、一次全是 404。本评审的六次运行在 15:15～15:34 UTC，那时 `report.json` 里还没有 `site` 指纹，只能事后核对。

**结论**：画的是 `2d1c7d7`，评审结论不受影响。核对了三件事：

1. **不是 404 页**。
   - 66 张图逐张算了灰度标准差（缩到 320×180），全部在 12 以上，没有一张是空白页或单色页。
   - 每张图都看过：石面、树皮、瓦面的扫描纹理都在。如果纹理文件 404，材质会退回扫描的平均色，看起来是平的。
   - 六份 `report.json` 的 `shots` 都没有报错。但要注意，`job.cjs` 的错误过滤会滤掉 404 消息，所以这一条本身不足为证，要靠前两条。
2. **那段时间别处的 `app/` 是什么**。
   - `git log --all` 查 14:30～15:40 UTC 动过 `app/` 的提交：`main` 在那段时间最新的 `app/` 改动是 14:18 的 `0a88f96`（#89），之后 `main` 的 `app/` 与 `2d1c7d7` **一字不差**（15:40 时的 `main` 是 `67f1d27`，`git diff 2d1c7d7 67f1d27 -- app/` 为空）。
   - 别的分支只有 `claude/zen-edison-vshjy9` 在 15:27 有一次 `app/` 提交（`2a2104e`，#71 的自动镜头）。它与 `2d1c7d7` 的差别是：
     - `director.js`、`rites.js`、`game.js`、`settings.js`、`interior.js`、`well.js` 等打卡点运镜和菜单开关；
     - `site.js` 里给打卡点加机位数据；
