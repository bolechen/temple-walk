## 四、预算

#72 定的门槛：首院高档 ≤ 16 ms，p95 ≤ 25 ms。**首院高档现在没有超过 16 ms**（10.1–10.8 ms），所以按 #74 的要求，不列「要砍的三项」；上面第二节最贵的是建筑（2.16）、倒影（2.13）、泛光（0.35），仅作参考，没有提议要改。

| | 现在 | 上限（建议） | 留给 #72 | 留给结构线 |
|---|---:|---:|---:|---:|
| 高档 三角面（一帧，含倒影） | 193 万 | **230 万** | 约 10 万 | 约 27 万 |
| 高档 绘制次数 | 354–378 | **430** | 约 20 | 约 30 |
| 高档 画一帧（T4 `__cost`） | 10.1–10.8 ms | 12 ms（硬线 16 ms） | | |
| 低档 三角面 | 87 万 | **87 万（不增）** | 0 | 0 |
| 低档 绘制次数 | 177–189 | **190（不增）** | 0 | 0 |

依据：
1. **高档的硬限是 p95，不是 16 ms。** 画一帧还有 5.2–5.9 ms 到 16 ms，按 1.75 ms/百万面可再加约 300 万面；但 tour 的 p95 已是 21.1–25.0 ms（含浏览器呈现的约 10 ms），第一趟已经顶在 25.0，余量实际接近 0–4 ms，折合 0–约 100 万面，取保守的 +37 万（≈ +0.65 ms）作为上限 230 万，其中结构线（角梁、飞子，平坐已在 `0a88f96` 里）取 27 万、美术（#72）取 10 万。这个分法是我的取舍，见下面「请所有者定」。
2. **低档不留余量。** 技术美术给手机的预算（HANDOFF）是 45 万面 / 120 次 / 不画倒影，现在已是 87 万 / 177–189，超过一倍；T4 比手机快数倍，手机一帧多少没测过。在有一台手机量过之前，低档只守住不增。结构线的新增在低档应靠 LOD（低档不出飞子、补间铺作等）抵消，不是在低档上加。
3. 绘制次数近乎不随几何涨（四项全关 62 次，`site` 占 215 次），上限按当前最大值 +约 20%。

## 五、主创 2026-11-16 定

来自 PR #107 的评审评论（主创 + 上线前评审，head `37d99fa`）：

1. **高档上限 230 万面 / 430 次，结构线约 27 万、#72 约 10 万：接受，不压到 210 万。** 画一帧离 16 ms 还有 5 ms 以上，真正紧的是 p95，而 p95 里约 10 ms 是无头浏览器自己的呈现。这个上限是软线；硬线仍是 #72 定的「首院高档 ≤ 16 ms、p95 ≤ 25 ms」。哪条线的 PR 让 `__cost` 超过 12 ms，就在 PR 里说明并停下。
2. **低档「只守不增」：接受，现在不要求降到 45 万。** 没有手机量过就砍建筑细节，是在没有数据的情况下动画面。结构线和 #72 的新增在低档必须靠 LOD 或关闭抵消（第四节第 2 条的规则保留）。手机实测另行安排，量过以后再定低档的数字。
3. **p95 以 tour 第 2、3 趟里较差的一趟为准（现在是第 2 趟的 22.0 ms）；第 1 趟单独报告，不作判定。** 第 1 趟（p95 25.0 ms，最长一帧 141.4 ms）是载入后的编译和上传，属于冷启动，玩家每次访问只遇到一次。第 1 趟的最长一帧记下来作基线（141.4 ms），以后不许明显变长。

## 六、没有验的

- 手机真机：没有测。
- 重复性：高档一次 Job，没有取多次平均，也没有换 Job 实例比较机器差异。
- 每项 `?off=` 各测一次；`cost` 是 `__cost(40)` 的 40 帧平均。
- 殿内帧耗没有测（本次只测首院和 cam06）。
