# 第三人称里他在画面中的位置（#271）：量、两套方案、B 定为默认

**结论**：所有者和用户要「行走时人在正中间」，主创 2026-11-19 定 **B 为默认**：横向居中，他的中心在画面高度的 58%（主创给的范围 55–62%）；被挡只拉近、不左右挪；台阶上镜头的俯仰随他修正，全身在框内。A（过肩）留在 `?frame=a` 对照，改前的镜头留在 `?frame=old`。

## 一、怎么量

- **页面**：`tools/frame-measure.cjs` 在真页面里（软件渲染，场景建好不画，`BARE`）按键走路、拖鼠标转镜头，每帧读 `__probe().monkBox`（通过 `__frame()` 读同一个框，不多画一帧），记他中心的横坐标、纵坐标（占画面宽、高的百分比），框的上沿、下沿（脚在不在框内）。软件渲染每秒约 3 帧，一条路几分钟。
- **Node**：`tools/frame-routes.mjs` 用同一份平面、walker、`eye.js`，每秒 60 帧算同样的数，几秒出全表；两边对得上（院心直走，16:9 改前：页面 36.3%（28.4–37.7），Node 36.8%（29.3–37.9））。改前的数是在 main（`11496b1`）的检出里跑同一个工具得的。
- **六条路线**，夏日白天，镜头俯仰 0.06：
  - 院心直走：x = 5，z 32 → 18，朝北。
  - 绕香炉：以（0, 13）为心、半径 2.6 m 走一圈，镜头跟着转。
  - 贴柱列：禅堂廊前柱列在右手边约 0.6 m，x = 12.25，z 24 → 7（中间横穿禅堂台阶脚下）。
  - 贴白墙：东院墙在右手边约 0.7 m，x = 21.3，z 33 → 9（后半段在禅堂背后的夹道里）。
  - 台阶上行 / 下行：进山路上半山亭旁那段（z = 77.5，x 19.5 ↔ 10，亭在左前方，和用户截图同一处），再接上 x = 0 那段台阶到 z = 63.5；下行反过来。

**页面里量的改前**（`__probe().monkBox`）：16:9 院心直走 36.3%（28.4–37.7）；绕香炉 38.6%（27.4–50.0），最快 15.2%/s；4:3 绕香炉 35.2%（22.5–49.0），33.2%/s；**竖屏院心直走 9.0%（−14.5–13.2），绕香炉 29.8%（−11.9–50.4），60.7%/s**。小于 0 是人已经在画面左边外面。

**读出来的：**

1. **偏左是旧设计，竖屏上偏出画面。** 旧镜头站在他右边 1.2 m、后面 6.2 m，偏置按米定：横屏是 11° 的过肩（37%），竖屏画面横向窄，同样 11° 就到了 10%，一拉近就出画。
2. **不稳来自侧移。** 旧代码一发现右手 1.4 m 内是墙就把侧移拉到 0（贴墙 50%、离开 37%，绕香炉时香炉一进来就跳），被挡拉近时侧移米数不变而角度变大（贴柱列每秒 48–144%）。
3. **台阶下行人被切掉**（用户截图那种）：改前下行时他的中心平均落在画面高度的 155%，只有约三分之一的帧看得到他的脚。原因是眼睛在他身后的高处（上坡一侧，还为看清台阶边被抬高），镜头却照访客的俯仰平视，人落到画面底下。

## 三、B 怎么做的（默认）

同一个机制，也就是 #161 第 5 步要做的「弹簧臂」：

- **一根直臂。** 眼睛站在一根从他头顶附近（脚上 1.3 m）伸出的直臂上，臂的方向相对镜头朝向固定（`frameArm(frame, fov, aspect)` 按当时视角和画幅现算）。被挡**只缩短臂**，不再侧移、不再甩到他身后。所以「他在画面的哪里」按画面比例定，不按米：竖屏和横屏一样在正中。
- **俯仰随他修正（`aimAt`）。** 每帧在眼睛定下以后，按「他的中心落在画面高度 58%」算出镜头该俯多少：开阔处等于访客自己的俯仰（臂已经让他落在那里），台阶上眼睛高于或低于他时自动多俯或少俯。这就是 Cinemachine 在 Follow 之后接一个 Rotation Composer 的做法；业界说的「看点随地形抬高或压低、俯角随坡度修正」，这里由「始终看着他」直接得到，不另设坡度表。访客拖动俯仰时臂绕他转（往下拖，眼睛升高往下看他），他在画面里的位置不变。
- **走过香炉一类东西时：臂横移让位，镜头水平也看着他（主创评审 #291 后加）。** 只缩臂时，香炉从侧面切进他和眼睛之间，眼睛只能沿臂往前拉，就得穿过香炉，结果一帧里被推出 1.4 m（山门门洞那条 1.5 m）。所有者的硬要求是眼睛不许一帧内跳，所以：臂被「一个东西」挡住、要拉近 1.5 m 以上、而横移能完全绕开时，整根臂绕他头顶那一点转开（臂伸满时眼睛往左或往右 0.3–1.5 m，取最小能绕开的再多让 0.3 m；起初做成整根臂平移，网格版的扫掠单测抓到「头到臂起点」那一段没人检查、在半山亭穿过柱子，于是改成转），走弹簧（`FOLLOW.slideTime` 0.15 秒、`slideSpeed` 每秒最多 5 m），绕过以后慢慢回到正后方（`slideBack` 1.2 秒）。墙、坡面不绕，照旧拉近。横移期间镜头的水平朝向跟着转（`aimAt`，水平方向的 Composer），他仍在画面正中：页面里实测横向 49.8–50%，只是视角跟着转了几度。
- **臂的起点为什么是 1.3 m**：正常距离时眼睛离他脚面的高度由构图决定（约 0.7–1.1 m，随俯仰），起点只影响靠近他那一段的斜度。起点低于台基栏杆顶（1.29 m）时，他背靠栏杆站，臂会擦过栏杆顶（`sweeps` 单测抓到的一处）；1.3 m 刚好越过。
- **两处旧规则的修正（改到了 `site.js` 的 `eyeShut`，旧镜头也受益）**：殿前台阶的「实体」框和两侧栏板，对眼睛原来一律按「脚上 5.5 m / 地面上 1.1 m 以内都挡」，比台阶本身高得多（禅堂台基才 0.45 m）。旧镜头偏在右边绕过去了，正对着的臂就被挡、被收进他身体（贴柱列那条路有四分之一的帧看不到他）。现在台阶实体和栏板带上台基高度（`building.js` 给 `h: platH`），眼睛只在台阶顶以上 0.3 m 内被挡。臂另外还避开台基栏杆 0.25 m（`railNear`，和观礼镜头的避让一样）。

## 四、A（`?frame=a`，对照）

他的中心固定在画面宽度 37.5%、高度 60.5%（改前 16:9 开阔处的位置），三种画幅一致，竖屏不再出画。代价：**右肩一侧贴墙时站不住**。纯粹「偏置不变、只拉近」在贴白墙那条路上整程把眼睛收进他身体里（右边 0.7 m 就是墙）。所以 A 照 Cinemachine Third Person Follow：右边被挡时先把臂的侧倾收回，再拉近，收回和放开用 1.2 秒的弹簧（`FOLLOW.leanTime`）。结果开阔处稳了，贴右侧墙时他慢慢回到正中（每秒约 4–5%，超过验收的 2%）。这是过肩构图的几何，不是参数没调好。

## 五、前面的路看不看得见

- **B**：他站在路的正中，中心在 58%，挡住的是脚前最近的一段路面（6.2 m 外他只占画面高度约五分之一）。访客俯仰 3°（向上）时地平线在画面高度约 63%，和他腰腿同高，所以**正前方最远处那一点在他身后**，两边的路、门洞的上半、殿的屋顶都露出来；想看正前方远处，往下拖一点（眼睛升高），他就落到消失点下面。台阶上因为俯仰跟着他修正，上行时前方台阶在他头顶以上露出，下行时脚下的台阶和前方的路都在框内。
- **改前 / A**：横屏上他在左三分之一，正前方的路完全露出；但改前在竖屏上常常「路看得见、人看不见」。
- 六个锁定机位是第一人称，不受影响；视场角、距离、第一人称都没改。

## 七、二阶影响

- **别的模块**：观礼机位（`director.js`）和开场镜头的终点都从「当时的跟随眼」出发，起点变了；`director`、`opening` 的单测照跑通过。`followEye` 不传 `arm` 时默认就是 B（`DEFAULT_ARM`，16:9、50°），所以 `follow/eaves/sweeps/director/plaques/eye-edge/censer` 这些拿 `followEye` 测的单测现在测的都是新默认；`plaques` 单测里跟随眼改成和页面一样不低于地面（原来它取的点会落到地下 4 m）。
- **走路的格子**：`walk.solids`、`walk.posts` 多了 `top`/`eyeTop` 两个字段（只给眼睛用，挡脚的矩形没变），烘焙的指纹会变、重新烘一次，可走的地不变。
- **玩家**：所有第三人称画面的构图变了（宣发、商店页里第三人称的图要按新构图重出）；存档、分享地址不受影响；`?frame=old` 能看回旧的。
- **第 5 步**：球形扫掠只是把「沿臂每 0.125 m 问一个点」换成「沿这根臂扫一个球」，`kx/ky`、缩臂、`aimAt` 原样并进去。
- **维护**：旧的侧移代码（`side`、`walker.wall` 那一段）仍在，供 `?frame=old`；选定稳定后（主创在预览里走过、所有者线上看过）可以删掉，连同 `?frame=old`。

## 九、怎么看、怎么复现

- 预览：PR 预览地址，不带参数是 B；`?frame=a` 是 A，`?frame=old` 是改前。`__frame()` 报当前用哪套、臂长和他的框。
- 数：`node tools/frame-routes.mjs`（Node，几秒）；`node tools/frame-measure.cjs [--frame=old,b] [--walk=stair-down]`（页面）。
- 图：`node tools/frame-views.cjs`（三种画幅 × 六条路线 × 六个点，`--frame=old,a,b`），`python3 tools/frame-sheet.py <dir>` 拼成对照表（每行一套，红十字是他的中心，白线是三分线）。证据在 Hugging Face 数据集，见 `docs/t00/evidence/271-frame/`。
- 单测：`tests/unit/follow.test.mjs` 末尾：「the default eye never jumps」两条（从香炉正后方往北走过香炉、从门前斜着走进山门门洞），每帧眼睛自己的位移（含被推出）不超过 0.15 m——在修之前的提交上会失败（1.40 m、1.50 m）；原有的「the eye does not jump」四条路线改为测默认的 B（之前 `walk()` 默认传 `arm: null`，测的是旧镜头）；A、B 各三种画幅横向偏离 < 1%；默认（B）在开阔处横向范围 ≤ 3%、各处每秒变化 ≤ 2%、横向均值在 50 ± 1.5%、台阶上下行脚和膝都在框内、不被藏。B 沿 follow.test 的四条路线没有一帧被推出。
- 不在范围：用户截图里横在他头顶上方的一行英文提示（另记）。
