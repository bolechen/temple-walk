## 配乐 Goal（2026-11-15 用户点头，已接入游戏，待试听）

目标：音乐有可辨认主题和段落，随探索自然发展，支持寺院空间与停留；不只是持续底噪和零散钟声。

1. 先交T00一个完整3–5分钟竖切体验：竹林接近→山门揭示→院落停留→入殿→回望。配一个6–8音短主题，用编配和留白变化，不在每段机械重复。
2. 音色方向：少量高质量拨弦、木质/气息类主奏和轻薄和声。先用两版60–90秒样片比较；不以正弦波随机音序或冥想垫底替代成曲。主观听感需要真实试听，自动测试不能宣布“好听”。
3. 音乐、环境声、交互音效分层。步入/离开区域稳定约2秒后才切换状态，约4–8秒平滑过渡；边界往返不反复重启。敲钟等关键交互让音乐短暂退后，恢复自然。
4. 完整走访10分钟检查无明显拼接、爆音、突然静音或刺耳重复；音乐不能盖过钟声、脚步和关键提示。音量须实机试听，响度/峰值报告只能辅助。
5. 音乐与环境/音效可分别调节和静音，偏好保存；尊重浏览器首次交互播放与后台暂停/恢复。切换场景不叠播多个音乐实例。
6. 交付母带、可用循环/分轨、曲目与场景映射、授权来源、实机含声音录像及剩余问题。验收按音乐完整度、场景贴合、过渡、疲劳感、混音五项听评；技术通过不等于审美通过。

用户 2026-11-15 认可「七印集主题」结构和合成路线，要求子代理评审后直接接入游戏（跳过两版样片对比）。实现见 `app/src/score.js`（乐谱即数据）、`instruments.js`（琴、泛音、箫、和声垫）、`audio.js`（三条总线、室内外两套混响、钟鼓让位、后台暂停）。
`node tools/music.mjs` 把同一份谱沿十分钟模拟走访离线渲染成 MP3，并给出峰值、削波、响度曲线、静默段、乐句记录和各音色实测音高。
**还没有人听过**：自动测试只证明不叠播、不削波、音准对、切换按规则发生，不证明好听。第 1 条的「两版样片」没有做；第 6 条的实机含声音录像要用户来录。

## 2026-11-16 用户需求（按提出先后）

以下是用户提出的需求和评审交接，不是完成证明；是否已在线以实时JSON和完整SHA为准。

1. **玩法与文案打磨。** 山顶静坐任何时候都给，第一次完成就播序章结尾，不论集了几印；看过与否存进朱印帐（旧存档兼容）。撞钟一按一下，钟槌荡回来前拉不动。吃茶三口后他坐着不走，按「起身」才走。帖文、七印短句、提示按具体的人、器物、动作改写，传说标「相传」。实现：#52、#58。
2. **换季可再看结尾，香会烧完。** 换了季节后序章结尾可再播（每季一次）；上香后三支香往下烧，默认 5 分钟烧完，烧完可再上香。实现：#68。
3. **观礼自动转场。** 每个有动画的打卡点，自动切到最合适的机位播放，播完回到玩家视角；切换用墨色帷幕，提示行保留，地上的圈在镜头里隐去。目标和验收：https://github.com/bolechen/temple-walk/issues/71 ；实现 PR #87，所有者评审时只有燃灯一镜通过，其余须重新构图。
4. **评审直达。** 本地 dev 和 PR 预览默认打开调试面板（`?debug=0` 关）；`?seals=`（临时朱印帐，不读写本机存档）、`?at=`（站到打卡点）、`?play=ending|<仪式>`（直接播结尾或开始仪式），预览评论里有一行直达链接。正式站忽略这些参数。用直达参数看到的效果属诊断证据，不能代替正常游玩的录像。
5. **按《营造法式》修改木构。** 目标：`docs/t00/structure-goal.md`（四个阶段），评审：`docs/t00/structure-review.md`。所有者在第三阶段定了两条：山门上层与下层同深；凌霄阁保持体量，只对二层角柱（其余记为与法式不合的偏差）。结尾镜头最后一格阁顶离画面上沿至少约 8%。结构这条线新增几何合计让首院高档单帧多出不超过 1 毫秒（T4）。
6. **向美术原型靠拢。** 目标：`docs/t00/art-goal.md`、`art-targets.md`，issue #72；原型在 `refs/art-prototype-2026-11-16/`，机位 `art1`–`art6`。原型只管光和色调，建筑以法式为准（`structure-goal.md`「2026-11-16 调整」）。
