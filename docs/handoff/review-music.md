# 音乐与声音评审：交接（2026-11-19）

写给接任的音乐评审会话。你只需要读这份、[`docs/t00/MUSIC.md`](../t00/MUSIC.md)、[`AGENTS.md`](../../AGENTS.md)、
[`CLAUDE.md`](../../CLAUDE.md)。配乐的结构、每处听到什么、乐器怎么做，都在 `MUSIC.md` 里，这里不重抄。本页只写那里没有的：

## 一、职责和标准

**范围**（所有者 2026-11-16 定）：音乐、配乐，加上音效和山声（钟、鼓、磬、脚步、鸟、风、滴水、井、檐铃、竹竿相碰、拍照声、投币）。
主创派来的声音活直接接，不用再问所有者（所有者 2026-11-17：「后续主创派你的活，不用我确认，全部接」）。
评审结论写在对应 PR / issue 的评论里，再 `send_message` 给主创。合并要所有者或主创一句话，自己不合。

**作曲怎么判**（按这个顺序）：
1. 先合不合「画面精美庄严」和《小王子》那种安静、可以停留的气质。宁可少，不可满；留白是作品的一部分。
2. 全部合成，不用录音、不用采样、不用第三方曲库（2026-11-16 评过研究站点给的三首 Pixabay AI 曲目：授权上有 Content ID 和 AI 权属两个隐患，
   成品立体声没法跟着地点变，调也和大钟的 G 羽不合，结论是不用，只作听评对照）。
3. 一切建在大钟 98 Hz 的 G 羽（G B♭ C D F）上。新加的有音高的东西（檐铃、磬、远钟、标题音）都要在这个调式里，否则一撞钟就打架。
4. 新加声音要先想**会和什么同时响**：钟（约 45 秒）、得印的磬、换场时的淡出、结尾的远钟。2026-11-17 序章标题那声 D 和山门第一句撞车，就是没想到这一层。

**评审怎么判**：
- 「对不对得上」先查**时钟和触发条件**，最后才调音量（见五、踩过的坑第 1 条）。
- 每条结论给数：多少 dB、几秒、在哪些情况下不响。不给「略大」「稍响」这种话。
- 一个声音什么情况下**一定不响**，和它什么时候响一样重要：殿内、冬天（雪）、夜里、雨后湿的时候、开场镜头期间、拍照冻结时。

**响度基准**（都是页面里的相对量，在无头 Chromium 里测的）：

| 什么 | 量 | 说明 |
|---|---|---|
| 配乐总线 | 平均约 −31 dB RMS（在 `audio.js` 里实测） | `MUSIC.md` 里 2026-11-15 的「约 −36」是离线渲染的总线，口径不同 |
| 竹林风 | 约 −32 dB RMS | 2026-11-16 降过约 5 dB（#69），让配乐和脚步在竹林里也听得见 |
| 石面一步脚步 | 最响的 60 毫秒约 −57 dBFS | 「若隐若现」，比配乐平均低约 26 dB；`steps.test.mjs` 守在 −52..−60 |
| 雪地一步 | 约 −53 dBFS | 四种脚步的次序：干石 < 湿石 < 水洼 < 雪 |
| 撞钟 | 最高约 −11 dB | 配乐降到 18%，14 秒后回来；同时最多三声在响 |
| 远钟（结尾） | 低通 650 Hz、0.32 | 结尾配乐在那一刻本来只留和声，不再另压 |
| 新加的「若隐若现」量级 | 比石面脚步再低 10 dB 以上，即约 −67 dBFS | 到这个量手机上基本听不见，做了等于没做，见三、第 1 条 |

## 四、常用工具和怎么出样片

```bash
node tools/music.mjs summer-day
```
默认模拟路线约 11.5 分钟，输出到 `tools/out/music/`，见 `MUSIC.md`。
- `MUSIC_WALK='[["stair",25],["gate",25]]'` 换路线；`MUSIC_QUICK=1` 不出分轨，也不在页面里测各总线的响度。
- `MUSIC_OUT=<目录>` 换输出目录。
- 和研究站点那样的 90 秒对照：用 `MUSIC_WALK` 排 15/25/25/25 秒，再用 `ffmpeg -af loudnorm=I=-20:TP=-2` 统一响度。

```bash
node tools/steps.mjs
```
四段脚步（干石、雨后、雪、殿内），比页面里响三倍，方便单独听。它的步频是估算的（约每秒 2 步），不是 `monk.js` 的真步频。

**页面里的探针**（`?debug` 或测试里）：
- `__music(true)` 开声并报告：分区、段落、乐句数、让位、各级音量。
- `__listen("music"|"ambience"|"effects")` 某条总线此刻的 RMS 和峰值。要在**同一次 evaluate 里**先发声、忙等几十毫秒再听（参考 e2e `sound` 场景的写法），分两次调用会因为帧慢而听空。
- `__cues()` 远钟、山钟、标题、终章、跳过各响了几次；`__steps(kind)` 各种脚步响了几次，或者现在响一步。
- `__knock()` 环境声的状态（#281 起报 `gust`、`gustT`）；`__bells()` 钟；`__well()` 龙井；`__shots()` 快门。
- `__ending()` 重播结尾；`__prologue(true)` 立刻出序章标题。

**出一段样片的做法**：结尾、开场、台阶脚步这类配合画面时间线的样片，
`tools/music.mjs` 走不出来。做法是写一个临时脚本，起一个本地服务器，让 `app/src/` 里的 `score.js`、`instruments.js` 在
Playwright 的 `OfflineAudioContext` 里按时间线排音，可以直接调 `bell()`、`hillEcho()`、`createPlayer()`、`makePhrase()`、
`endingPhrase()`、`titlePhrase()`，导出 PCM，再用 ffmpeg 转 mp3 并统一到 −20 LUFS。参照 `tools/music.mjs` 的写法即可。
样片放 `tools/out/<名字>/`（已在 gitignore 里），用 `SendUserFile` 发给所有者，并写清每一秒发生了什么。
先出样片、听过再接进游戏，这是所有者一贯要求的顺序。

## 五、踩过的坑

1. **对不上先查时钟。** 环境声原来用自己的计数（从第一次点按才开始，后台时停住），画面用帧时钟，两边差几十秒（#281）。新加任何「跟着画面起落」的声音，都从 `place().t` 取时间。
2. **两个触发器撞车。** 序章标题的 D 和山门第一句各自触发，先后响了两个 D，中间隔约 7 秒。样片里能听出来，单元测试测不出来。还有一层：玩家绕过照壁要几秒，配乐常在标题出来**之前**就进了山门那段、把第一句奏掉了，所以要 `awaitTitle` 把山门第一句留给标题。只看代码会漏，在页面里走一遍（`opening` 场景）才看得出。
3. **`hush` 和 `duck` 互相覆盖。** 撞钟让位期间如果他坐下喝茶（`hush`），以前会把让位的回升冲掉。`hush` 现在只改让位结束后回到哪一级，见 `audio.js`。
4. **e2e 里的声音断言要放宽门槛。** 脚步降音量后，`steps`、`snow` 场景里「有没有出声」的 RMS 门槛要跟着降（静音时是 0，门槛只要大于 0）。降音量时记得改。
5. **e2e 里要先开声。** 环境声和配乐只在第一次点按后才开始，测之前先调 `__music(true)`，再等 0.8 秒让环境声的定时器跑几次。
6. **冻结画面时帧数不动。** 拍照冻结时 `t.frames(n)` 会一直等，这时要按秒等。
7. **`?shot` 和「减少动态」时画面的 `t` 恒为 0。** 声音不跟着停，照常往下走。
8. **本机 `pnpm test` 里 `notices` 失败**多半是缺授权文件：跑一次 `node tools/setup.mjs --force`。main 加了新依赖时，`pnpm build` 会报找不到包（例如 `three-mesh-bvh`），先 `pnpm install`。
9. **流程上：** 每个看得见、听得见的改动，同一个提交里改 `docs/t00/SOURCES.md` 那一行；同步 `docs/t00/delivery.json`；`CLAUDE.md` 的 Sound 段落要跟上。不要把推断写成出处。
