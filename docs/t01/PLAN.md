# T01 白盒与开工计划

核对日期：2026-11-17。本文只写到「第一版白盒能走通、能看图、能量帧」为止。精模、NPC、登塔、全城都不在第一版。

---

## 1. 第一版做什么、不做什么

### 做

- 五区白盒：街边门口（A）、池桥与首院（B）、台阶与殿侧（C）、林下折路（D）、看塔与回望（E）。
- 七重台地与主要殿宇的体块（山门、钟鼓楼、弥勒殿、大雄宝殿、玉佛殿、万佛殿、罗汉堂/法界宫、塔）。
- 一条可走通的路线，键盘 + 触摸。
- 塔的三次露出（设计）。
- 六个候选机位。
- 城市背景的低多边形体块与雾。
- 菜薹田、摩崖石、古树的简化体。
- 五段声场的合成层（可先做 Z1/Z3/Z5）。

### 不做

- 塔内、登塔。
- 五百罗汉、万尊金佛的精模。
- 全寺所有配殿/僧寮的室内。
- 整座武汉街区、长江、黄鹤楼。
- 多人、NPC、对话树。
- 七印/朱印体系（第一版用「便笺三处观察」的轻记录）。
- 四季四时的全部 16 种（先做基准 + 1 备选）。
- Steam/桌面外壳。

## 2. 白盒的五个节点与验收

| 节点 | 位置 | 必须能做的事 | 验收 |
|---|---|---|---|
| A 街边门口 | 山门外 20–30 m | 从城市界面进入；拿到便笺（可不读）；走到山门 | 能从街边走到山门，不卡；街声还在 |
| B 池桥与首院 | 山门内 | 绕过放生池、过圣僧桥、看钟鼓楼；第一次见塔 | 桥能走；塔露出；钟鼓楼可看 |
| C 台阶与殿侧 | 弥勒殿—大雄宝殿—玉佛殿 | 上台阶、看两处修补、记一条（可选） | 台阶可走；不穿墙；殿门可进/可看 |
| D 林下折路 | 玉佛殿—万佛殿—罗汉堂，或西侧环山 | 沿路看到 3–5 块摩崖；听声场变化 | 不靠箭头能找路；不迷路到不可达区域 |
| E 看塔与回望 | 罗汉堂—塔院—塔影田 | 看塔、站住、回望城市、结束 | 塔完整出现；回望见城市；可随时结束 |

### 2.1 总体验收

- [ ] 从 A 到 E 全程可走，无卡死、无穿模、无掉出。
- [ ] 键盘（WASD/Shift/E/Space）与触摸（摇杆/点地/跳/交互）都能完成。
- [ ] 三处观察都可跳过，不集齐也能到 E 并结束。
- [ ] 塔的三次露出成立（局部—遮住—完整）。
- [ ] 六个候选机位都能站人、能取景。
- [ ] 城市背景压住高度（一线 ≤40 m、二线 ≤60 m）。
- [ ] 无页面错误、控制台错误、失败请求。
- [ ] 单测：从第一步洪水填充能走到每个命名地点。
- [ ] `pnpm run edges` 0 处超限；`nearplane` 无切割。
- [ ] `mobile-audit` 无 <44 px 控件、<12 px 文字、越界。
- [ ] T4 上量一次帧耗，记录在 `docs/t01/`（不是 T00 的数字）。

## 3. 白盒的技术路线

### 3.1 先分关卡，再写内容

T00 的平面与关卡数据还写在引擎里，拆分是 #138（T00 发布后做）。T01 不要重复这个错误：

- `app/levels/t01/`：平面、建筑参数、views、places、locales、gallery、boards。
- `app/shared/`：引擎、材质、行走、镜头、音频、界面。
- 若 #138 还没做完，先在 `app/src/site.js` 里加一个 `T01` 分支，但**把数据放在 `app/levels/t01/site-t01.js`**，不要散在引擎里。

### 3.2 建筑

- 第一版：`buildHall` 加 `style: "qing-wuhan"` 参数；先做体块 + 屋顶剪影。
- 塔：新 `buildPagoda`，八角七层，底径 12 m，顶径 4 m，高 45 m。
- 法界宫：新 `buildMizongHall`，19×16 m，五亭顶。
- 山门：`buildGate` 或 `buildHall` 的 `gate: true`，20×10 m，中门 + 两侧门。
- 钟鼓楼：`buildHall` 的 `tower: true`，三层，10.8×10.8 m。

### 3.3 地面与可走性

- 七块台地：`put` 的 `level` 0–6，`baseY` 按 `SITE.md` 的提案（0、1.5、4.5、9、16、25、30）。
- 每段台阶：`stairGeo(w, rise, {sides})`；级高 0.16–0.18 m，踏面 0.30–0.34 m。
- 台地边缘：挡墙/栏杆，不做 `drops`。
- 放生池：水面不可走，桥可走；桥栏杆是 `posts`。
- 菜薹田：田埂可走，田里不可走（或可走但减速；第一版不可走）。
- 摩崖：石头是 `posts`/`solids`，前面留 1.5–2 m 可站带。

### 3.4 镜头

- 第一版用 T00 的第三人称跟随 + 第一人称；不做新的镜头系统。
- 六个机位用 `views` + `shots.js`；`?show=cam01` 等。
- 塔的七层檐进 `walk.roofs`，否则跟随镜头会穿塔。

### 3.5 城市背景

- 低多边形体块：武珞路沿线的商场、医院、住宅、地铁口；不建整条街。
- 高度控制：一线 ≤40 m、二线 ≤60 m（相对 1985 高程）；用雾与树冠遮挡硬边。
- 远景：一层城市剪影 + 天空；不做黄鹤楼/长江（太远，容易假）。
- 声音：城市低频 + 车流，进门后衰减。

### 3.6 季节

- 第一版只做基准（冬晴或秋末雨后）+ 一个备选。
- `moodOf` 新增字段：`cityHaze`（城市雾）、`field`（菜薹状态）、`wallWet`（黄墙湿痕）。
- 不做 16 种；等基准定了再扩。

## 4. 性能预算（草案，必须实测）

T00 的数字（T4，1080p）：

- 首院高档 9.3 ms，低档 4.7 ms；屋顶是三角形大头；绘制次数比像素更紧。
- `?tour=120x3` 高档平均 61 fps，95th 21 ms。

T01 的体量估计：

| 项 | 估计 | 依据 |
|---|---|---|
| 建筑三角形 | 80–120 万 | 七重殿宇 + 塔 + 五亭顶；比 T00 多 |
| 树 | 20–40 万 | 36 株古树 + 林下；用 instanced/低模 |
| 城市背景 | 5–15 万 | 低多边形体块 |
| 菜薹田 | 5–10 万 | 实例化小植株 |
| 摩崖/石 | 2–5 万 | 8 块巨石 |
| 总三角形 | 110–190 万 | 高于 T00 的 110 万 |
| 绘制次数 | 250–400 | 需合批；塔/五亭顶/城市可能各占一批 |

**目标**：高档 1080p ≤12 ms，低档手机尺寸 ≤6 ms。达不到就砍：先砍树的数量、城市细节、万佛壁；不要先砍塔与五亭顶。

**量法**：同一个 GPU job 里比差值；报告带站点指纹；不用软件渲染的数字外推。

## 6. 风险

| 风险 | 影响 | 应对 |
|---|---|---|
| 没有现场测绘 | 殿宇比例、塔的收分可能错 | 白盒先按 OSM/SRTM；精模前现场补测 |
| 建筑词汇与 T00 不同 | `buildHall` 要大改 | 先做 `style` 参数与体块，不追求一次到位 |
| 城市背景容易假 | 画面像贴片 | 低多边形 + 雾 + 树冠遮挡；不做整条街 |
| 塔的七层檐穿镜头 | 第三人称穿模 | 全部进 `walk.roofs`；`eaves`/`sweeps` 测试 |
| 菜薹田不可走 | 玩家踩进田里 | 田埂可走、田里挡；或允许走但减速 |
| 五亭顶比例难 | 法界宫认不出 | 先做剪影，再从四角/俯视看图 |
| 季节与 T00 重复 | 像同一座寺 | 基准选冬晴/秋末，不用夏昼 |
| 素材授权 | Commons CC BY-SA / 书法 | 只作参考；进游戏前逐张核 |
| 性能 | 三角形/绘制次数超标 | 先砍树/城市/万佛壁，不砍塔 |
