# T04 白盒与开工计划

核对日期：2026-11-17。本文只写到「第一版白盒能走通、能看图、能量帧」为止。精模、NPC、登塔、全城都不在第一版。

---

## 1. 第一版做什么、不做什么

### 做

- 六段白盒：前院、门口适应区、巨像近侧、侧向观察、经卷展柜、院外远景。[S00]
- 一座大佛殿：48.3×24.5×20.2 米的体块、重檐歇山、门/砖雕、佛坛、侧廊。
- 一尊原创卧佛：34.5 米，头北脚南、面西；先用灰盒/低模，不做精模。
- 31 尊群像：卧佛+10 弟子+2 胁侍+18 罗汉；用 3–4 个变体 + 实例化。
- 530 m² 壁画：先做 4 组烘焙纹理占位，不做逐笔。
- 藏经阁（21.3×10.5 米）+ 经橱/展柜/经卷占位。
- 土塔（33.37 米、23 米基座、13 层、36 风铎）体块。
- 山门、钟楼、鼓楼、配殿/厢房体块；广场/城市低层背景。
- 一条可走通的路线（键盘 + 触摸）；六个机位；Z01 侧向天光。
- 六段声场的合成层（可先做 Z1/Z3/Z5/Z6）。
- 「长照札记」六格 + 3–5 条安静观察（可跳过）。

### 不做

- 卧佛/31 尊/壁画的精模（第一版只做灰盒/低模/占位）。
- 佛肚/装藏/夹壁的内部空间（不做可进入）。
- 开经柜/取经/取宝/功德值。
- 登土塔/进地宫。
- 全寺所有配殿的室内。
- 整座张掖城/祁连山/沙漠远景。
- 多人、NPC、对话树。
- 七印/朱印体系（T04 用长照札记）。
- 四季四时的全部 16 种（先做基准 + 1 变体）。
- Steam/桌面外壳。

### 2.1 总体验收

- [ ] 从 A 到 F 全程可走，无卡死、无穿模、无掉出。
- [ ] 键盘（WASD/Shift/E/Space）与触摸（摇杆/点地/跳/交互）都能完成。
- [ ] 门口只看到局部；侧廊才看到全长；六个机位都能站人/取景。
- [ ] 佛首/佛脚两端都能看到 34.5 米全长，头/脚不被切。
- [ ] 经卷展柜不开柜、不取经；没有「宝库/开箱」反馈。
- [ ] 土塔/地宫不可进入；没有登塔。
- [ ] 城市背景低层；土塔在屋顶上；没有群山/沙丘替代。
- [ ] 无页面错误、控制台错误、失败请求。
- [ ] 单测：从第一步洪水填充能走到每个命名地点。
- [ ] `pnpm run edges` 0 处超限；`nearplane` 无切割。
- [ ] `mobile-audit` 无 <44 px 控件、<12 px 文字、越界。
- [ ] T4 上量一次帧耗，记录在 `docs/t04/`（不是 T00/T01 的数字）。

## 3. 白盒的技术路线

### 3.1 先分关卡，再写内容

T00 的平面与关卡数据还写在引擎里，拆分是 #138（T00 发布后做）。T04 不要重复这个错误：

- `app/levels/t04/`：平面、建筑参数、views、places、locales、gallery、boards。
- `app/shared/`：引擎、材质、行走、镜头、音频、界面。
- 若 #138 还没做完，先在 `app/src/site.js` 里加一个 `T04` 分支，但**把数据放在 `app/levels/t04/site-t04.js`**，不要散在引擎里。

### 3.2 建筑

- 第一版：`buildHall` 加 `style: "hexi-qing"` 参数；先做体块 + 屋顶剪影。
- 大佛殿：48.3×24.5×20.2 米，九间/七间，重檐歇山；台基 1.2 米；门 3.6 米；佛坛 1.2 米；侧廊 2.5–3.5 米。
- 土塔：新 `buildStupa`，23×23 米基座、33.37 米、13 层、36 风铎。
- 藏经阁：21.3×10.5 米，单檐歇山；经橱/展柜。
- 山门：11.7×7.8 米，三间；钟鼓楼：6.9×6.6 米，二层。
- 城市背景：低多边形广场/博物馆/小学/饭店/住宅；不做整条街。

### 3.3 地面与可走性

- 六段 `level`/`baseY`：广场 −0.3、山门 0、前院 0.4、殿台 1.2、藏经阁 1.0、土塔院 0.9。
- 每段台阶：`stairGeo(w, rise, {sides})`；级高 0.16–0.18 米，踏面 0.30–0.34 米。
- 台基边缘：挡墙/栏杆，不做 `drops`。
- 佛坛/佛像/31 尊/经橱/土塔：solids/posts；侧廊留 0.5 米安全距离。
- 土塔：整体 solid；周围 2.5–3 米环道；不登塔/不进地宫。

### 3.4 镜头

- 第一版用 T00 的第三人称跟随 + 第一人称；不做新的镜头系统。
- 六个机位用 `views` + `shots.js`；`?show=cam01` 等。
- 大佛殿重檐/土塔 13 层进 `walk.roofs`，否则跟随镜头会穿。
- 室内侧廊的 `nearplane` 要单独测：34.5 米的长空间 + 近墙，容易切。

### 3.5 城市背景

- 低多边形体块：广场、张掖市博物馆、小学、饭店、住宅；不建整条街。
- 高度控制：低层（2–6 层），不要玻璃幕墙/高层；用树冠/雾遮硬边。
- 远景：土塔 + 低层城市 + 天空；不做祁连山主峰/沙漠。
- 声音：城市低频 + 车流，进门后衰减。

### 3.6 季节

- 第一版只做基准（秋末西晒 16:00–17:30）+ 一个备选（冬雪）。
- `moodOf` 新增字段：`dust`（尘）、`earthWet`（墙脚返潮）、`sunAzimuth`（西晒）、`cityHaze`（城市干雾）。
- 不做 16 种；等基准定了再扩。

## 4. 性能预算（草案，必须实测）

T00/T01 的数字（T4，1080p）不能外推到 T04；T04 没有 GPU 测量。下面是**设计预算**，不是实测。

### 4.1 三角形/绘制次数

| 项 | 估计三角形 | 估计绘制次数 | 依据 |
|---|---:|---:|---|
| 大佛殿建筑（含重檐/门/砖雕/柱网） | 150–250 k | 60–100 | 九间/七间、重檐、厚墙 |
| 卧佛（原创，LOD） | 60–120 k | 2–4 | 34.5 米；面部/手部单独 LOD |
| 31 尊群像 | 200–350 k | 15–30 | 31 × 6–10 k；3–4 变体+实例化 |
| 壁画（4 组纹理/墙面） | 20–40 k | 8–16 | 530 m²，烘焙纹理；不做逐笔 |
| 佛坛/供桌/香炉/长明灯 | 10–20 k | 6–12 | — |
| 藏经阁+经橱/展柜/经卷 | 30–60 k | 10–20 | 21.3×10.5 米 |
| 土塔（13 层+36 风铎） | 30–60 k | 4–8 | 风铎实例化 |
| 山门/钟鼓楼/配殿 | 80–150 k | 30–60 | 体块+屋顶 |
| 广场/城市背景 | 80–150 k | 30–60 | 低多边形 |
| **合计** | **660 k–1.2 M** | **165–310** | 高于 T00 的 1.1 M 上限附近 |

**目标**：高档 1080p ≤12 ms，低档手机尺寸 ≤6 ms。达不到就砍：先砍城市背景、配殿、十八罗汉数量（用 impostor/8 尊+背景）、壁画分辨率；**不要先砍卧佛的面部/手部、大佛殿的轮廓、土塔的比例**。

### 4.2 为什么「30 米室内」是三角形/绘制次数问题

- 大佛殿内部是一个 48×24×20 米的长空间；如果按「每根梁/每块砖/每片瓦/每尊罗汉/每笔壁画」建，三角形会爆炸。
- 真正占三角形的是：卧佛的衣纹/面部、31 尊群像、重檐/斗栱、土塔 13 层。
- 真正占绘制次数的是：31 尊（每尊一个材质/网格）、壁画（每组一张纹理）、经橱/展柜、风铎、城市体块。
- 解决：**合批 + 实例化 + 烘焙 + LOD**：
  - 卧佛：头/手 40 k，身体 30 k，远景 10 k；法线/AO 烘焙，不做 displacement。
  - 31 尊：3–4 个变体，实例化；十八罗汉可只做 8 尊近景 + 10 尊 impostor。
  - 壁画：4–8 张 2k/4k 纹理，合并到墙面材质；不做逐块砖。
  - 重檐/斗栱：模块化，合并到 1–2 个 draw。
  - 土塔/风铎：13 层合并；36 风铎实例化。
  - 城市：低多边形 + 雾；不建整条街。

### 4.3 量法

- 同一个 GPU job 里比差值；报告带站点指纹；不用软件渲染的数字外推。
- `?off=` 开关：`hall`, `buddha`, `arhats`, `mural`, `stupa`, `city`；`window.__cost()`；`window.__census()`。
- 目标手机：至少一台中端 Android/iPhone；目前没有测量。
