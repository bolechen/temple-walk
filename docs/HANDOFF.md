### 性能（T4 实测，2026-11-14）

| 档位 | 画面 | 画一帧 | 三角面 / 绘制次数 |
|---|---|---|---|
| 高 | 1920×1080 | 9.0 ms（改之前 10.4） | 133 万 / 478（含倒影那一遍） |
| 低 | 手机尺寸 585×1266 | 5.0 ms（改之前 7.4） | 66 万 / 239（低档已关倒影） |

帧耗几乎不随分辨率变，瓶颈是三角面和绘制次数。手机大约是 T4 的四分之一到十分之一，所以低档还要再砍一半才稳。
技术美术给的预算：手机 45 万面 / 120 次绘制 / 不画倒影；笔记本 70 万 / 200；台式 100 万 / 300。

### 还没做的，按评审排的优先级

**性能**
- 屋面网格只在翼角附近加密，其余放粗（瓦面加椽底共 23.7 万面，可砍到四分之一）；椽底只在出檐部分建。
- 光晕、烟、雾气共七十多个精灵各占一次绘制，改成三次 `Points`；十九种灰泥材质合成一种（墙脚高度放进顶点属性）。
- `mergeStatic` 里做顶点去重（现在 204 万个不带索引的顶点，约 70 MB）。

**建筑（宋式，尺寸出自评审对《营造法式》的记忆，他自己标了不确定的地方）**
- 斗拱：现在是一圈回纹。应是倒梯形的一朵朵：栌斗、泥道栱、华栱、令栱、昂嘴朝下朝外，拱端卷杀。
  主殿下檐五铺作，总高约柱高三分之一；配殿四铺作，约四分之一。每间一朵补间，当心间两朵。
- 檐口从上到下：瓦当（和筒瓦同宽，每垄一个）、燕颔版、飞椽、大连檐、圆的檐椽（中距 25–30 厘米）；翼角有角梁和套兽。
- 大殿像两层楼：上下檐之间露出 3.3 米格扇，真的只露约 1 米。下檐举高应约为出檐的一半（`rise` 3.4 → 约 6），
  上檐 6.2 → 约 4.7，配殿 3.0 → 约 1.9。**改之前先对照 `scratchpad/photos` 里的实拍。**
- 正脊太小：主殿应约 0.95 米高，鸱尾 2.2 米，正脊当中有火珠；垂脊端有兽头。
- 立面每间都一样：当中三间格子门（四扇），两边应是一米高白槛墙上的破子棂窗。**这会给立面添上白色，正合明暗规划。**
- 歇山山面是一块平三角：要有博风板、悬鱼。
- 台基边缘要有压阑石，踏道两侧的垂带下是三层内凹的象眼；主殿是须弥座。
- 栏杆是一排板：应是单勾栏，望柱八角带莲头，寻杖、盆唇、华版。
- 柱础：覆盆加櫍；柱础、碑、石灯是整石，不该有砌缝（要一个素面石材质）。
- 匾额：华带牌，高宽五比四，脚踩阑额，向前倾 25–35 度。
- 柳杉：真的下面一半多是光杆，上面是不规则的垂挂的团块。

**评审指出不合传统的**
- **石灯笼是日式春日灯笼**，六对排在轴线上像神社参道。宋代禅寺没有成排的石灯；换成唐式灯幢，只在大殿阶前留一对。
- 春天的粉花和飘瓣像樱花：换白玉兰，冬天可以有蜡梅；殿前宜有一对圆柏（「庭前柏树子」）。
- **席地的茶席、提梁壶、茶勺、茶入是日本茶道**。宋代茶宴是 0.78 米高的桌子、凳子、汤瓶、黑釉盏配漆盏托。
  我刚建的茶席要照这个改（`site.js` 里「A tea mat on the court」一段，以及 `journey.js` 里的提示语）。
- 钟口应是永乐大钟那样的波口。

**值得加的小东西**：阑额上的「七朱八白」（每间八道白）；翼角下的风铎；檐下的滴水线和青苔；门槛和踏步的磨损。

**画面**
- 远山是正弦波：改成分形的山脊，每层顶深脚淡，层间差 8–10%；天上要有一轮低的日或月。
- 地面：轴线甬道用 0.6×1.5 米的石板，只有三成的缝里有苔；雪地要有扫出来的路、屋面的瓦垄、檐口十厘米的雪檐。
- 竹：竿色 `#6F7F5A`、节下有白粉，叶子十厘米一簇，饱和度降到 45% 以下。
- 光束：晨昏从山门和檐口斜下来的光。
- 给地面烘一张光照图（柔和的半影加天光遮蔽），可以顺便把灯光也烘进去。

## 怎么验证

```sh
npm run check && npm test                       # 脚本能解析；单元测试（寺院平面、行走、建筑生成器、季节）
npm run e2e:quick                               # 端到端第一档：页面能起来，各级台地点地面都能走到
npm run e2e:smoke                               # 再加钟鼓频谱、十六种光景、两种视角、手机触屏
npm run e2e                                     # 再加上山进殿上香、点大殿、登顶、拍照三种画幅
node tools/portrait.js autumn-dusk              # 小沙弥的五个角度（正、侧、背、合掌两张）
node tools/shots.js court@autumn-dusk@third     # 机位名@季节-时辰@视角，输出到 tools/out/
```

**测试是每次改动的一部分。** 用户的原话：「这是你的长期项目，要在一开始就做好完善的测试和 e2e」。
规矩写在 `CLAUDE.md` 的 Commands 一节：加一个地方就把它加进 `tests/unit/plan.test.mjs` 的 `places`；
加一个访客能做的事就加一个端到端场景；修 bug 先让一个测试因为它而失败。端到端里等的是帧数（`t.frames(n)`），不是秒数。

第一次把这套测试跑起来就抓出了八个真问题，都已修掉：前院两侧能走出寺外；石阶脚下有一条没有高度的两厘米的缝；
三处平台和石阶之间有接缝；两个机位落在建筑里面；半山亭几乎走不进去；未知季节会让页面崩掉；
**在高处台地上点地面，落点是按山脚的高度算的**（山顶上点了没反应，第一级台地上会走出三倍远）。
最后这个是原型以来一直存在的，之前的全程测试用的是写死的路点，所以从没发现。

测试钩子：`window.__probe()`（画一帧并返回平均颜色，以及季节、时辰、视角、拍照状态、相机距离、雪、灯、视角大小）、
`__mood(season, time)`、`__view("first"|"third")`、`__photo(open, opts)`、`__capture()`、
`__pose(x, z, yaw, pitch)`，加上原有的 `__yard / __walk / __strike / __listen`。

网址参数新增：`?season=` `?time=` `?view=`。带 `?shot` `?show` `?cam` 时默认是夏昼、第一视角，保证旧截图可比。

### 2026-11-13 修过的一次部署失败

`ce429fa` 的部署失败过：那次运行被重跑，第一次尝试留下的 `github-pages` artifact 没被清掉，
第二次又传了一个，于是 `deploy-pages@v4` 看到两个同名 artifact 而拒绝部署。错误与代码无关。

已删除那两个陈旧 artifact。`.github/workflows/pages.yml` 现在给每次尝试生成带
`run_id/run_attempt` 的唯一名字、只保留一天，并把这个名字显式传给 `deploy-pages`。
重跑部署不会再撞名。以后查 CI 先看 `gh run view <id> --log-failed`，别猜是页面代码坏了。

## 几条容易踩的坑

- `procMat` 的 GLSL 片段会被包进一行 `{ ... }`，**片段末尾不能有 `//` 注释**，否则右花括号被注释掉，着色器编译失败。
- 页面没有 `<!doctype>` 和 `<head>`，`[hidden]` 需要靠 `index.html` 里那条 `display:none !important` 才生效。
- 阴影贴图只在换时节时重画一次（`shadowMap.autoUpdate = false`），所以会动的东西没有真阴影，沙弥脚下是一块假的暗斑。
- `FOG`、`SUN_DIR` 和 `glsl.js` 里的 `U` 是按引用共享的对象，只能就地改值，不能重新赋值。
- 仓库里的佛像模型来自如是我闻 `/zen`，仓库需保持私有；Pages 站点本身是公开的。
- 云端环境的网络白名单是用户手动放开的；百度百科拒绝访问，维基百科要用浏览器的 User-Agent。
