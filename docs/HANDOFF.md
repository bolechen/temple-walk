## 用户要什么

用户的原话，按时间顺序，后面的覆盖前面的：

1. 「对照真实的径山寺地图、调查资料，保留核心细节，实现完全灵魂层面数字版重现」
2. 「把这个当成你自己项目，如同你一生唯一的作品一般对待它。保留只取意的设计，保留每个寺院的灵魂元素即可，
   在复杂度跟艺术性之间取平衡点」
3. 「我希望你能超越他们的视觉效果和艺术效果」（他们 = 小王子游戏、韩国 Sansa、Saltline）
4. 「参考小王子，以小沙弥的视觉来游览寺庙，可以切换第三视角和第一视角，可以选择季节和时间，
   不同季节不同的景色和光线效果，可以选择调整视角后拍照发社交媒体，分享出去的照片一定要美轮美奂，
   艺术品级别，让人看了就想体验」
5. 「尽量去选开源的、精细的、有艺术感的 three.js model，自己画的画要注意高精细度」

长期设想见 `VISION-AND-RESEARCH.md`：「游览全球的小众寺庙，一城一寺，一处净心空间」。径山寺是第一座。

**用户的工作方式**：希望你自己拿主意、持续推进，不要每一步都问。验收只看画面。
他在 Mac 上测，线上地址是 <https://bolechen.github.io/temple-walk/>，推 `main` 自动部署。

## 下一步，按我认为的优先级

### 1. 小沙弥换成精细的模型（用户第 5 条，最要紧）

现在的沙弥一入画就把成片拉低了，见 `tools/out/card.jpg`。用户明确要「开源的、精细的、有艺术感的」模型。

- 找授权清楚的开源角色模型（CC0 / CC-BY，注明出处），或者用 Tripo / Meshy 生成后在 Blender 里修。
  小王子作者的做法是：先出四视图，Tripo 生成，Auto-Rig Pro 绑骨，Mixamo 取动作（见对话记录里他的原文）。
- 需要骨骼和至少三个动作：站立、行走、合掌。`monk.js` 对外只有 `group` 和 `update(dt, speed, pray, t)`，
  换实现不用动别处。
- 走 `gltf-transform`：几何 meshopt，贴图 webp 或 KTX2，目标 2 MB 以内。发布平台和 Pages 都能直接放 `.glb`。
- 我没做这一步的原因：本轮时间用在了把四样功能接通上，没有去找和验证模型。**不要再手写几何体当角色。**

### 2. 近处的东西全部提高精度（同样是第 5 条）

用户说「自己画的画要注意高精细度」。目前所有 canvas 画的贴图都偏糙：

- `plaque.js` 匾额是 256 像素一个字，近看发虚。提到 512，做旧要更细。
- `bamboo.js` 的竹叶贴图 512，叶子是简单的二次曲线，放大了像贴纸。
- `trees.js` 的花和叶是一堆椭圆，秋天远看可以，近看是色块。
- `card.js` 的纸纹和印章可以更讲究（印章现在用的是毛笔字体，不是篆刻）。
- 石灯、斗拱、铁香炉、茶具都是低面数的手写几何，是换开源模型的第二批候选。
  `VISION-AND-RESEARCH.md` 里有压缩预算和不该换的东西（`buildHall` 建筑本体不要换）。

### 3. 拍照模式打磨

- 没有景深。成片要「艺术品级别」，浅景深是最直接的手段；后期链在 `post.js`，需要加一个带深度的散景通道。
- 默认机位太近、太正。应该给几个预设构图（低机位仰拍、远景小人、隔着门框），或者进入拍照模式时自动退到一个好位置。
- 成片底部的网址在本地测试时显示的是 `127.0.0.1`，线上是正确的域名，不用改。
- 可以考虑成片不带沙弥时用另一套更安静的装裱。

### 4. 性能

**这是我最没有把握的地方。** 加了季节树、粒子、沙弥之后，大院一帧是 133 万个三角面、约 780 次绘制（含倒影那一遍），
之前是 62 万、240 次。绘制次数涨得多是因为每栋建筑的每种材质各一个网格，没有跨建筑合并。

- 从来没在真机上测过帧率，只有无头浏览器的软件渲染。用户在 Mac 上说过「没问题」，那是加这些之前。
- 该做的：跨建筑按材质合并静态几何（`site.js` 的 `put` 之后做一次）、倒影那一遍不画粒子和竹叶、
  低档位下减少竹子和树叶数量。`quality.js` 已有分档和按帧时间降级的框架。

### 5. 其余

- 殿内（`hall.js`）还是固定机位的一张图，季节和时辰对它不起作用，沙弥也进不去。真 3D 的殿内是早就欠着的。
- 环境声不随季节变（冬天应该更静，夏夜该有虫声）。
- `README.md` 还没写这一轮的四样新功能，`CLAUDE.md` 的架构一节也没提 `mood / monk / trees / drift / card`。
- `VISION-AND-RESEARCH.md` 第五节的六个待决事项，用户后来的第 3、4 条已经回答了其中两个：
  要可见化身；画面要往上做，不是往下省。其余四个仍未定。

## 怎么验证

```sh
node tools/shots.js court@autumn-dusk@third     # 机位名@季节-时辰@视角，输出到 tools/out/
node tools/walkthrough-test.js                  # 全程：上山、进殿、上香、登顶、钟鼓的频谱、拍一张照片
```

测试钩子：`window.__mood(season, time)`、`__view("first"|"third")`、`__photo(open, opts)`、`__capture()`、
`__pose(x, z, yaw, pitch)`，加上原有的 `__yard / __walk / __strike / __listen`。

网址参数新增：`?season=` `?time=` `?view=`。带 `?shot` `?show` `?cam` 时默认是夏昼、第一视角，保证旧截图可比。

## 几条容易踩的坑

- `procMat` 的 GLSL 片段会被包进一行 `{ ... }`，**片段末尾不能有 `//` 注释**，否则右花括号被注释掉，着色器编译失败。
- 页面没有 `<!doctype>` 和 `<head>`，`[hidden]` 需要靠 `index.html` 里那条 `display:none !important` 才生效。
- 阴影贴图只在换时节时重画一次（`shadowMap.autoUpdate = false`），所以会动的东西没有真阴影，沙弥脚下是一块假的暗斑。
- `FOG`、`SUN_DIR` 和 `glsl.js` 里的 `U` 是按引用共享的对象，只能就地改值，不能重新赋值。
- 仓库里的佛像模型来自如是我闻 `/zen`，仓库需保持私有；Pages 站点本身是公开的。
- 云端环境的网络白名单是用户手动放开的；百度百科拒绝访问，维基百科要用浏览器的 User-Agent。
